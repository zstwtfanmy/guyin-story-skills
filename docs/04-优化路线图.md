## 0. 三条总原则（所有优化项的过滤器）

任何优化项必须同时过三条线，不过线者进 §6 不做清单：

1. **全 flash 线**（研究员，v1.1 修订）：编排层与执行层同为入门模型，任何环节都不得暗设「换个强模型就好了」的退路。质量缺口的补偿只有三个来源：**确定性算法（脚本）、机械判据（可计算条件切换）、作者选择（多采样外选）**——工程哲学第 1 条「框架智能替代模型智能」的彻底化：作家的智力不住在模型里，也不住在强模型编排层里，只住在框架与作者手里。衡量标准：优化后产出质量**不降反升**——flash 干的全部是它命中率高一个量级的任务（填空 / 三选一 / 对照改写 / 是非题）。
2. **哲学红线**（[01](01-需求框架.md) §4.3 康德红线）：「**养**」「**查**」「**观**」的工具可以做，「**造**」的工具不能做——场景素材模板库、人物小传生成器皆属腔调卡 2.0，拒绝。
3. **作家风险线**：写作的真实死因排序是 选题失败 > 中期结构失控 > 烂尾 > 单章质量。资源投向必须与风险分布对齐，而非全押单章优化。

## 1. 诊断汇总

### 1.1 token 账本（架构师视角）

| 流程 | 现状 | 判断 |
|------|------|------|
| 写章循环 | 卡片 <500 token、低模型执行、`上下文.md` 8KB 预算、伏笔按「活跃」过滤 | ✅ 已近最优，不动 |
| 章检 | 六脚本全本地确定性，零 token | ✅ 架构已对 |
| guyin-review | full 模式四视角 subagent 各自读全文 = 同段正文进 4 次上下文 | ❌ 最大户 |
| guyin-analyze Stage 2 | 逐章原文全文进模型，300 章 = 30-50 万字输入 | ❌ 天文数字 |
| 自检卡 | 整卡给模型跑，但约一半题目是确定性可查的 | ⚠️ 可下沉 |
| guyin-deslop | lint 本地扫 → 只改写报警段 | ✅ 全框架唯一「漏斗式」流程，是好榜样 |

**核心洞察**：工程哲学第 2 条「确定性规则交给脚本，模糊性文采交给范例和重写」（[01](01-需求框架.md) §4.2）——deslop 已实现此条，review 与拆文尚未。省 token 的正确方向**不是换更强算法替代模型，而是让模型只看算法筛不出来的那部分**。

### 1.2 作品风险分布（作家视角）

| 死因 | 真实发生率 | 框架现状 |
|------|-----------|---------|
| 选题失败（开头惊艳，30 万字后无以为继） | 高 | ❌ 无压测机制 |
| 中期结构失控（支线拧了 / 配角抢戏） | 高 | ❌ 大修止于章级（L1/L2/L3），无卷级手术 |
| 烂尾（线头太多收不回） | 高 | ❌ 无收线审计 |
| 单章质量（生硬 / AI 味） | 中 | ✅ 四卡 + 章检 + deslop + review |
| 状态漂移（设定矛盾 / 时间线错乱） | 中 | ✅ 追踪系统 |
| 跨章复读（同一比喻第 5 次出现） | 中 | ❌ 检查脚本全是单文件密度检查，无历史库（P6 补） |

## 2. 理论基础

### 2.1 低模型三特性 = 省 token 的安全边界

| 特性 | 推论 |
|------|------|
| **Lost in the middle**：长上下文中段利用率断崖下跌 | 塞在中间的内容本来就没被消费——砍掉是零损耗 |
| **复读衰减**：长生成后输出分布自发坍缩到高频模式 | 跨章复读不是「忘了写过」，是分布问题——光贴前文没用，要主动扰动 |
| **开放任务敷衍，填空任务稳定** | 任何「综合判断一下」「总结一下」的调用都是 token 打水漂——低模型的钱要花在锚定答案空间的任务上 |

### 2.2 分布坍缩三推论

跨章复读的根源是输出分布坍缩而非记忆缺失：flash 级模型采样多样性本来就低，写到几十万字后，比喻域、句式、转场方式会自发收敛到固定的高频模式。推论：

1. **灵感装置本质是分布扰动**——感官骰子、发散卡不是「激发灵感」，是强行把采样推出坍缩区，应随章节进度**加密**而非恒定频率（第 50 章的坍缩压力远大于第 5 章）；
2. **多采样外选本质是覆盖分布的多个峰**——单次采样是坍缩分布的单点，3-5 次采样才能画出「还能写出什么」的轮廓；
3. **范文切片防复读**——「同章内不重复」升级为「跨 N 章轮换来源」；此推论同样适用于章尾钩子类型（连续同型钩子钝化，见 P4）。

### 2.3 位置偏差的系统性利用

低模型对 prompt **开头与结尾**的利用率远高于中间（「卡尾复述禁令」已在用）。推广为所有卡片的设计纪律：**指令贴两端，材料放中间**。分诊卡：证据放开头、三选一问题放结尾。位置敏感度 > 内容量敏感度。

### 2.4 分卡温度

写作卡与检查卡的理想温度是两个极端：**写作卡高温**（对抗坍缩，多采样才有意义——温度低则抽 5 版 = 同一版抄 5 遍，外选经济学红利归零）；**检查类低温**——摘要 / 自检零温（要可复现），分诊中温采样 3 次投票（§2.5：投票的前提是样本间有差异，零温采 3 次 = 同一票抄 3 遍）。落点见 P1 双执行 agent。

### 2.5 全 flash 质量补偿四算法（v1.1 新增）

强模型退场后，质量的地基是四个被反复验证的弱模型补偿技术：

| 算法 | 机制 | 用在哪 |
|------|------|--------|
| **自一致性投票** | 同卡中温独立采样 3 次，多数一致生效，分歧升级作者。flash 单次错误率高，投票后正确率显著提升——**用采样预算买确定性**（「量弥补质」的算法形态） | 分诊卡、自检终判 |
| **二叉树聚合** | 聚合 N 份摘要不一次性做（flash 必丢信息且自我感觉良好），两两合并（每次只合并 2 份约 300 字 → 1 份约 400 字），信息保持率远高于一次性聚合 | 金字塔 10 章聚合层 |
| **前缀缓存友好设计** | DeepSeek API 的 context caching 自动按前缀匹配，命中部分价格约为原价 1/10。卡片组装保证**固定内容顺序稳定**（纪律行 / 角色锚点 / 范文切片在前，变动的 beat 内容在后），同章连续 beat 天然命中 | 四卡模板的组装顺序纪律 |
| **提示空间采样** | 外选多样性从提示维度获取（感官入口 / 写法分类各指定一版），而非指望温度——flash 的分布本来就尖，温度采样的方差远小于提示空间采样的方差 | 多采样外选（「5选1 分类提示」的算法依据） |

### 2.6 哲学辨析：读者信号 ≠ 庆赏爵禄

- **选题期市场热度** = 庆赏爵禄（写作前被市场绑架）→ 维持不做（[01](01-需求框架.md) §10.4）；
- **创作期追读曲线 / 弃书点** = 作品的心电图（「见者惊犹鬼神」的测量，已进入作品之人的生理反应）→ 恰是哲学要求的输入：魂档案「**回响收编**」字段（读者读出而作者未写、反复出现者收录）本就需要读者输入，目前无供给管道。

斋心七日是为了进山林，不是蒙眼砍树。数据回流不违反「忘庆赏爵禄」，反而执行了它。落地见 P5。

### P1 审查漏斗化 + 自检卡下沉 + 分卡温度

**动机**：review 四视角全文 ×4 是最大 token 户；自检卡一半题目白给模型跑；统一温度让多样性与可靠性互相伤害。

**方案**：

1. **四视角分级**（按「是否真需要全文」）：

| 视角 | 执行者 | 形态 |
|------|--------|------|
| 文字（AI 味） | 低模型 | ai-patterns 脚本全扫 → 引号内对话 / 系统播报格式的命中**规则化降级**（本地先降误报约 30%）→ 报警段 ±2 段进**分诊卡** |
| 一致性 | 纯脚本 | 读 `_tracking-state.json` + 本章正文，机械比对「状态断言 vs 正文」（实体 / 数字 / 时间点的冲突检索）；伏笔矛盾按 F003 式 ID 精确召回，不经模型 |
| 架构（节奏/钩子） | **本地算法 + 作者抽检** | 钩子强度曲线、主线推进间隔（连续 N 章无主线推进即报）、章尾类型分布全部本地可算（读 P2 金字塔），信号表生成后**作者判读** |
| 角色对话 | 低模型 | 维持单章输入 |

> 架构判断是长程语义理解，deepseek-flash 做这个不是「效果打折」而是「一本正经地胡说」——格式工整、每条带证据、判断全错，比没有报告危险。全 flash 前提下架构视角的正确形态：**可计算信号本地算（钩子强度 / 主线推进间隔 / 节奏曲线），语义终判归作者抽检**。flash 在审查里的领地：局部模式识别 + 填空 + 是非题。

2. **分诊三选一卡**（新卡片，进 `cards/`）：

```
【分诊 3/17】
报警：比喻密度超标（本段 5 处「像/仿佛」）
原文：……（报警段全文）
三选一，选 2 必须写一句证据：
1. 真问题（构成 AI 腔复读）→ 进改写队列
2. 有功能的正常文本（这个角色/这个题材本来就这样）→ 证据：____
3. 拿不准 → 进作者待审清单
```

行为学设计：**真问题选项置顶**（低模型对选项有位置偏好）；**选 2 必须给证据**（对抗自查自纠的宽容偏差——抄出「功能是什么」的一句原文，敷衍成本上升）；**「拿不准」是合法选项**（有退路时 1/2 判断更诚实）；**中温 3 票制**（同卡独立采 3 次取多数，分歧升级作者——§2.5 自一致性投票）。

3. **自检卡改造**：
   - 可计算题下沉新脚本 `guyin-check-beat.js`：「是否出现第X章/细纲/伏笔/读者」「是否连续 4 句对话无动作插入」完全可查；「心理独白 ≤2 句」引号外心理动词计数半自动。beat 拼接后先跑，模型只剩 2-3 道真语义题；
   - 剩余题改「**先抄后判**」：每题先抄原文相关句、再答是/否——抄写任务强制逐句过文本，判断寄生在抄写之后（对强模型只是格式差异，对低模型是注意力从概率行为变机械行为）。

4. **分卡温度**：执行层拆双 agent——`guyin-beat-writer`（高温）+ `guyin-checker`（低温档：摘要 / 自检零温，分诊中温跑 3 票），部署件随 guyin-setup 模板分发；不支持分 agent 温度的环境，检查类卡卡头加「本次输出保持确定，不要发挥」弱补偿。

**落点**：`skills/guyin-review/SKILL.md`（P1/P2 流程）、`skills/guyin-write/cards/`（分诊卡）、`skills/guyin-write/scripts/guyin-check-beat.js`（新）、`skills/guyin-setup/templates/`（双 agent 部署件）。

**验收**：整卷审查输入 token 降 ≥50%；分诊 3 票分歧率可观测（即升级作者的比例，过高说明报警质量差）；自检敷衍率（全答「是」比例）明显下降。

### P2 章节金字塔 + 分诊/摘要卡

**动机**：`上下文.md` 的「近三章速记」是滚动窗口，不是金字塔——写 / 审第 100 章时对 90 章之前完全失忆，只能重读文件（30 万字级）。

**方案**：

1. **三层金字塔**：
   - 章摘要（约 300 字，写完当章由低模型顺手生成，成本≈免费）；
   - 每 10 章聚合摘要（约 1000 字）——**二叉树两两聚合**（§2.5）：一次性聚合 10 份，flash 必丢信息且自我感觉良好；
   - 卷摘要（约 500 字，常驻）。
2. **摘要卡 = 字段填空 + 原文锚点**（新卡片，进 `cards/`）：

```
【章摘要卡】从本章正文填空，每个字段必须带原文锚点：
- 新事件（≤3 条，每条：谁+动词+结果）：____
- 情绪走向：从____到____
- 章尾钩子（抄最后一句原文）：____
- 伏笔变动（引用 F 编号）：____
- 出场角色：____
```

> **开放摘要对低模型 = 废话生成器**（「本章讲述了主角继续变强的故事」零信息量）。字段锚定答案空间 + 原文锚点防敷衍，是低模型产出稳定性的全部秘密。

3. **金字塔消费时渲染成表格，不是散文**：结构化字段位置固定可预测，lost in the middle 对它的影响远小于散文。
4. **消费方**：review 架构视角（审第 100 章 = 卷摘要 ×2 + 近 10 章章摘要 + 本章全文 ≈ 5K 字，替代 30 万字）、写章读盘、P5 结构手术、P3 收线审计。

**落点**：`scripts/guyin-tracking-commit.py` 补一类派生视图（近三章速记已是雏形，扩展为完整金字塔）；`cards/摘要卡.md`、`cards/分诊卡.md`（与 P1 同批）。

**验收**：审第 N 章的架构视角输入 ≤6K 字；章摘要抽查零废话率（每字段有原文锚点）。

### P3 点子压测 + 收线审计

**动机**：最贵的失败是 30 万字后无以为继（点子势能只有 20 万字硬拉到 200 万）；烂尾的一半原因是线头太多收不过来。两个协议合计 <200 行文档，拦截的是最贵的两种死法。

**方案**：

1. **点子压测**（guyin-write 开书场景 Phase B 前置，不立新技能）——三问，有明确否决权（否决则建议换点子或降级为短篇）：
   - **核心冲突再生能力**：主角的欲望与障碍是否可升级？（升级流天然合格；一次性复仇流必须设计第二引擎）
   - **同类书倦怠点**：题材被喂到什么程度、差异点撑得过 100 章吗？
   - **自己续航**：这个题材写 200 万字会不会吐？（写作倦怠是真实弃坑原因）
   - **答卷主体是作者**（口述问卷式，与作者性引导同构）：flash 只做结构化整理与机械字段检查（如「第二引擎」在否），语义判断不交给它——全 flash 前提下压测不降级为走过场；
   - 压测结论 + 差异点承诺写入卷纲。
2. **收线审计**（guyin-write 新「完书」场景）：
   - 触发：「完本 / 收线 / 进入尾声」；
   - 追踪系统列出全部「已埋未回收」伏笔 + 未兑现承诺 → 强制过堂：**明收 / 暗收 / 放弃+说明** → 生成收线清单 → 尾声细纲必须消化清单；
   - 顺手交付：**完书复盘报告**（数据验证了哪个指纹、下一本迭代方向——02 阶段四「复利飞轮」的落地形态）。

**落点**：`skills/guyin-write/SKILL.md` 场景路由加两行（压测 / 完书）+ 协议细则入 `references/`。

**验收**：压测三问对候选点子能产出「写 / 换 / 降级短篇」三态结论；收线清单由 `_tracking-state.json` 一键生成。

### P4 场景台账 + 蓄力成对设计 + 钩子类型轮换

**动机**：追踪系统有角色状态、时间线、伏笔、上下文——**唯独没有场景状态**。同一场景写 10 次必然漂移（桌子方位变了）；Muse 判据只有「高潮章升档」，缺「前置章蓄力」；钩子类型也会坍缩（连续五章危机钩，第六章读者已免疫）。

**方案**：

1. **场景台账**（`追踪/场景/`）+ **场景卡**：
   - 字段：五感锚点 / 布局事实 / 状态变迁（「第三卷那场火之后，西厢塌了」）——与角色状态完全同构，tracking-commit 加一类实体；
   - **锚点必须存从正文摘出的原句，禁概括**：存「院里有棵歪脖枣树，树底下压着半扇磨盘」，不存「院子里有植物和农具」——低模型**补全具体名词的能力远强于从抽象生成具体**，见过「歪脖枣树」才写得出「枣树叶子扫过磨盘」；
   - 写作卡组装时涉场景贴锚点行（与「上一章结尾 300 字贴卡」同构）；锚点半自动获取：显影器 / 指纹库扫描时标出实体名词密度高的句子（脚本预排序），作者勾选入台账。
2. **蓄力—爆发成对**：Muse 判据触发时自动前置 1-2 章「**蓄力章**」标记——禁发散、收敛感官、降字数。爆发章的爽感一半来自前几章的克制；现在的判据是独立的，应成对。
3. **钩子类型轮换**：细纲每章标注章尾钩子类型（危机 / 反转 / 期待 / 悬念 / 情绪），编排层查连续同型即提示轮换——与 §2.2 分布坍缩推论 3 同源：**跨章的任何模式重复都是坍缩，比喻如此，钩子也如此**。

**落点**：`scripts/guyin-tracking-commit.py`（场景实体）、`cards/README.md` 占位符取数表（场景锚点行）、guyin-write 细纲协议（钩子类型字段）。

**验收**：review 一致性视角的场景漂移报警下降；Arena 盲评「爆发章爽感」提升（蓄力章生效）。

### P5 结构手术 + 读者信号回流

**动机**：写到 80 章发现支线拧了，每个长篇作者都干过砍线的事——框架大修止于章级，卷级 / 线级手术无协议；框架与 Arena 盲评是封闭系统，缺作品的心电图（哲学辨析见 §2.5）。

**方案**：

1. **结构手术**（guyin-write 新场景，触发「砍线 / 并线 / 这条线不对」）：
   - 流程：读金字塔 → **作者定砍线**（flash 只出候选线清单与各线戏份 / 伏笔统计）→ **影响面清单**（该线全部伏笔 / 事件 / 角色状态——纯查询，`_tracking-state.json` 事件库已有，脚本一键生成）→ 残留处置（留作闲笔 or 补丁章消化）→ 分批出补丁指令；
   - 人类作者在负向决策上最痛苦（沉没成本），协议替作者把痛苦变成清单。
2. **读者信号回流**：
   - `追踪/读者信号.md`：作者手动录入每章追读数 / 评论关键词（一分钟/章）；
   - 掉崖章归因机械化：生成掉崖章 ±2 章的信号表（钩子类型 / 主线推进标记 / 字数 / AI 味报警数），**作者看表归因**——flash 直接判「为什么掉」不可靠；
   - **弃书点思维**：读者不是因某章差而弃书，是某章**给了他一个离开的借口**——单章看都合格、连续两章无主线推进叠加即弃书点；用金字塔 + 钩子强度曲线（章尾悬念结构，本地启发式可估算）做跨章弱点审计；
   - 评论关键词 → 魂档案「回响收编」候选的供给管道（该字段从此有输入源）。

**落点**：`skills/guyin-write/SKILL.md` 场景路由（结构手术）、`scripts/` 影响面清单与钩子强度曲线脚本、追踪模板（读者信号.md）。

**验收**：影响面清单一键生成；掉崖归因报告可定位到章 + 原因类别。

### P6 段落指纹库 + 人物显影器 + 配角管理

**动机**：现有检查脚本全是**单文件密度检查**，无跨文件历史库——跨章复读是 flash 级模型分布坍缩的直接产物（§2.2），是最常见的中期死因之一；「选择即显影」（[01](01-需求框架.md) §4.1 第 10 条）目前只有多采样外选一个操作化身，**人物在正文中的累计显影无工具**——按「缺操作化身的理念不进流程」铁律，这是必须补的哲学缺口。

**方案**：

1. **段落指纹库**（`guyin-check-repetition.js`，纯 Node 零依赖，排进章检序列）：
   - 每段落 64 位 SimHash（字符 bigram 加权），分桶入库；新章入库前先查，海明距离 ≤3 报「疑似重复描写」；
   - **处置按相似度硬分级**：距离 ≤1（近乎照抄）→ 直接进改写卡，卡内**两段原文并排** + 方向「换比喻域」（低模型看对照改写是强项；其中约七成可直接删，但脚本只标不删，删令由作者确认）；距离 2-3（模式复读）→ 待审升级作者，结合意象台账判「有意回环还是坍缩」（flash 判不了这个，回环是意图，坍缩是分布）。
2. **意象台账**（与指纹库同源落地）：比喻 / 闲笔资产登记——哪个域、被哪个角色用过几次。「人物之眼」改写协议的消费端：**换域，而不是换词**。
3. **人物显影器**（guyin-flesh 独立轻量技，或 review 第五可选视角，实施时定）：
   - 本地扫描正文抽角色行为链（动作动词 + 对话归属，就近人名规则，70-80% 准确率够诊断用）→ **断裂初筛靠规则**（行为链统计特征 vs 角色卡标注关键词的机械比对）→ 终判归作者：报「设定 vs 呈现」断裂（设定说果决、正文里躲了三次）+ 角色实际呈现弧线图（对补纲直接有用）；
   - 与 review「角色对话」视角分层：那个查**单章声线**，这个查**跨章行为链对设定弧线的累计偏移**；
   - 对话呼吸分析（话轮长度 / 打断率）做子功能，不独立成技。
4. **配角管理**（显影器姊妹）：戏份统计（每角色出场章数 / 对话量）+ 工具人检测（配角连续 N 章只有递话 / 制造冲突功能即报）——网文中期群像死亡：配角全变功能性 NPC。

**验收**：跨章重复报警可用且误报可忍；显影报告的「断裂清单」可直接转 review findings 格式。

### P7 guyin-pitch 开书文案包

**动机**：书名决定点击率、简介决定转化、章节标题是门面工程——网文作者的真刚需，且完全在框架能力圈内（拆文能力的反向应用）。

**方案**：

1. **书名**：多采样外选（框架自身机制复用）+ 十年测试过滤热词名；
2. **简介**：从前三章反向提炼——flash 做**卖点抽取填空卡**（主角身份反差 / 核心冲突 / 最大悬念各一，从原文抄锚点句），作者拼装成 200 字；禁「请总结卖点」式开放调用（拆文管道 Stage 1 的能力用在自己书上）；
3. **章节标题**：写章循环落盘时的标题协议（与 P4 钩子类型联动）。

**验收**：简介含前三章全部钩子承诺；书名过十年测试（剥离热词后依然成立）。

## 4. 全 flash 任务形态总纲（v1.1 重写）

前提修订：不存在「什么活给低模型」的分配问题——**全流水线（编排 + 执行）只用入门模型**。这张表回答的是：每类任务在 flash 手里以什么形态不塌，塌的部分由什么补偿。

| 任务 | flash 形态 | 质量补偿（flash 之外） |
|------|-----------|----------------------|
| beat 写作 | 填空卡 + 范文 few-shot + 高温采样 | 提示空间采样（5选1 分类）+ 作者外选 |
| 报警分诊 | 三选一 + 证据要求 + 真问题置顶 | 中温 3 票制，分歧升级作者 |
| 章摘要 | 字段填空 + 原文锚点，**禁开放摘要** | 聚合层二叉树两两合并（§2.5） |
| 自检 | 是非题 + **先抄后判** | 可计算题先过 `guyin-check-beat.js` |
| 对照改写 | 两段原文并排（模仿是它最强项）+ **一卡一病** | 多轮迭代排队，不把多个问题塞进一张卡 |
| 一致性 | 不经模型 | 纯脚本：状态断言 vs 正文的实体 / 数字 / 时间点比对 |
| 架构审计 | 不做语义判断 | 钩子强度 / 主线推进间隔 / 节奏曲线本地算，作者判读信号表 |
| 外选判词（合问） | 不判「哪版更合」 | 机械特征初筛（句长方差 / 比喻密度 / 禁令违规数）+ **作者终选**——选择即作者性，判词回归作者反而更纯粹 |
| 豁免五测试 | 只跑「不可替换测试」的重写对照实验 | 击中 / 删疼 / 共振 / 消化全归作者 |
| 压测 / 作者性引导 | 只做结构化整理与机械字段检查 | 三问与四件的答卷主体是作者（口述问卷） |

> 一句话总纲：**flash 出方差，算法管下限，作者做选择**——流水线的智能 = 脚本 × 机械判据 × 采样预算 × 作者品味，「换个强模型」的退路已从设计中移除。

## 6. 明确不做（延续 [01](01-需求框架.md) §10 决策补记风格）

| 项 | 不做的理由 |
|----|-----------|
| **embedding 向量检索** | 外部 API 违背「模板随技能分发、纯本地」；本地推理重依赖，复杂度上一个数量级。BM25 / 倒排索引 + 结构化状态（伏笔 ID + 活跃过滤）覆盖 90% 场景。**够用的算法 > 时髦的算法** |
| **场景素材模板库 / 人物小传生成器** | 「造」的工具，腔调卡 2.0，撞康德红线（§0 原则 2）。正确供给路径：口述采集 + 拆文积累 + 灵感池——管道已有，缺的只是场景 / 意象两个登记维度（P4 / P6 补） |
| **选题期扫榜数据** | 维持 [01](01-需求框架.md) §10.4（忘庆赏爵禄，魂谱对表替代）；创作期读者信号不在此列（§2.5 辨析） |
| **技能数量膨胀** | 多数新能力做成现有技能的新场景 / 新协议，八技能数量保持克制。唯一新增候选：P7 guyin-pitch；P6 显影器独立成技或并入 review，实施时再定 |

## 7. 与 02 四阶段（守工灵显）的关系

| 本路线 | 在四阶段中的位置 | 说明 |
|--------|----------------|------|
| P1 / P2 | 「工」层深化 | 确定性边界再外扩：deslop 的漏斗模式推广到 review 与全局视角 |
| P4 / P6 | 「灵」层激活的前置基建 | 灵感装置加密、范文轮换、指纹库防坍缩——正是阶段三 Muse 全量启用需要的护栏（防「灵感装置失控崩设定」风险的另一半：防它不失控但坍缩） |
| P3 / P5 / P7 | 新维度：作品全生命周期 | 02 未覆盖的从点子到完本；建议作为与阶段四并行的「生命周期线」滚动推进 |

02 的 Arena 协议不变：本路线每一项的验收都可进擂台打（如「蓄力章是否提升爆发章盲评爽感」即一场标准对战）。
