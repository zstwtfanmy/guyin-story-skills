# 框架整改任务书 v3：修正默认偏置、补齐因果供给与真实验收

> 日期：2026-09-15。性质：二次审核修订，尚未实施。
> 范围：guyin-skills 框架、部署模板、检查器与框架验证；不修改任何小说项目的正文、细纲、设定或追踪。
> 保留原文件名便于引用，但撤回“文风只由题材决定、作者签名只能退居次位”的标题论断。题材、场景任务、人物视角、作者表达与目标读者共同约束写法。
> v1/v2 的实施指令由本版替代。本文不是对全部历史诊断的认证，也不是“框架已具备名作生产能力”的证明。

## 0. 审核结论

**v2 不通过直接执行审核。** 它既指出了真实的契约接线问题，也把编辑假说写成了实证，把未验证的写法升级成了硬规则，并遗漏了框架本身的风格偏置及检查器错误。

本版区分三种交付，不能混称“整改成功”：

1. **工程修复**：接口一致、字段可达、误报不强迫改文、状态不误放行。这些能用代码与夹具验收。
2. **创作能力试验**：解除通用笔法限制、补因果材料、增加全文审读等，具有可解释的作用路径，但是否改善成稿必须比较验证。
3. **长期作品质量**：人物生命力、历史社会质感、连续多章的期待兑现及整体完成度，不能由前三章字段、单段胜负或脚本绿灯证明。

**可以在作者确认后先实施 A 类工程修复，再实施 B 类受控试验；不能按 v2 全量加规则后宣称“木、没钩子、重写无效已经解决”。** 同样不能把“尚未证实提分”当成框架免责：已证实的误报、默认偏置和语义验收漏洞必须处理。

## 2. 当前仓库已确认的问题

以下路径相对仓库根，行号对应本轮审计时的现行文件，不是实施后的定位承诺。

### 2.1 生成到后处理存在同向笔法偏置

| 环节 | 可核查位置 | 当前限制 | 可以确认什么 |

这些规则**存在且会施加选择压力**是事实；它们对用户所述退步贡献多大，尚未被隔离实验测出。解除通用限制也不等于鼓励无限心理独白、滥抒情或注水。

### 2.2 检查器既有误报，也有部署契约不一致

- `guyin-check-beat.js:50-55,241-255` 将“不多时”“一番……之后”等通用时间压缩判为 blocking 跳写；未区分合法概述与跳过必须展示的事件。
- 同脚本 `:68-70,260-295` 只凭行内有引号判断连续对白，却输出“无动作/表情/环境插入”；同行已有动作也命中。
- 同脚本 `:298-318` 数心理词命中次数，不是真正的心理独白句数；`:94-96,353-354` 默认 advisory 也返回 1。调用者若只看退出码，会把建议放大为失败，不能说所有调用目前必然如此。
- `guyin-check-ai-patterns.js` 的 `prose-fragment-ratio` 可因短叙述段比例触发 blocking；这仍是文体启发式，不是“必然错误”。
- `guyin-check-trial-gate.js:105` 只接受纯“试读记录”标题及空白/冒号后缀；部署模板 `追踪/读者信号.md:11` 却是“试读记录（活人反馈，Fw-06）”。按模板填完仍可能报无试读节。
- `guyin-check-pending.js:80-83` 只把空、待审及未回填裁决的升级作者视为开放态，其他任意字串都算关闭；hook `skills/guyin-setup/templates/long/.claude/hooks/guyin-hook.js:164-165` 同样如此，与终态五选一契约不符。

### 2.3 “试读门通过”不等于“读者愿意读”

`skills/guyin-write/scripts/guyin-check-trial-gate.js:83-95,136-150`：

- 文件缺失或读取异常均 fail-open；并非所有项目都被硬门覆盖。
- 只取试读人和章范围，不验证回答填写，不处理负面回答，也不绑定正文版本。
- 因此旧稿试读不能证明新稿有效，填写人名也不能由脚本认证“真人”。

记录覆盖检查本身不是错，但 v2 把它用作质量验收，是错。负面反馈应保留并触发决策，不应迫使作者把答案改成“想看”才过门。

### 2.4 题材契约存在生成保障缺口，但不是知识完全隔离

`skills/guyin-write/references/细纲协议.md:161-162` 已依赖 `设定/题材定位.md` 的阶段底牌及读者契约。当前主开书流程、文件契约和 setup 模板未形成明确的生成—读取—更新保障。

应补书级事实来源，但不能断言历史所有项目都没生成过，也不能断言 consult 知识从未通过细纲、范文间接传入。`consult/INDEX.md` 的“永不下发”应澄清为不下发方法论全文，而非禁止编排层采用经过核实的方法。

新增“题材正文提示卡→批次题材区→题材口吻”三层复制会增加漂移和预算。本版不采用该重复存储链。

### 2.5 语义自检存在漏判，全文质量审查不是稳定必经动作

v12 `:220-223` 要求推功后“全场看向老爸”，`:247` 却只抄推功台词便把整项判是；B 稿结尾未兑现该反应。`:250` 把“三十万数目”判为新信息，但背景已有三十万订单额；如果新增是订金性质，须证明这一变化，不能只见数字便判增量。`:251` 列物件为记忆点也不等于读者实际记住。

现行框架并非没有结构标准：细纲已有起因、发展、转折、高潮、因果链、信息差和契约四项。但 `cards/README.md:57` 拼接只查信息重复与事件顺序；`skills/guyin-review/SKILL.md:29-36` 文字走报警片段漏斗、架构靠本地信号与作者抽检。现有流程不能稳定保证由有能力的审读者完整检查“设计的变化是否真的发生、场景为何值得读”。

所以不能再把“模型抄到一句话”当成兑现，把“脚本没有报警”当成无需编辑阅读。

## 3. 整改原则与作用边界

1. **先消除框架制造的问题，再实验增强能力。** 新增提示不能补偿反向硬禁令，也不能靠增加表格掩盖漏判。
2. **硬门管可判定的契约，不管普适审美。** 字数、状态、必要文件、明确禁泄露项可有硬门；短句、心理、解释、感官数量、爽点频率不得冒充普适正确性。硬门并非只能用于缺件。
3. **作者性与读者契约不是上下级。** 两者冲突时具体说明取舍，不能把作者风格一律覆盖，也不能只问气句而忽略当章任务。
4. **展示、概述、心理、解释都是工具。** 判断是否必要、是否重复、是否越视角，不按名称禁用。沉默、慢热、纯对话、无反打都可能成立，不要求额外特批。
5. **编排层负责理解，执行层收到足够事实。** 单 beat 架构可以保留作为成本选择，但不再被宣布永远正确；跨拍因果的传递及上下文损失必须测。
6. **不把工作转嫁成作者逐段救火。** 框架应产出带原文证据的诊断、有限候选和清晰取舍；作者判断偏好与最终接受，不替框架补每个漏掉的因果。

## 4. 工单 A：确定性工程修复

### A1. 检测结果、分诊与待审终态对齐

**落点**：`skills/guyin-write/scripts/guyin-check-beat.js`、`guyin-check-ai-patterns.js`、`guyin-check-pending.js`；`guyin-write/SKILL.md`；`cards/{README,自检卡,改写卡,分诊卡}.md`；setup 的待审台账模板及 `.claude/hooks/guyin-hook.js`；`tests/run-tests.js`。

**改法**：
- 时间概述词不再直接判 blocking 跳写；明确任务占位/未完成输出与普通叙述分开。是否跳过“必须展示”的事件交语义检查，不能靠删词修复。
- 连续带引号行、心理词频、短叙述段比例仅报告真实观测值及“需结合上下文判断”，不声称已检测无动作、心理独白过多或作品错误。取消由通用短段比例直接 blocking 的策略。
- 写章调用显式按 blocking 判断机械阻断，advisory 进入分诊，不因 exit 1 一律发改写卡。工具错误单独报告，不当作品错误。
- 为确认的误报/有功能写法增加明确终态 **“不适用”**：备注必须含原文位置及判定理由，不消耗每卷艺术豁免名额；真正违反已确认契约仍走修复、契约修订或作者豁免，不借该终态逃避。
- 同步脚本、hook、模板及消费说明：终态枚举从五种扩为六种，未知值保持未终态；升级作者仍须有已裁决内容，不能只写冒号；“不适用”缺证据也不关闭。所有路径不删历史行。

**验收**：§2.7 的过渡句不再要求补动作；连续带引号行不再误称无动作；advisory 可经证据分诊不改文；未知终态与空裁决阻断；脚本和 hook 对同一台账给一致结果；可机械识别的工程泄漏、确切禁项、任务占位/未完成输出和既有确定性契约继续受检。事件是否真正兑现属于 B2 的语义评测，不计作 A1 已保证的能力。不得仅删除旧测试来换绿灯。

### A2. 试读门改为可审计的反馈手续门，而非满意度认证

**落点**：`scripts/guyin-check-trial-gate.js`、setup `追踪/读者信号.md`、`guyin-write/SKILL.md` 的试读与大修路由、相关测试。

**改法**：
- 支持现有部署标题的括注形式，并用实际模板而非手造简化表头写回归测试。
- 明确区分“未试读、回答不完整、有效反馈待处理、作者已决定下一步”；脚本验证结构和关联，编排层消费反馈。有效的“无”“不想看”不是非法答案，空白/占位不是反馈。
- 在原试读记录末尾增加版本关联与处置信息：试读涉及的文件及内容哈希、相对偏好（可平/都差；非比较试读注明不适用）、原话、作者决定（修订/保留并说明原因/暂停）。哈希由工具计算，不能由模型编造；多章用有序文件—哈希列表，不能只存章范围。
- 第 4 章起缺试读文件、缺有效记录或版本不匹配，明确报告未完成手续；不再把读错误当“没有问题”。旧项目补齐手续由作者启动升级，不批量补造真人记录。第 1-3 章不要求预先有试读。
- 负面反馈保留并停在作者决策，不自动要求改成正面；同样不把“作者决定保留”改写为质量通过。任何“已批准继续”只能记录真实授权。

**放行表**（第 4 章及之后，放行只指手续完成）：
- 缺件、空答、版本不符、读取异常、有效反馈但尚未处置 → 不放行。
- 作者决定暂停 → 不续写；作者决定修订 → 允许修订目标章，不开放后续新章，修订后按新哈希重新完成试读手续。
- 当前哈希反馈完整，作者决定保留并明确授权继续 → 可进入其他写章预检；反馈为负面也保留原话，不篡改为质量合格。其他硬门仍独立有效。

**验收**：模板填完可识别；缺件/空答/旧哈希不计有效覆盖；负面反馈原话不丢、有明确处置入口；正文改动后旧试读不能冒充新稿试读；读取异常非成功；上述放行表逐项测试。脚本不能认证真人身份或文学品质，报告必须明示这一点。

### A3. 一个书级题材/读者契约来源，打通实际输入

**落点**：新增 setup `templates/long/设定/题材定位.md` 骨架；修改 `guyin-write/SKILL.md` 开书、补纲、读盘及文件契约；`references/细纲协议.md`、`references/consult/INDEX.md`、`cards/README.md`；setup 完整性清单与测试。

**改法**：
- 沿用已被引用的 `设定/题材定位.md`，不加入作者性第五件，不再新建重复的题材正文提示卡。
- 只保存书级约定：目标读者/可选平台、主要阅读回报、本书差异、阶段性期待与终局储备、允许的叙事手法/边界、对标作品及取用维度。无法确定的非必要信息明确未定，不伪造市场事实；非升级型作品允许注明不适用并说明替代的阶段变化。
- 开书进细纲前确保阅读回报和阶段边界有可用内容；沿现有 outline 检查器校验依赖文件及必要字段，不新增“genre-fit 好看评分器”。机械门不检测题材与收放风格是否匹配。
- 细纲将本章承担的承诺写入既有契约风险、情节安排和收益归属；执行卡通过背景、必须发生和必要笔法说明携带本场景的具体事实，不塞“装逼要快”等口号。不增三层同义字段。
- consult 全文仍按需查，不整篇下卡；方法须经过本书材料核实后编译，气句/魂档案原文的防泄漏边界保留。不能靠全库删“永不下发”来验收。

**验收**：在空测试项目完成契约生成、细纲消费及实际终卡生成；逐项指出承诺落实到哪个事件/反应。另验证 solo 读取路径、无匹配范文路径、混合题材路径。只 grep 模板多了一行不算接线完成。

## 5. 工单 B：创作能力改造，先试验后作为默认推广

### B1. 通用审美硬令改为场景工具；生成与后处理一起改

**落点**：批次公约感知模式区、`references/作者性引导.md` 的默认笔法、细纲密疏/黄金三章段、写作卡及组卡表、改写卡、`guyin-deslop/SKILL.md`、对应检查器提示与 setup 镜像。

**改法**：
- 保留高低压手法供选择，取消“一章只能一种模式”“高压只能短句”“情绪一律外化”“默认心理最多两句”“视觉不能入场”等普适约束。作者明确选择的书级写法仍保留，不擅自改用户个性。
- 密疏保留字数预算与重点分配，不强制感官层数、段长或标点句式。写不满先核查事件和关系是否有足够内容，不默认再填手、杯、筷、呼吸。
- 黄金三章保留读者入口与近期回报的设计责任，但不把所有书都套成能力展示+热怒笑；允许恐惧、好奇、怜惜、荒诞、关系兴趣等经具体情节成立的回报，允许有功能的心理和解释。是“给出本书成立的入口”，不是“每章填一个情绪词”。
- 统一即兑钩子粒度：前三章整体至少一笔声明的近期回报，各章可标承担/承接/不承担并引用该笔；每章单文件检查不应强迫造三笔。沿现有批次检查读取 ch001-003，显式解析兑现字段，校验正章号及声明时序；不以行内任意“第N章”冒充兑付。当前 ≤5 章只是开篇约定的现行窗口，不是全题材文学定律；特殊开篇由作者明确约定窗口，不自动生成豁免。
- 去味只在重复、失真、视角越界、说明替代了必要戏剧等具体问题上改；心理/情绪命名/解释本身不再是改写理由。删除保护继续生效，不以报警下降作为文学收益。

**验证**：同一中性任务比较旧限制与修订限制，保留原始生成、逐次修订、最终稿。检查改善是否发生于初稿，是否被改写/去味抹平；加入合法心理、直接情绪、视觉开场、时间概述、纯对白、慢热段等反例。工程上规则可解除，成稿是否更生动仍须 §6 评读。

### B2. 从“抄到一句”升级为因果兑现与完整章审读

**落点**：`references/细纲协议.md` 既有情节安排/信息差/行动成本收益、`cards/{README,自检卡,改写卡}.md`、`guyin-write/SKILL.md` 拼接步骤、`guyin-review/SKILL.md` 架构视角。

**改法**：
- 不新增张力三选二门。用现有情节点说明相关人物为什么采取行动、凭什么能做、行动后改变了什么；信息场景区分读者已知、人物已知和本次新增，关系场景允许变化在信任、立场或理解，不强制反转。
- 必须发生条目按完整结果验收：动作、关键承受者/反应、必要后果分别找证据；拆成一条一个结果或逐子项检查，不能抄台词就代替结果。证据不足填未兑现/无法判断，不得默认是。
- Q9-Q11 不再每 beat 强制补主动、信息、物件。先问此 beat 的功能，再检查它是否完成；开篇整体必须有可理解的参与理由与阅读回报，但听取信息、蓄势、关系余韵可合法承担其中一拍。
- 组卡优先保留该拍所需的动机、信息边界、限制及前后因果；删通用禁令和无关范文给事实让位。100 字前文与 500 token 上限不被视为天然充分，按实际模型计量验证，见 C1。
- 拼章后、正式状态提交前，由编排层或有能力的独立审读者**完整读一遍本章**，再结合相关细纲与前序状态核对：因果和收益是否兑现、人物是否仅在配合剧情、重复铺垫是否产生新作用、读者为何继续。报告引用前后句，不只统计字段。review 架构视角不得再用脚本信号冒充完整语义阅读。
- 初读与对照分开：读正文先记录真实理解，再看细纲核对，防把“设计者本来想写”误当“正文已经写到”。无能力完成全文审读时明确未验收，不能用零温、多票或摘要替代。
- L3 明确允许在作者确认后重设计情节点因果，再切 beat；不得只重新切分旧事件便称结构修复。涉及既有资产的改动继续走保护与影响核查。

**验证**：给出“台词完成但众人反应缺失”“已知数字被当新信息”“每拍都有动作但整章无变化”的人工标注坏例，必须能指出缺口；同时用戏剧反讽、共谋、关系回收、无代价能力兑现等好例检查误杀。模型自检有误判率，不能把新问法视为保证。

### B3. 有限候选、整章比较与状态隔离

**落点**：`guyin-write/SKILL.md` 外选/大修/写章链、`cards/改写卡.md`、现有逐章记录约定；状态隔离及提交测试。

**改法**：
- 外选依据改为“是否完成本场景的阅读任务、人物是否可信鲜活、是否符合作者选择的表达”，引用稿件证据；不把每个场景都问成“哪个更爽”。允许平局、两稿都差、没有足够证据；不承诺选优确定性。
- 大修前冻结旧稿、目标问题、保护资产与可接受代价；比较范围覆盖完整改动及上下游，整章改就读整章，不能只读章首 300 字。记录问题消除、新问题、表达损失和读者偏好，机械减少报警不直接计净收益。
- 不默认前三章或 L3 各产 2-3 整章。先按一次明确修订假说产一版，与保留的原稿比较；需要多采样时先声明候选数与费用上限。相同预算下比较方法，而非给新法更多抽卡机会。
- 候选放在独立临时项目快照中，均从同一正文/追踪/指纹基线开始；一候选一目录。依赖提交态的全链检查只在各自快照中执行，失败候选也留记录，不共享正式追踪文件。
- 仍使用 beat-writer 时，由编排层为每个候选独立顺序组织各 beat；不能直接让单 beat agent 写整章。更大场景单元可另作等预算试验，不在本轮暗换架构。
- 选定后由编排层重新核对正式基线未变，按既有存档、正文发布、追踪重提交与指纹提交流程串行发布；不复制候选整棵追踪树覆盖正式项目。任何一步失败保持未完成、阻止续写并按原事务恢复规则处理。
- 无净收益不默认覆盖原稿；纯品质润色保留旧版。若旧版存在必须修复的事实/安全契约错误，即使阅读偏好平局仍须单独处理，不用“保旧稿”掩盖硬错误。达到事先预算或没有新修订假说时停，不再机械重写第十几版。

**验证**：A/B 候选使用不同道具、事件与伏笔，未选候选不得进入正式状态；候选失败不改变基线；胜出发布后正文、摘要、追踪、指纹同版；正式基线已变则拒绝覆盖。没有实际隔离测试，不启用整章多候选流程。

### B4. 对标要提供机制与材料，不是给范文换书名

**落点**：`guyin-analyze/SKILL.md` 既有拆文/对标产物、`references/exemplars/README.md`、取片规则及书级题材定位；不新建宏大方法论库。

**改法**：
- 区分市场定位、情节/关系机制、句法手感。取片按本场景功能、视角与叙述距离匹配，题材是辅助条件，不以文件名字符串作为唯一确定性路由。
- 《隐杀》《晚明》《铁血残明》分别列为用户的质量参照，不能把后两者合并成一个“历史种田风格”。本轮没有完成三书原文对标研究，不冒充已得到其成功公式。
- 对标材料应回答可迁移机制：能力与生活关系如何共存、信息差如何产生期待、利益和制度如何限制选择、资源/组织如何形成后果。历史战争类还需有依据的制度、兵粮、地理与社会经验材料；心理/关系类需动机、经历与关系阶段。放入既有设定/角色/对标来源，不靠更多感官替代。
- 原文切片仅用合法可用来源，并按现有规范保留来源与私有使用边界；不能把未授权原文新增到公共技能仓库。教学自写例明确标为原创示例，不能冒充原作证据。
- 当前库存没有这三本具名切片，不等于没有任何可迁移样本；库存切片 500-1000 字与下卡约 300 字也不是同一规格。无匹配材料时如实报告缺口，使用明确标记的示例或暂不取片，不伪造“原文已补齐”。

**验收**：每条提炼可追溯来源及适用条件，实际终卡选择理由可解释；分别测试同题材不同场景、跨题材同机制、无样本三种情况。版权/来源未满足时，对标能力项标未验证，不妨碍 A 类工程修复，不得把整项写成完成。

## 6. 效果实验：防止第十四轮仍只证明“表填得更好”

### 6.1 两条轨道，不互相冒充

- **工程轨**：固定夹具与断言、模板实例化、脚本/hook 同步、状态隔离。判断实现是否符合约定。
- **作品轨**：真实目标执行模型生成正文，独立评读。判断读者是否获得更多、人物是否更活、是否更想继续。没有正文或真实评读，状态只能写“工程完成，效果未验证”。

实验使用专门构造且可公开的框架任务或用户另行授权的素材，不打开、不重写用户小说。既有 v12 可作故障解释例，不同时充当新判据的唯一训练样本和唯一验收样本。

### 6.2 冻结实验记录

每次开跑前记录：待检验假说、基线版本、任务/输入哈希、模型与实际可见上下文、生成参数（不可控写不可控）、候选数、总费用/调用上限、改写次数、评读问题、主指标、判平/判负规则、进入整章验证的条件与停止条件。全部初稿、终卡、改写过程、脚本真实命令/输出/退出码和评读结果保留，失败稿不得消失。

默认筛查主指标为目标读者的“愿意继续”比例，每个独立任务等权，不用重复生成次数替某个任务加权。数值相同记平，低于基线记负；缺评读记缺证，不记平。某类场景进入整章验证的条件是：该类两项独立任务的新法主指标都高于旧法，相对偏好未倒向旧法，没有新增未解决的确定性契约错误，且未超预定成本。仅该类别晋级，其他类别不搭便车；这是预算内继续试验的门槛，不是统计显著性或品质达标证明。若实验目的需采用不同主指标或晋级条件，必须在看结果前记录理由并冻结，禁止事后换口径。

不得把手工模拟检查写成脚本执行，不得声称未调用的模型参加实验，也不得伪造真人试读。无法获得目标低模型或外部读者时明确缺证，不能以当前主模型代跑后宣称跨模型有效。

### 6.3 最小试验顺序

1. **先测约束影响**：同场景设计、同模型与预算，只比较旧通用笔法限制与 B1 修订限制。逐阶段保留稿件，判断损失发生在初写还是去味。
2. **再测因果供给/审读**：固定已选写法，对比原输入与 B2 的具体因果信息和结果验收；新增信息与新增审读若同时改变，只能报告组合效果，不能分别分配功劳。
3. **再测选择方法**：固定候选池，对比旧外选与 B3 外选，避免把“多花钱生成更多稿”冒充判别能力增强。
4. 若仍无改善，再以独立实验比较同 beat 输入在不同实际模型的表现，以及单 beat 与完整场景组织的差异；不得未经这一步就继续归咎模型或宣布骨架无关。

首轮建议作为预算有限的筛查：3 类场景（能力/关系反差、利益/制度博弈、低压生活或悬疑信息差）× 每类 2 个独立任务 × 新旧各 2 次生成，共 24 份场景稿；此数量是成本选择，不是统计充分性保证。每个实验变量单独使用该设计或预先缩小并声明结论范围，不要求将全部试验一次做完。

至少覆盖实际计划使用的低模型路径；solo 如也声称支持，则另测并单独报告。方法未稳前不强制长篇全量生成；候选方法出现一致改善后，再用未参加规则设计的完整开篇组和连续章节片段验证跨 beat、跨章关系与状态。

### 6.4 判读与判负

- 匿名、随机呈现顺序；先独立问每稿想不想继续、记住了谁/什么、哪里退出，再问相对偏好。相对赢但两稿都不想读，应记录“双差中较好”，不是质量达标。
- 作者评偏好，另尽量取得至少两位未见设定和方案的目标读者反馈；没有外部读者就只报告作者/模型判断，不混成市场证据。该人数同样不代表统计显著。
- 以实际获得的因果理解、人物识别、情绪/兴趣及继续阅读意愿为主；检查器误报、事实一致性、耗时/成本为共同约束。不能为了爽点破坏设定，也不能因语法规整就判更好。
- 平局/负向结果全部保留；无明确改善则不将该创作假说升级为默认强制，退步则保留基线并查发生阶段。明确的工程缺陷修复独立保留，不因文学试验平局而恢复误报漏洞。
- 允许预先设计的重复实验、独立复验及新假说；禁止选择性报告、换样本直到胜出、游说读者改判。小样本只支持局部采用，不能外推“任何题材都有效”。

## 7. 工单 C：部署、预算与回归交付

### C1. 先替换再增加，不靠悄悄放宽预算过关

- 删除/压缩已撤回的通用硬令、重复解释与失实实证结论，腾出契约及全文审读入口；细则留在既有 references/cards，不把整套审计常驻主提示。
- 使用 `scripts/check-doc-budget.js` 检查静态预算，同时保存实例化后的终卡，使用目标模型 tokenizer 或实际 API usage 计量。不能用模板字数、英文估算或“约 300 token”充作中文终卡实测。
- 对原 <500 token 约束先测是否可容纳必要因果和范文；若不能，优先删无关范文/通用禁令，不砍必要事实。仍装不下时提交实际 token、成本、遗漏项与效果对照，再调整合同预算或试验场景单元，不能静默截断或凭空填一个新阈值。

### C2. 旧项目升级与三端一致性

- 修改 `guyin-setup/SKILL.md` 的陈旧 solo 说明；涉及 agent 提示时同步长篇三端部署件，并检查短篇叠加的共享行为，不顺带重写短篇架构。
- 保持用户内容 create-if-absent。更新技能只刷新受管理部署件；对旧批次公约、语言纪律、AGENTS 等输出差异及待仲裁项，由用户另行启动项目迁移并确认，不静默覆盖。
- 框架仓库通过隔离旧项目夹具验证迁移报告、用户自定义内容保留、重跑幂等与冲突显式化；报告必须区分“技能已更新”与“项目旧规则已处理”。
- 本任务不修改真实项目，也不修改用户权限、真实宿主模型配置或远端部署。未来确需调整 CI 检查清单时单独说明变更，不通过跳过检查隐藏失败。

### C3. 验收矩阵

| 层 | 必验内容 | 不能冒充什么 |
|---|---|---|
| 语法/契约 | 修改脚本 `node --check`；`node scripts/check-skill-contracts.js` | 不能证明调用时实际读到了契约 |

| 自动回归 | `node tests/run-tests.js`；补 A1/A2 正反例、模板实例化、候选隔离与发布失败用例 | 不是文学质量回归 |

| 作品效果 | §6 的全部生成和匿名评读，合法反例与低压题材不被系统性误杀 | 不以“多数表格已填”替代阅读体验 |
| 长期能力 | 独立开篇组、连续章节及对标材料覆盖 | 未测不得宣称支持名作级长篇生产 |

本轮只做审计、10 个现状行为用例及预算盘点，**没有运行改后回归、没有生成新框架作品、没有获得新真人试读、没有完成上述实施验收**。

## 8. 执行次序、依赖与停止点

1. **第一批 A1+A2**：先固化本轮故障夹具，再修检测/终态/试读接口，核对脚本、hook、模板和调用一致。可单独交付工程修复，不宣传提分。
2. **第二批 A3 与 C1/C2 对应部分**：单一书级契约和输入传导，空/旧项目演练；保留对标未定和材料不足的真实状态。
3. **第三批 B1 试验 → B2 试验**：每步留下基线和负结果。B1 涉及开篇字段改动时必须同步协议、解析器、模板和测试；B2 不以增加更多每拍配额为代价。
4. **第四批 B3**：在隔离/发布测试通过后才开放额外候选；先旧稿对一份修订，不默认三稿；审读与选择的成本也计入预算。
5. **B4 按材料条件推进**：能核实多少写多少，不等待三本对标全到手才修工程，也不因工程通过而宣称对标达成。
6. **C3 与作品轨共同结案**：分别列“已修、仅工程完成、效果支持的适用范围、无提升/退步、仍未验证”。用户小说的升级和重写是后续独立授权事项，不列为本次框架整改的完成条件。

依赖与停止点：A1/A2 失败不得开展正式候选发布；终卡因果信息不完整不得以模型表现差结案；无目标模型/合法素材/真人反馈时暂停相应效果主张，仍可完成其余工程工作。完成所有文档改动不是自动获得下一个阶段的质量认证。
