# 框架总诊断与重构方案（第四版 · 证据审计与叙事闭环）

> 修订日期：2026-09-16。审计基线：guyin-skills `e2a75fa`。
> 状态：**方案已修订，框架尚未据此实施，作品效果未验证。** 本版替代本文件第三版的诊断与整改安排，不把方案当成运行事实。
> 范围：只优化 guyin-skills 技能框架。本次只修改此文档；不改小说正文、设定、细纲或追踪，不操作外部小说项目。后续由用户更新对应项目的技能、生成新章节并验收。
> 目标：不是让小说更像合格报告，而是提高产生**好看、有趣、人物可信且可持续追读**的作品的能力。《隐杀》《晚明》《铁血残明》是质量参照，不是统一文风模板，也不是框架已达到的水平。

## 0. 审核结论：方向部分正确，根因与处方必须改写

第三版抓到了一个真实问题：执行层仍有“填空式写手”的定位，创作权限和流程约束需要重审。但它把这个问题归结为“低模型从未运行”，继而主张废除 subagent、只允许主模型分饰三角，并认为原检查链不动即可。这条因果链没有足够证据，且与当前仓库中已经存在的 solo 直写协议矛盾。

**本版的核心判断是：优先重构的不是模型数量，而是创作决定如何生成、传递、接受反馈的方式。** 当前协议存在可核实的冲突：上游允许因果与人物设计，下游仍要求逐拍填空、逐项补句；粒度配置允许整章，agent 却禁止整章；整章审读强调阅读效果，逐拍验收仍能先把正文修成可勾选的形态。

由此提出的**待验证主假说**是：框架把“对事先描述的忠实”和“局部信号齐备”当成了过强的控制目标，完整场景中的人物行动、读者体验和后果积累反而失去优先权。这比“某个低模型没接通”覆盖更广，也更值得优先改造；但不冒称已经证明了所有小说质量问题的唯一根因。

### 0.1 第三版不合理之处与本版裁决

| 第三版判断或动作 | 审核结果 | 本版替代 |
|---|---|---|
| “三端分离就是三模型分离” | 概念混淆。三端是 Claude Code / Codex / OpenCode；角色数、调用数、模型数是不同维度 | 分开描述宿主、角色、上下文、实际模型，不再混用 |
| “模板未配置 model，证明低模型从未运行” | 不成立。静态模板不是调用日志；继承同一模型也不必然等于没有独立 subagent 上下文 | 运行事实只认宿主实际调用与可获得的记录；未知就写未知 |
| “solo 必然按任务卡填空” | 与现行 SKILL 的“允许读细纲直写、卡可选”相冲突 | 排查仍被强制执行的逐拍门禁和相互矛盾的契约，而非再宣布一次已存在的权限 |
| “多模型时零创作权合理，单模型时才不合理” | 无证据。压缩任务可能帮助弱模型，但零创作判断不是合理的普适前提 | 无论由谁执笔，都需要足够的因果信息与有边界的表达权 |
| “创作权是趣味的唯一来源” | 过度归因。趣味还依赖选材、人物、结构、信息安排、兑现与修订判断 | 创作自由是必要空间之一，不是充分条件；允许自由也可能产出套路 |
| “删掉低模型和三端部署，solo 成为唯一路径” | 错把部署策略当文学解药，并损失隔离上下文和可选模型的能力 | 默认适配用户现有环境，保留可选 subagent；不强制采购外部模型，也不禁止它 |
| “提示词中的高温/零温使角色真正分离” | 不成立。角色提示不改变未开放的采样参数，也不能清除主会话已见的细纲 | 参数由宿主确认；信息隔离由调用边界实现；同会话审读如实标为自审 |
| “脚本＋自检卡都是零温机械，不必改” | 错。自检卡明确包含语义题；确定执行的正则也可能只是文学判断的弱代理 | 重分硬错误、待核实信号、编辑建议，改造处置链，不只换提示词 |
| “正确性门禁与趣味正交” | 目标可区分，操作不独立。补字数、补反应、删句式都可能改变节奏与人物 | 每次修改同时审查错误是否消失、表达是否受损 |
| “现有读者信号会随解禁自然激活” | 无效果证据；模型自检也不等于真实读者反馈 | 保留读者信号，建立正文证据、用户反馈和失败归因的闭环 |
| “必须出现细纲外涌现，末尾附一行登记” | 把意外变成指标，容易强塞动作并污染正文 | 不要求涌现数量；有价值才保留，持久事实才登记，元数据与正文分离 |
| “重写旧 ch001 作为必做验收” | 与本次授权边界不符，且单章不能证明长期积累或跨题材能力 | 用户后续生成新章节验收；旧章不动，对照试验仅在另行授权时进行 |

保留第三版的合理方向：取消“填空即作者”的定位；保留可靠的事实与状态保护；不给趣味制造自动评分器；实际阅读效果高于方案自我论证。

## 2. 更深层根因：三个结构性失配，而非一个模型开关

### 2.1 设计对象失配：事件清单不等于能持续产生故事的关系与局势

现有细纲已要求因果，但执行接口更容易保存“发生了哪几件事”，而不是“为什么这些人只能作出这些选择、读者此刻在期待什么”。如果上游只完成栏目，人物就会配合剧情，阻碍就会按时出现，收益就会由旁白宣布。

重构目标不是再添“人物鲜活”“有灵魂”字段，而是让已有设定、卷纲和细纲真正回答并传递：

- **人有自己的意图**：主角与重要配角分别要什么、知道什么、误认什么、能做什么；配角不因主角需要就改变立场。
- **世界会回应行动**：资源、制度、关系与时间构成约束；行动改变局势，局势又改变下一次选择。生活流也可以由关系、习惯和认知变化驱动，不必强造敌人。
- **回报属于具体体验**：能力被看见、关系更近、谜面获得解释、荒诞让人发笑、生活值得留恋，都是回报；不是人人夸主角，也不是每章一次反转。
- **进展能长出新处境**：不是只换更强对手，也不是每次收益都必须被代价抵消。已经赢得的东西应真实存在，并改变可选择的道路。

“魂”的工程落点是人物一贯而非机械的选择、作品反复关心的生活矛盾，以及这些选择留下的后果。作者性口述可以帮助选择，但填出一个哲学标签不等于作品有灵魂，更不能把生成失败归咎于用户没有提供足够人生故事。

### 2.2 生产对象失配：完整场景被切成多个先验合格的小片段

beat 适合标记节奏，不应天然等于独立模型调用、固定字数桶与必须即时修完的交付单位。一个对手戏的试探、误读、停顿和余韵可能跨越多个 beat；反复重启和只保留尾部原文，会增加重复起腔与局部闭合的风险。

把章写长也不是解药。正确原则是：**在模型可承载范围内，优先保持最小完整戏剧过程；需要拆分时按场景/视角/时空边界拆，而不是按字数机械切。** 字数是交付要求，不是内容生成原因。

### 2.3 反馈对象失配：检测到一个信号，就生产一个满足信号的句子

“缺反应→补反应句”“缺记忆点→补狠话”能够提高勾选率，却未必提高可信度或记忆度；先大量修局部再审整章，可能已经损失了原本可保留的表达。即使正文由最强主模型一次写完，这条返工链仍会发生。

当前框架已提出“宁糙勿滑”“修改要有净收益”，因此问题不是缺口号，而是**这些原则没有在所有分支拥有一致优先级**。应把反馈落到实际缺陷的发生层：事实错修事实，人物选择无由修动机，事件没有阅读价值回到场景设计；不能把所有问题都送进句子改写。

### 2.4 主假说与可证伪条件

```text
局部规格过密 / 必要因果在传递中受损
    → 执笔优先逐条兑现，而非形成完整阅读过程
    → 局部检查先奖励“信号存在”，不足就补句
    → 整章即使通过检查，仍可能人物工具化、回报失真、表达同质
```

这是一条需要验证的机制假说，不是对用户小说的既成判决。若新流程能保留上下文、完成场景并减少表面返工，但用户仍不想读，应转查选材与情节本身、材料真实性、模型能力或审读偏差；不能继续宣称“只差再放开一点创作权”。

## 3. 新架构：书级选择 → 滚动规划 → 连续创作 → 分层审读 → 后果回流

### 3.1 架构原则

1. **质量优先，模型中立**：不以低模型为唯一前提，不强制换模型；模型、上下文规模、调用成本和效果分别记录。
2. **职责分离，信息按需**：编排负责选择与事实边界，执笔负责连续表达，审读负责发现实际阅读损失；角色可以共享模型，不能伪装共享模型等于独立判断。
3. **约束收缩到真实契约**：已发生事实、视角知情边界、用户明确保密项及锁定结果是边界；动作顺序、台词、叙述距离等尽量保留实现自由。
4. **先生成可读整体，再修非致命局部问题**：中途发现确定的事实越界可立即停止；不在每拍插入整套文学问答。
5. **替换旧契约，不叠一套新术语**：下文是对现有字段与流程的重排，不要求每层新增同义卡片、评分表或台账。

### 3.2 信息权威与消费链

| 层级 | 复用的现有载体 | 主要保存什么 | 谁实际消费 |
|---|---|---|---|
| 书级选择 | `设定/题材定位.md`、`作者性/` | 主要阅读回报、叙述约定、关注的问题、不可擅改的选择 | 卷/单元规划；编排据此为执笔选材，不下发哲学口号 |
| 人与世界 | `设定/角色/`、`设定/世界观/`、既有追踪 | 人物目标/关系/能力限制、世界规则、带来源的题材事实 | 场景设计与执笔上下文，审读用来核实因果 |
| 中程规划 | `大纲/卷纲_*.md` | 当前局势、阶段目标、尚未兑现的承诺、关键后果与备选走向 | 当前章设计与后续滚动规划 |
| 近程设计 | `大纲/细纲_第XXX章.md` | 本章阅读任务、场景因果、知情差、已锁结果和实现自由 | 直接执笔或由编排组装必要上下文 |
| 创作结果 | 正文候选、`追踪/逐章记录/第NNN章.md` | 正文与审读证据分离；记录实际调用、修改及未解决项 | 编辑、用户验收、正式发布 |
| 持久后果 | 既有角色状态、伏笔、事件资产、`追踪/上下文.md` | 谁改变了看法/立场，什么资源或承诺变了，哪些后果会约束下一章 | 下一章读盘与单元规划；通过既有追踪事务提交 |

每项新要求必须说得清“来源、消费者、失效后的处理”。没有消费者的字段不加；纯修辞变化不写成世界状态；正文才是“发生过什么”的证据，细纲是意图而非已发生事实。

### 3.3 上游：从十章全部细化改为分层滚动

保留卷级方向与阶段储备，但不默认把未来十章全部写成十多节点的确定剧本。初始建议是**当前章细化、后续2—3章保留承接与后果、较远章节留里程碑**；这是可调起点，不是新的字数式硬门。

- 已经获得用户批准的既有细纲不自动删改；方案只约束后续新建或用户授权修订的规划。
- 章细纲保留核心事件、人物目标、信息差、逻辑线、回报/收益、保密边界与承接；合并重复的五段式、结构公式、事件复述，不要求同一情节填三遍。
- 点数、情绪落点数、场景数量、密疏预算不再充当普适文学标准。特定书的长度与交付约定仍要明确。
- 章末允许情绪余韵、关系期待或阶段目标承接，不强制把每种继续阅读的理由都做成实体谜物和悬念问句。
- 需要比较走向时，最多先提出2—3个**人物选择/局势后果真正不同**的简案，再选一个落地；普通场景不默认多采样，更不靠五种感官入口冒充结构搜索。

### 3.4 执笔：以完整场景为默认连续单位，允许承载得住时整章

重写 `guyin-beat-writer` 的职责，不以名字决定粒度，也不为改名另起一套 agent。beat 留作内部节奏标签；默认连续写一个完整场景，短章或模型能承载时可整章；能力或输出上限不足时在自然边界拆分。

将现有写作卡替换为一份按需的创作简报，只有三组信息，不再叠加新的情绪配额：

| 组 | 内容 | 权限 |
|---|---|---|
| 不可擅改 | 已发生事实、人物知情边界、明确保密项、用户锁定的结果 | 发现冲突要回编排，不靠即兴自圆其说 |
| 本场需要成立 | 人物分别想做什么、为何受阻或相遇、这一场给读者什么、前后状态怎样衔接 | 是设计意图，不是指定必须出现某句反应；未成立则查原因 |
| 可现场决定 | 台词、行动细节、叙述节奏、幽默、心理、转场及不改变事实边界的局部走向 | 执笔自主决定；不得为展示自由强塞“计划外惊喜” |

上下文不再只等于上一拍100字。编排提供**本场完整必要背景＋与当前关系/伏笔直接相关的原文＋连续声线锚**；这些从已有权威文件按需提取，不把全书、consult 库与检查词表全部灌给执笔者。若无工具的 subagent 缺材料，由编排补齐或缩小到仍完整的场景，不静默删掉动机与限制来凑卡预算。

改写后的所有调用方式遵守同一创作权限：

- solo：同一主会话顺序完成，承认审读只是自审。
- 同模型 subagent：可隔离执行上下文，但不声称形成了独立模型意见。
- 不同模型 subagent：仅在用户已配置且宿主实测可用时选择；是否更好仍待作品验收。
- 参数不可控或模型身份不可见：记录“宿主默认/未知”，不得用“高温作者”“零温编辑”替代真实配置。

正文输出保持纯净。局部创意无需尾附“本拍涌现”；会影响后续的变化由编排在章审后单独对账。一般细节可以只在这一场存在，不必转正为伏笔，也不考核涌现率。

### 3.5 审读：事实门、语义核实、阅读判断分开

**确定性执行不等于判断对象确定。** 脚本能稳定检测某词或句式，不能因此断定它伤害了阅读。

| 类别 | 例子 | 应有处置 |
|---|---|---|
| 工程与明确契约错误 | 文件损坏、章节版本错配、状态事务未完成、已确认的用户硬约定未满足 | 阻止正式发布/续写；按明确错误修复，不用文学偏好豁免 |
| 需要上下文核实的风险信号 | 可能剧透、角色知情越界、资产被否定、锚句改写后可能失义 | 保留原文和上下文，语义复核；确认触及硬契约才阻断，未能排除重大事实风险则暂停 |
| 编辑与风格观察 | 对话比例、短段比例、比喻频率、心理长度、疑似套话、记忆点不足 | 观察不自动判错，不因计数直接改稿；要有具体阅读损失与修改假说 |

字数可准确计数，但不足时不能自动补杯子、呼吸或多余对话。先判断场景内容不足，还是长度约定与本章任务不匹配；前者修结构，后者由用户决定是否调整约定，不能静默放行或填水。

复用现有4a两段审读，调整其优先级与处理单位：

1. **第一遍只评价正文呈现**：我在期待什么、哪里开始无聊/困惑、人物为何值得关心、哪里真正兑现。引用原文，可答“不知道/没感觉”，不按细纲替正文补解释。
2. **第二遍核对因果与契约**：动作为何发生、凭什么成功、改变了谁/什么、后续承诺是否被偷走。后果可延迟显现，不强制每个动作后跟反应句和总结句。
3. **按根因分诊**：措辞问题走 L1；场景执行问题走 L2；人物动机、事件价值或承接出了问题走 L3/回规划。结构问题不能用局部补句掩盖。
4. **证据与不确定性对称**：判“真问题”和判“有功能”都须说明上下文依据；不用三次同模型投票制造真相，也不把证据句存在当效果成立。

若宿主支持独立上下文，第一遍审读优先只传正文、必要前文与读者定位，不传细纲、意图说明、候选排名或作者自评；否则如实标“同会话自审，存在先验污染”。模型审读帮助找问题，不能冒充真实读者。

### 3.6 返工：先结构后语言，保护净收益，允许停下

保留现有“修订假说＋表达损失对照”，将它提升为所有改写分支的共同规则：

- 一次只修一个主缺陷，先说明证据、预期收益、要保护的内容；不是先列十条风格建议。
- 结构失败先修人物选择与场景后果，不先去AI味；尚未产生有效事件时，辞藻加工没有意义。
- 默认一轮结构修订，确有必要再做一轮局部语言修订；这是成本上限的初始策略，不是保证两轮成功。达到预算或没有新假说即停。
- 比较整场/整章的阅读得失，不只数报警减少；可以判平、都差、无净收益。
- 已有版本未经批准不覆盖；候选、正式正文和追踪隔离。对新章可报告“未通过，暂停”，不能把失败候选当正式完成章继续累积。
- 硬事实错误仍须处理；“旧稿更有味”不能成为保留错误的借口。反过来，风格信号未清零也不必磨平一篇可读正文。

### 3.7 发布与长期积累：让下一章真正读到上一章造成的变化

统一顺序为：

```text
读取权威状态与当前规划 → 形成必要上下文 → 连续写场景/章候选
→ 工程检查与完整章审读 → 必要的定向修订和复查
→ 确认本次发布版本 → 正文发布＋摘要/状态事务提交＋指纹提交
→ 最终一致性核验 → 后果回流到下一章
```

需要文件才能检查时，先写隔离候选，不因此提前提交正式追踪。正文、摘要、追踪与指纹尚不同版就标未完成并阻止续写；“多个文件先后写过”不等于跨文件原子事务，失败恢复沿用并补测现有恢复机制。

复用角色状态、伏笔和 `上下文.open_threads`，保存已经在正文发生且会影响未来选择的关系、资源、认知、承诺变化；不再只保存“发生了三个事件”。远期里程碑如果被正文产生的合法后果影响，应显式重排，不能把人物拉回旧剧本。

不另造“灵魂数据库”。灵感台账只登记值得跨章保留的内容；普通闲笔不强制转正、不自动补替代物。已形成连续性事实或用户明确保护的资产仍须维护，删弃要有可追踪理由。

## 4. 跨题材的高标准，怎样避免落成一种腔调

本版没有开展三本参照作品的原文研究。下面是**拟验收的质量维度与研究问题**，不是已证实的名作公式。后续拆文须基于用户合法提供/可用的材料，标清证据来源与未验证部分，不把书名写进提示词就算完成对标。

| 创作方向 | 应优先研究与检验 | 不能误用的替代品 |
|---|---|---|
| 能力型爽感与日常关系并存（以《隐杀》为质量参照） | 能力如何改变具体处境；信息差如何制造期待；日常关系为什么值得留恋；收益是否真的归属人物 | 万能强者＋所有人惊叹；每章“压抑再打脸”；用几件生活物品冒充温度 |
| 历史、战争与社会运行（《晚明》《铁血残明》分别对标） | 人的私利/恐惧如何与组织、资源、制度相互作用；行动成本和胜负后果是否可信；各书如何组织幽默、压力与群像，分别举证 | 堆官名兵粮术语；人人像现代项目经理；为“厚重”强行牺牲与苦难 |
| 悬疑 | 读者已知与人物已知怎样变化；猜测何时有依据、何时被修正；解答是否支付悬念债 | 把关键信息藏到最后；反复说“另有隐情” |
| 言情、关系与生活 | 人物互相吸引/误读/回避的具体原因；日常交往怎样改变理解与亲密；舒适与余韵是否真实 | 误会循环、强塞冲突、满章金句；把“不推进主线”等同无用 |
| 成长、幻想、科幻及其他 | 本题材主要回报是什么；规则怎样影响选择；进展怎样改变生活与关系；读者为何愿意留下 | 把所有题材套成历史权谋；把升级等同数值递增 |

拆文产物保留“定位/机制/手感”三层，并为关键机制补上**原文位置—前置条件—人物行动—读者获得—适用边界—当前项目如何取舍**。机制提取与句法示例分开：前者进入规划，后者按场景选用；不复制原作人物、情节与措辞。

“有灵魂”不是单独加一个深刻主题环节；是人物没有在冲突中被临时换脑，作品关心的东西会影响选择，事情过后真的留下痕迹。允许轻盈、幽默、单纯的快乐，不把复杂、沉重或悲剧当高级的同义词。

短篇复用创作权限、分层审读和因果原则，但仍以现有情节节点、情绪曲线、反转表组织完整体验；不照搬长篇的滚动卷纲、十章记忆和长期升级。其回报期限按篇成立，不硬套黄金三章或第4章试读门。

### 5.1 检查链必须逐项审计，不能“一律保留”或“一律降级”

逐项记录：检测对象、输入、确定性边界、是否需要上下文、严重级别、下游动作和误报样例。重点覆盖：

- `guyin-check-beat.js`：禁词/禁止项、字数及对话/独白观测；移除对固定beat调用形态的依赖，不损坏明确的用户硬约定。
- `guyin-check-outline-slots.js`、`guyin-check-opening-retention.js`：伴随细纲瘦身更新字段契约；有字段不等于语义成立，不能继续以普适能力展示或固定情绪数冒充开篇质量。
- `guyin-check-outline-deliver.js`：区分世界内必须逐字一致的原话与可自由表达的设计意图；不因同义改写自动改正文。
- `guyin-check-ai-patterns.js`、`guyin-check-authority-leak.js`：分清工序内容真的泄漏、明确禁令被触犯，与正常词语/心理/解释被误报；不能只看命中字面。
- `guyin-check-wordcount.js`：保留长度核验，但修改“不足就补细节”的默认响应。
- `guyin-check-pending.js` 与部署 hook：与新的分类一起调整，避免主流程把风格信号设为观察，hook却因任一未结项阻断；事实风险未裁决仍不能静默继续。严格匹配终态，拒绝“未修复”等相似字符串；区分合法缺件、权限错误和损坏，无法读到状态就不能宣称已清零。

脚本应输出可消费的类别、严重级别和证据，调用方按字段处置，不把exit 1一律理解为“必须改正文”。工程检查失败、审读未完成、等待用户裁决和普通风格观察必须可区分；“已裁决”文字存在不证明用户真的授权，需能对应用户决定。

这项整改须连同脚本输出、调用方、台账终态、hook和测试完成；只改 advisory 字样、把全部问题写成“不适用”，都不算完成。hook是特定宿主/工具路径上的保护，不宣称能拦住所有写盘方式；在支持的入口测试其与状态生产者的schema及字数口径一致。

### 5.2 删减清单：防止重构又变成规则堆积

- 删除“执行层永不见必要背景”的绝对化表述，替换为“不接收无关全局与检查噪音”。
- 删除默认逐beat全套语义验收、缺项必补对应句、必补记忆物件。
- 删除强制五感入口、前两候选必差、普通高潮默认多次采样等无验证依据的选择规则。
- 删除普适情绪次数、场景次数、段长、比喻域轮换对创作的硬控制；用户明确选定的书级风格保留。
- 删除“有创意必须脱纲”和“灵感转正率越高越好”；连续性资产保护保留。
- 删除以词频清零或检查全过作为“更好看”的结论；工程检查保留。
- 不新增“趣味总分”“灵魂分”“名作相似度”，不把本方案全文塞进每次写章上下文。

### 5.3 技能更新与项目部署不是一回事

用户后续更新技能，不代表旧项目里的 agent、hook、AGENTS 路由及 create-if-absent 模板会一起更新。实施交付必须附**升级差异报告与受控更新入口**：

1. 先识别技能版本、实际加载路径、宿主能力与项目部署版本；不把仓库已改误报为用户项目已生效。
2. 区分框架维护片段和用户修改；先展示差异，用户确认后才更新项目部署。保留用户model/provider配置与额外路由。
3. 模板默认值只影响新项目；旧小说的正文、设定、细纲、作者性与追踪不自动迁移。涉及协议转换时，单独说明并取得授权。
4. 更新后做不生成小说的能力与路由检查；未支持或未验证的端如实列出，不宣称三端都跑通。

本次不执行上述升级，也不替用户修改任何项目权限或配置。

## 6. 验收：工程能运行、创作有改善、跨题材可迁移，分开判

### 6.1 工程验收由实现方负责，不拿小说当试验耗材

用仓库内最小合成片段与临时项目做回归，不调用用户小说作为可写测试数据。至少覆盖：

| 测试 | 必须证明 |
|---|---|
| 多种调用形态 | solo、继承同模型的subagent、已配置其他模型、agent不可用时的路径能被正确区分；未测宿主标未验证 |
| 权限与上下文 | 允许的局部实现不被判越界；已知事实/信息边界冲突能被识别；必要前情不因预算被静默丢弃 |
| 连续创作 | 场景可以跨beat完整生成；不再每拍强制补反应/后果；输出截断不会作为正式章发布 |
| 反同质化 | 合法心理、长对话、概述、余韵、不同题材情绪不会因单一表面规则强制改写；真正工序泄漏仍被处理 |
| 规划与后果 | 角色/资源/关系的变化由正文证据进入既有状态，并能被下章读盘消费；规划意图不冒充已发生事实 |
| 发布与恢复 | 未选候选不入正式追踪；状态或指纹提交失败会阻断续写；正式版本变更时旧候选不能覆盖新基线 |
| 反馈来源 | 用户验收、第三方试读、模型自审分别标注；负面反馈与“都差”可保存；版本不匹配会失效 |
| 部署 | 技能升级与项目部署更新可辨；用户自定义model/路由保留；小说文件不被覆盖 |

**执行前置：先完成P0的测试隔离。** 当前 `tests/run-tests.js` 会读取外部小说项目（E17），本次没有运行，也不应照抄下面命令就执行。应以合成fixture替换默认外部依赖，并验证默认测试不访问仓库/临时目录之外；真实项目集成仅在用户明确授权和显式启用时运行。

完成隔离及实际实现后，再运行并保留结果：

```text
node tests/run-tests.js
node scripts/check-skill-contracts.js
node scripts/check-doc-budget.js
```

预算脚本目前统计去空白字符数，不是模型token。除静态预算外，要对同等输入记录实际加载资料和调用/修订次数；不以少换行伪装瘦身，不靠引用更多冷路径资料转移成本。

这些命令通过只能说明相应工程契约通过，不能说明作品达到参照水平。新行为还须有对应测试，不能让旧的“关键词存在”断言替代端到端验证；合成片段仅测权限与路由，不宣称能自动证明幽默或人物鲜活。

### 6.2 作品验收由用户生成新章节后决定

不要求重写旧 ch001，不替用户生成验收小说，不用模型给自己打分宣布达标。用户先更新实际项目的技能/部署，再选择后续要生成的新章；如新开书，可先看前三章；如续写，选择一个能看到起因、过程、兑现与余波的连续段。

建议分三次观察，具体章数由用户根据作品决定，不新增强制创作任务：

1. **第一轮：新章是否真的更想读。** 不看框架报告，只读正文；能否知道自己在期待什么、记住具体的人、看到真实的回报。
2. **第二轮：一个连续单元能否积累。** 日常/铺垫不是拖延，高潮不是突然给结果，关系与胜负的后果能进入后续；不只是首章漂亮。
3. **第三轮：换一种题材仍成立。** 与首轮明显不同的题材，不沿用同一套抒情、物件、短句和冲突模板。未完成此轮，只能称已测题材有改善，不能称跨题材解决。

用户每轮只需提供最有判断力的信息，不要求填满文学术语：

- 我想/不想接着读，具体从哪里开始出现这种感觉。
- 我记住谁，因为什么选择、关系或行为，而不是因为被写了一个标签。
- 我在等什么，已经拿到了什么；哪些地方让我觉得失信或只是拖延。
- 哪段最像真的，哪段像模型在完成任务；可直接标原文。
- 比此前体验更好/相近/更差，允许没有可比较基线。

这些是观察问题，不是逐章必须满足的五项信号。不是每章都要高潮、代价、反转、笑点或能摘抄的句子；整体阅读是否值得继续才是核心。

### 6.3 对照纪律与归因边界

- 有对照时先约定比较对象、同等预算与版本；记录模型、宿主、技能版本、输入状态、人工介入、生成/修订次数，以及可获得的耗时和token。不可见的数据标未知。
- 尽可能一次只改变框架或模型中的一个变量；两者同时改变时，不把收益全归给框架。
- 同一新起点做A/B，须用户另行同意并按候选隔离协议执行；不擅自回改旧章，不给新法更多抽卡机会。
- 用户亲自验收是有效的产品验收，但不冒充独立读者盲评；第三方反馈是可选的补充证据，不转化为额外人工准入负担。
- 没有对照时，可记录用户接受/拒绝和具体缺陷，但不宣称已经识别提分的唯一因素。
- 接受负结果；不能用“模型太弱”“作者性不够”“再试十稿”自动取消失败结论。

### 6.4 停止与回查条件

| 观察结果 | 下一步 | 禁止的补救 |
|---|---|---|
| 检查通过但仍无聊 | 回查阅读回报、人物选择与场景价值；由反馈定位最早失效层 | 再加情绪词/狠话/细节指标 |
| 场景设计有价值但正文无法兑现 | 查上下文损失、生成粒度、执笔能力；必要时提出单变量模型试验供用户选择 | 把同一失败重复多次当更认真 |
| 原稿有趣，审后更平 | 查具体改动和对应规则，修正反馈链；在授权与版本保护下保留较好表达 | 以报警变少证明修订正确 |
| 首段好、连续单元变空 | 查后果回流、关系变化与中程规划，确认是否又回到预排任务清单 | 只继续强化黄金三章 |
| 一种题材好，另一种失真 | 查题材材料、阅读契约与示例选择；缩小已验证范围 | 宣称通用框架已治愈所有题材 |
| 达到预算仍无新判断 | 保存失败原因与版本，交用户决定暂停或换假说 | 自动再抽卡、再造概念、再宣布终版 |

## 7. 本版最终决策

**不采用“三模型改成单模型就能根治”的方案。** 改造对象是从书级选择到完整场景、再到审读和长期后果的整条链路；保留可用的多端、多模型和状态保护能力，删除把文学判断压成局部填空的控制方式。

后续完成的标准不是文件改了多少、机制新增多少，而是：工程路径真实接通，用户更新后生成的新章节更好读，这种改善能在连续单元中保持，并在实际测试过的其他题材中复现。**在用户验收前，只能称“已实现待验收”，不能称“已根治”或“已达到名作水平”。**
