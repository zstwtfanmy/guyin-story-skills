> 日期：2026-09-18 ｜ 性质：框架诊断，只判机制、不评文章 ｜ v2 修正了 v1 一个关键误判
> **v1 错误**：我上一版说"框架没有标点检查门"——**错**。框架有 `guyin-normalize-punctuation.js`，且能识别"——"。本次读了源码，把三个问题都定位到"代码行 + 机制挂载位置"。

## 0. 结论先行

这次暴露的不是"文章写得不好"，而是框架的**四类机制缺陷**，且三者（"——"、误删锚句、开头没变）有一个统一根因：

| # | 问题 | 框架机制缺陷 | 代码/位置证据 |
|---|---|---|---|
| 1 | "——"漏进正式正文 | ①em-dash 定级过低 ②不在发布全检 ③执行层漏跑 | `normalize-punctuation.js` L285/L302/L84-88；`SKILL.md` L44；`tracking-commit.py` L2049/L2472 |
| 2 | 误删"往前倒三十八年"无人报 | 无"一次性关键锚句/时间锚"登记位，检查门只做"后验正确性"、不做"完整性留存" | 14 道门清单无此校验 |
| 3 | 开头一字未变 | "授权照抄区"无边界 + 无"重写模式"开关，默认保护定稿 | 细纲第四组「功能性原话授权区」 |

**统一根因**：框架是"后验正确性检查器 + 前置自动改写器"，但它**不校验"该保留的保留了没有、该重做的重做了没有"**，且"前置自动修正"与"后置阻断验证"之间**脱节**——前置漏跑，后置不兜底。

## 1. "——"问题：落地到代码行

### 1.1 事实（字符级）

| 项 | 值 |
|---|---|
| 出现位置 | 新稿 L13、L23，各一行 `——`（U+2014 × 2，单独成行） |
| 旧稿对照 | 旧稿 0 处破折号，用文字"往前倒三十八年。九月一号，开学第一天，三年级二班。"过渡 |
| 性质 | 用符号分隔符替代了文字时间过渡，且顺带删掉了世次时间锚句 |

### 1.2 框架明明有门，为什么没拦住（三层根因）

**第一层：门是"自动改写器"，不是"阻断检查器"，且严重度定级过低。**

`guyin-normalize-punctuation.js`：
- L285 正则 `const pattern = /…+|\.{3,}|——|—|--+/g;` —— **能匹配"——"**。
- L84-88 默认（不带 `--check`）模式直接 `fs.writeFileSync` 改写文件 —— **它是改写器**。
- L302 em-dash 的 `severity: 'advisory'`（**低优先级**），而 `---` 分隔线（markdown-divider）才是 L179 的 `blocking`（hard）。

→ 框架设计判断："——"是 **editorial（可改可不改的编校）**，`---` 是 hard（工程错误）。**这个定级与你"——明显是问题"的标准冲突**——它本该是 hard，却被定成 advisory。

**第二层：这道门不在发布全检里。**

- 门挂在哪：`SKILL.md` L44 = 写章循环**第 4 步（拼接环节）**，`workflow-chapter.md` L124 = "编排层跑"。
- 发布全检（prepared 阶段）只跑两个脚本：`tracking-commit.py` L2049 `guyin-check-pending.js` + L2472/L2488 `guyin-check-repetition.js`。**不含 normalize-punctuation。**

→ 即使第 4 步漏跑，publish 全检**不会兜底**。

**第三层：执行层（我）在第 4 步漏跑了这道门。**

我在章检链里跑了 wordcount/repetition/strip/integrity/consistency/degeneration/narrative-asset/outline-copy/outline-deliver/authority-leak/ai-patterns/beat/pending/rule-conflict/foreshadow-id/hook-rotation/reader-signal/trial-gate——**唯独漏了 normalize-punctuation**。

### 1.3 定性

"——"漏网 = **三层同时失效**：定级过低（advisory 而非 hard）＋ 不在发布全检（无后置阻断）＋ 执行层漏跑（前置改写器没被调用）。任何一层兜住都不会漏进正式正文。

**框架缺陷本体是前两层**（定级 + 挂载位置），第三层是我的执行疏漏，分开记。

## 2. "开头没变"：框架机制副作用

### 2.1 事实

新稿开头四句与旧稿 v2 逐字相同（"他四十七岁那年……那是他这辈子最后一次开口"）。倒叙钩子一字未动。

### 2.2 框架机制根因（不是执行层"懒"，是机制缺约束）

细纲第四组有「功能性原话授权区（既有定稿原话，允许逐字落地，免报）」——这是框架的**保护机制**，本意是保护已定稿的功能性台词不漂移。但：

- **缺陷 A：授权区无边界/上限。** 机制允许把"任何内容"列为"逐字落地"，不区分"功能性台词（该锁）"与"叙事入口/开头（该重写）"。于是开头四句也被锁进了授权区，机制不拦。
- **缺陷 B：无"保护模式 / 重写模式"开关。** 框架默认"保护既有定稿"，而你早先给的授权是"按爽文逻辑自由推翻重做"。**框架没有显式开关让执行层从"保护"切到"重写"**——两个意图冲突，框架默认站"保护"，执行层顺势照抄，重做授权被架空。

**结论**：开头没变，表面是"执行层保守"，底层是**框架的"保护定稿"机制默认开、无开关、无边界**，把"推翻重做"的授权吞掉了。

## 3. 误删"往前倒三十八年"：框架的"完整性盲区"

### 3.1 事实

新稿删掉了旧稿的时间锚句"往前倒三十八年。九月一号，开学第一天，三年级二班。"——这是把"47 岁"钉回"9 岁"、让读者锚进"重生回童年"的**唯一一句**。删掉后，14 道章检门 + publish 全检**零报错**。

### 3.2 框架根因

框架有"复沓锚句"台账（管**每章重复出现**的锚句），但**没有"一次性关键锚句/时间锚"的登记位**。后者删了，没有任何门报"缺失"。

更深一层：**框架的检查门全是"后验正确性"**——`repetition`（重复）、`consistency`（一致）、`integrity`（完整=文件在不在）——它们管"你写出来的**对不对**"，不管"你**该保留**的保留了没有"。删除关键句属于"完整性"问题，框架全部门都盲。

## 5. 统一根因（架构师判断）

**框架 = 后验正确性检查器 ＋ 前置自动改写器，但三个环节之间、以及它们与"内容完整性 / 创作意图"之间，全部脱节。**

一句话拆开：

1. **它只管"写出来的对不对"，不管"该写的写了没、该留的留了没、该重做的重做了没"。** → 误删锚句（3）无人报。
2. **它的"自动修正"依赖"被正确调用"，但没有"后置验证"确认修正真的生效。** → "——"（1）前置漏跑，后置不拦。
3. **它的"保护定稿"默认开、无开关、无边界，与"推翻重做"意图硬冲突。** → 开头没变（2）。

三个具体问题全部落在这三条盲区上，没有一个是"文章本身的问题"。
