## 〇、总判词与第五条根因

五轮失效模式演进（采 v5 §3.2，框架侧复核认可）：

| 轮次 | 修复动作       | 失效模式       | 失效层级     |
| -- | ---------- | ---------- | -------- |
| v1 | beat 模板精简  | 护栏缺失       | 细纲层·槽位设计 |
| v2 | 护栏槽位回归     | 高保真传导      | 细纲→正文接口  |
| v3 | 时序自检＋偏差槽   | 过保真（元语言入文） | 指令/内容分离  |
| v4 | 指令区分离＋剥离门禁 | **收尾断链**   | 检测→修复闭环  |
| v5 | （声称更新未落盘）  | 落盘失联       | 运维层      |

每轮修好上一层、暴露下一层——这不是"改错了"，是系统逐层显影。但 v4 之后暴露的闭环层问题有一个与前四轮不同的性质：**它不是新机制缺失，而是既有机制的产出无人消费**。

### 根因五：闭环只到"看见"为止（检测-消费断链）

框架有检测（意象台账捕获"钱压在碗底下×2"）、有登记（v4 报告 19 项修订清单）、有评估（v4/v5 两份报告）——三层全在，唯独缺第四层：**消费强制**。检测产出的 finding 没有终态制：不必被修复、不必被豁免、不必被登记偏差，无声消失零成本。三条并行证据：

1. **检测→修复**：意象台账 N2 区在册的复读缺陷，无任何回路触发回修（v4 A3'）；
2. **报告→执行**：v4 报告 11:10 落盘，19 项修订 0 项被消费（v5 §一）；
3. **欠账复利**：气韵卡坐标五轮未还、物证台账四轮未还、\_archive 三轮未还（v5 §3.3 债务表）——欠账不阻塞任何下一步，利滚利。

配套的两个次生根因：

- **根因 5a（诚实字段无验证）**：三查勾选框走过场（v4 G2）、偏差槽空报"无"（v4 A4'）、保护资产静默弃用三项（v4 §三）——这些 honor-system 字段由 LLM 在注意力压力下自填，无交叉验证，填"无"比填真话便宜。

- **根因 5b（批次不变量塞进每章槽位）**：比喻域、引号惯例这类**批次级不变量**被写进每章细纲的写作指令区，编排层以上一章细纲为模板锚定下一章，导致 61-63 三章指令区逐字相同、比喻约束全篇同域——不是错误指令，是**指令放错了层**。

### 〇.5 追加分析：review 能不能处理这些薄弱点（作者问题 4 的正面回答）

**结论：review 能看见，但看见≠消费；消费必须框架门。逐类判定：**

| 薄弱点类别                   | review 能否处理 | 判定依据                                                            |
| ----------------------- | ----------- | --------------------------------------------------------------- |
| 编辑级 A/B（引号、双付茶钱、二讲、评点句） | ✅ 能诊断，改写卡能修 | guyin-review finding 带句位证据＋L1 分级，本就是它的职责                        |
| 同类缺陷跨章复发                | ❌ 不能        | review 是事后的；复发防护要生成端规格（Y1 引号）＋消费门（U1）——否则每代正文都要 review 再修一遍同一问题 |
| 欠账复利（气韵卡/物证/\_archive）  | ❌ 不能        | review 每轮都看见了（v1-A3 起五轮在册），零消费——这正是"review 不能"的实证               |
| 情绪锋度／"人味"峰值不足           | ❌ 不能        | v4 判语明确：不是回炉能补的，要靠细纲把情绪落点硬化（B5）；review 只能事后指出"浅"，不能让正文长出感情      |
| 指令区复读／比喻域固化             | ⚠️ 能看见不能根治  | 根治靠归属重构（B1）——把批次不变量从每章槽位上移                                      |

**关于"改了一版还不如之前"的防护**：08 的防叠加四不变式继续有效（本轮逐项核对见 §五）；本轮新增第五条验收纪律——**代际对比协议**（§六）：框架大改后必须重新生成样板章并跑三方对比表，综合质量劣化超过编辑级即回滚对应改动。改框架不再以"感觉改好了"收尾，以代际对比数据收尾。

## 一、B 系：批次公约——指令与约束的归属重构（作者问题 3 的正面回答）

### B1 批次公约建制

**问题**：写作指令区 61-63 三章逐字相同；比喻约束（做饭域）三章同值，照此下去全篇同域。成因＝批次级不变量塞进了每章槽位＋编排层以邻章细纲为模板锚定。

**方案**：新建批次级声明文件 `大纲/批次公约.md`（项目侧），收录**跨章不变量**；细纲写作指令区只装**本章特有指令**。归属判据一句话：**删掉这行后下一章会不会自然写错——会，是本章特有；不会，是批次不变量**。

公约模板（框架侧提供，内容归项目）：

```markdown
# 批次公约（第 61-70 章）
- 比喻域：当前域=做饭域（咸淡/火候/揭锅盖），已用 3 章；第 64 章起切商贾域（秤/脚钱/船埠）；
  禁用域=（查 追踪/意象台账.md 高频域）
- 引号规格：对白 " "，嵌套 ' '
- 收束位轮换：章尾落点不连续同位（动作/画面/台词轮换）
- 批次级禁令：（如：本批禁出现"体系"类现代语感词）
```

**改动件**：

- 新增 `guyin-setup/templates/long/大纲/批次公约.md`（模板，create-if-absent 部署）

- `references/细纲协议.md`：写作指令区条目改写——"只装本章特有指令（术语锚定方式、本章推理步数、锚句落点）；批次不变量（比喻域/引号规格/收束位轮换）上移批次公约，本章重复声明属噪音"

- `SKILL.md`：补纲场景产出/核对公约；写章循环第 1 步读盘加公约；`cards/README.md` 占位符取数表加规格行来源

- `cards/写作卡.md`：加一行规格占位（引号＋当前比喻域，编排层从公约抄，≤30 字）

**对比喻约束问题的直接回答**：比喻域从"每章重复的指令"变成"公约里的一次声明＋换域计划"。域的选择与轮换是项目决策（v4 §七：做饭域三章统一是资产，ch64 切盐路行商域），框架只提供声明位与机械兜底（B3）。

### B2 指令区复读门（汇侧机械兜底）

**改动件**：`guyin-check-outline-slots.js` 加 advisory `outline-instruction-echo`——落盘门检查细纲 N 时，若细纲 N-1 存在且两章写作指令区归一化文本（剥空白）逐字相同、且非"无"，报"指令区与前章逐字相同——批次不变量上移批次公约，本章无特有指令写'无'"。

**执行偏差区的去留结论**：**保留在细纲，不动结构**。它本质是每章异质的（检测驱动回填，R1），三章同填"无"是合法状态——问题不是"重复"而是"空报"（ch63 场景下限未达却报"无"），空报的治理归 U1（消费门）＋U2（扩义），不靠挪位置。

### B3 比喻域轮换 advisory

**改动件**：`guyin-check-repetition.js` 章检模式加 advisory `metaphor-domain-stale`——从意象台账 library 计算本章主导域的连续驻留章数，超过阈值（默认 4，`--domain-stale=N` 可调）报"域 X 已连续 N 章主导——按批次公约换域"。与 B1 构成"源头声明＋汇侧兜底"两层。

### B4 场景下限自洽检查

**问题**：ch63 细纲自设"≥3 场"而涉及场景清单只列 2 处，细纲内部自相矛盾，落盘门没拦。

**改动件**：`guyin-check-outline-slots.js` 加 advisory `outline-scene-floor-conflict`——场景与对手戏下限行声明的场景数 > 涉及场景清单条目数即报。（正文实际场景数是语义判断，不做机械化，列走查残差。）

### B5 情绪落点硬化——协议＋卡级落位（追 v4 判语，自审后升级）

**问题**：v4 判语——情绪锋度与"人味"峰值以人工润色的卷一卷二为标高，"不是回炉能补的，要靠细纲把情绪落点硬化（每章至少一个'人'的落点换气）"。

**自审发现的缺口**：初版 B5 只改细纲协议——但 08 全轮教训正是"细纲有了≠执行层看见"：执行层读的是写作卡，不是细纲协议。人的落点若不落卡，等于把 P0-03 的失效模式在自己身上重演一遍。

**改动件**：

- `references/细纲协议.md` 情绪落点细则加一句：**≥3 落点中至少 1 个为"人的落点"——落在具体角色的具体反应或选择上，不落在信息揭示/案情推进上**

- `cards/写作卡.md` {{情绪目标}} 字段加"人的落点"子行（≤20 字，从细纲抄）——执行层可见，这是该机制的真正落点

- `SKILL.md` 组卡纪律一行：人的落点为空则不组卡

## 二、U 系：消费闭环——检测必有终态（v4 G7/G9 的落地）

### U1 待审台账＋终态制（本轮核心）

**问题**：章检报警"拦为待审"只是话术，待审没有台账、没有终态、不阻塞任何下一步。"钱压在碗底下×2"在册无回路；v4 报告 19 项修订 0 项被消费。

**方案**：报警从"话术状态"变成"台账行"。新建 `追踪/待审台账.md`，每个未消 finding 一行：

```markdown
| 章号 | 来源 | 报警/发现 | 终态 | 去向/备注 |
|---|---|---|---|---|
| 61 | repetition N2 | 钱压在碗底下×2 | 待审 | |
```

**终态五选一**（每行必居其一，无第六态）：修复（改写卡，删行或标已修）／豁免（五测试，登 豁免台账）／契约修订（登细纲偏差区）／顺延（登 伏笔.md＋章号）／升级作者。这正是细纲协议 R1 哲学（"无偏差无声消失是唯一禁区"）从偏差槽向全部检测产物的推广。

**改动件**：

- 新增模板 `guyin-setup/templates/long/追踪/待审台账.md`

- 新增脚本 `guyin-check-pending.js`：解析台账，未终态行（终态=待审或空）存在即 exit 1；`--through N` 只查章号 ≤N 的行

- `SKILL.md` 接线（三处，注意预算删等量旧文）：① 预检加"待审清零：guyin-check-pending.js 无未终态行"——**含 review/评估报告 findings 转入的行**（这是"报告 0 项被消费"的封堵：报告产出必须转台账行）；② 章检第 7 步末尾加"报警逐条登待审台账"；③ 大修/回炉场景消费后更新终态

- `guyin-review/SKILL.md` 输出结构加一句：findings 由编排层转入待审台账（review 依然只诊断不动刀，不动它的哲学）

- hook guard 加固（可选，确定性）：首建第 N 章正文时，待审台账存在章号 \<N 的未终态行 → exit 2

### U2 偏差槽扩义（v4 G9）

**改动件**：`references/细纲协议.md` 执行偏差区由两类扩为三类——**变体／未落实／弃用登记**（弃用须写理由与替代物）。消费端与 Y4 联动：弃用登记的合法前提是保护资产过堂（见 Y4），否则"弃用"就是静默丢弃的合法化外衣。

### U3 复读降噪（v4 G8）

**问题**：N2 区同族子串各记一行（"袖袋里的算盘"一族 14 行），表膨胀、信号淹没，{{禁止}} 注入取数被噪音污染。

**改动件**：`guyin-check-repetition.js` N2 聚合逻辑加同族去重——同批次候选短语按长度降序排列，是已保留条目子串的候选直接丢弃（只记最长命中）。不动 ≥2 入库门槛（提阈值到 ≥3 会漏掉"钱压在碗底下×2"这类真缺陷，不采）。

### U4 写前快照强制化（v4 G4'）

**问题**：裸奔覆盖式重写两次（v1、v3 稿永久丢失）。SKILL 大修路径已有 V1 纪律（"动刀前现稿拷 \_archive，无存档不动刀"），但重写走"写指定章"路径不经过大修行，且无 hook 强制——纪律存在≠门在路径上（08 教训三的第 2 条同款）。

**改动件**：

- `guyin-hook.js` guard 的 exists 分支加**覆盖门**：Write/Edit 已存在的章文件时，`正文/_archive/` 须有该章 mtime ≥ 目标文件当前 mtime 的快照副本，否则 exit 2 并引导"先拷 `_archive/第N章_vK_时间戳.md` 再动刀"。规则完全确定性（只比 mtime），零语义判断。副作用：每次连续改稿都要重新快照上一版——这正是"每一版都不许无存档消失"的语义，可接受

- `SKILL.md` 写指定章/日更场景加"目标章正文已存在 → 先快照再动"一行

- 边界登记：脚本直写（如 normalize-punctuation 改文件）不经 hook，不受此门约束——确定性变换接受为残差

## 三、Y 系：规格与新鲜度——状态层不再欠账

### Y1 引号规格落地（v4 A1' ＋ v5 §五升级）

**作者已拍板（2026-09-02）：选 A——统一 " "，存量不回改，自重新生成批次起生效。** ch1-60 保持原样（其中 ch17-60 为「」），重生成的 61-63 即为首批适配章。这是一次**显式接受的过渡态不一致**（分裂带留在存量），登记进批次公约与文风约定，防止后续评估再把它当缺陷报（v4/v5 两轮都在报同一个问题）。

**对 v5 判断的修正（重要）**：v5 称"工具链在制度性推向「」（yan 模式把 " 转「」）"——**不成立**。脚本默认 `--quote-mode keep`，yan/ascii 均需显式传参，v4/v5 报告期内无人跑过 normalize。`「」` 的真实传导链是 **`{{前文}}`** **声线锚**：写作卡章首 beat 贴上一章结尾 300 字原文，卷二 44/45 章全是「」，执行层临摹前文格式自然延续「」。这是"声线锚携带格式 tic 前传"的系统性洞——顺手改 normalize 默认值是错的（多平台场景 keep 默认是对的，盐言故事用「」），对症修复是：

- **写作卡加规格行**（B1 已含）：引号规格从批次公约抄进每张卡，与前文声线锚对抗——执行层临摹的是"离它最近的明确指令"，卡上规格行比 300 字前文更近

- **章级 normalize 兜底**：新章落盘前跑 `guyin-normalize-punctuation.js --quote-mode ascii`，仅对本章新文件（确定性零 token，零存量写入）——过渡期 {{前文}} 声线锚仍会喂进上一章的「」结尾（重生成 ch61 时 ch60 的「」就在前文里），临摹风险由规格行＋normalize 双层压制

- 规格结论写进批次公约，卷级不变；旧章维持原样为既定决策，不作回改

### Y2 气韵卡坐标门禁核验（v4 G5/G6 残留）

**问题**：气韵卡 §五停在"卷2 中段 ch28-32"五轮未还，而 outline-slots 本有 `qiyun-coord-uncovered`（细纲章号须被气卡区间覆盖）——机制在，61-63 细纲落盘时却没拦住。

**动作**（两步，先核实再补）：
