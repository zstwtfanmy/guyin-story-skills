## 4. 样本甲究竟提供了什么质量方向

下表是本轮基于样本文本作的机制分析，不伪装成用户逐条签署的评分表。它用于研究、编辑和验收，不作为逐章必须完成八项的生成任务。

| 可迁移的阅读品质 | 样本甲证据 | 应如何进入创作 | 不应泛化成什么 |
|---|---|---|---|
| 人物愿望真正支配选择 | :5、15，平常生活愿望影响忍让和藏拙 | 开书与阶段设想明确人物珍惜什么；场景选择服从人物处境 | 主角必须藏实力、必须追求平凡 |

| 配角各有自己的理解和选择 | :41–59、81，护短、好胜、看热闹并不一致 | 从各人知道什么、在意什么决定回应，支持与改变都可自主 | 配角必须反对、倒戈、误认或给主角认证 |
| 心理带私人口吻，不是功能说明 | :13、17–19，记账又自嘲、职业本能与生活相碰 | 心理直陈、转述、自由间接体、叙述评论按 POV 与体验选择 | 一律身体化、一律自由间接体、每段吐槽 |

样本也不是无瑕模板：动作专业可信度未由本轮考证；个别“委屈”处理和末句扣题可有求巧感。文本在家明、馆主、怀沙之间进入不同内在感受，不能把这种权限直接搬到一本已锁第三有限的作品；叙述距离能变化，不等于可以越过书级 POV。

### 4.1 “全局”必须拆成两个层次

1. **通用品质全局适用**：人物不像工位、关系各有尺度、选择有依据、语言有阅读收益、形式不先定罪、变化能积累。这些应进入长短篇共享入口及 review/deslop，而不是只在某个 Y 实验生效。
2. **具体风格按作品适配**：轻松、促狭、藏锋、能力与生活反差属于 relationship-payoff 的可选方向。历史、悬疑、竞技和其他题材保留各自回报与语感；不能把十一种 profile 全改成《踢馆》的喜剧。

也不要求其余 profile 都重写一遍。先确保共享执行和审读不会抵消上述品质，再按实际使用路线验证；没有测过的题材只报告共享工程覆盖，不外推文学效果。

### 4.2 旧诊断存在串稿，不能直接当全局规则来源

`R-y05-banan-details.md:24` 把“老厨子/奶油蛋糕”列为甲稿，`R-y04-samecast-comparison.md:16` 明确它属于 A/乙；Y05 报告 :44 的“未来的女婿”等也属于乙稿的对应描写，:56 又混入乙稿的内行分析措辞。因此不能把该报告全部“甲稿缺点→优化方向”直接提升为用户选样标准。

同时，Y04 报告 :62 的“每段最多一个包袱”、Y05 原结论的年代封禁、必须挑战者前摇与胜绩去认证，都不是用户对样本的整体认可所授权的普适规则。后续仅校正归属与适用边界，保留历史报告的可追溯性；不为修报告再改小说。

### F05｜连续性：关系增量说明与整份快照替换冲突

**位置**：同事务文档 `:282–295`，尤其 :284；`guyin-tracking-commit.py:1425–1431`。

**修正**：明确所有模式下，`character_snapshots` 都是受影响角色的完整当前视图；变化记入 delta，未变关系/知识/未结事项原样携带。无变化可以不提交该角色，而不是提交空快照列表擦除历史；相处没有状态变化仍可有阅读价值。优先修说明及示例，不为掩盖误用把脚本改成自动拼接、永远不能删除的隐式合并。

### F06｜审读：正常 rubric 仍会撤销已放开的形式

**修正**：情绪维度判断变化或稳定感是否可信、是否有实际体验；期待维度判断读者为何继续相处或看事态，不固定钩子位置。真正空转、突兀、没有阅读回报仍报具体损失。平台 rubric 仅在本批实际调用时核同类冲突，不以此次通用修正宣称所有平台完成。

### F07｜冷方法：样本的普通口语仍可能被反向剔除

**位置**：`C2/guyin-write/references/consult/writing-craft.md:332–349` 及其调用的 `dialogue-mastery.md:32–38、134–141、272–277`。

dialogue 的逐句必带功能、情绪四步缺一不可、即使没思考也要写出来、单次对白 40% 上限仍存在；这些是**按需调用后的冲突**，不是每次写章默认必读。craft 已把 ≤10/≥20 字数说明限制到特定模式，不再重复报成普遍热路径门。

**修正**：仅清实际会调用的相关段及尾部检查项，改为诊断工具和场景选项；保留可用技巧，不全库扫荡，不新设更隐蔽的包袱、心理或“原创比喻”配额。成人幽默的放宽始终受人物年龄及作品内容边界约束。

**修正**：细则补到已有事务/召回冷路径，热入口只留触发和指向；由获准连续试写展示一次磁盘恢复和来源修订后的重新判断。不要新增自动人格系统或每章记忆问卷，也不要靠新增一句“必须读取”宣布长期能力完成。

## 7. G0 封题需要重新定性，不得冒充原创留出

`A/sealed/README.md:3–7` 说明两包来自两部参照小说的随机中间章，含情境开头、原章全文和元数据，机械脚本封存；并转述用户接受可访问的残余风险。本轮没有读题，故不判定具体 brief 是否逐字截取、是否已改成原创，也不否认用户可能授权了这种私人练习。

**处置**：保留现有包，不解封、不删除、不重命名掩盖来源。若真实授权本来就是随机原文条件的私人挑战，按该用途单列证据，不能计为原创 W5；正式 G3 另由用户或未参加调参的会话提供同一路线两道新原创题，在下一轮调参/校准开始前独立封存，冻结 X 后才解封。允许匹配原文作评读锚，但原章与逐句报告留评读侧，不是给生成侧的题目答案。

## 10. 怎样才算样本方向真正全局生效

“全局应用”按以下链条验收，缺哪层就明示哪层未完成，不用一个总开关或一次复制掩盖：

1. **方向来源正确**：绑定 Y04 甲的具体版本；以通用机制迁移，不把 Y05、乙稿或原文特定桥段混入用户认可。
2. **共享指令一致**：write、短篇继承路径、实际加载 profile、review 的正常/fallback 路径和 deslop 不互相抵消；冷方法按需可用而不带回普适配额。
3. **运行输入无损**：新 run 冻结真实完整 profile，人物快照和旧文来源正确；旧 run 保留原冻结值，不因默认升级偷偷换声线。
4. **安装对象正确**：从获准制品安装技能，不用 `guyin-deploy install --dest` 冒充技能安装；该工具是书根脚手架部署。分别记录 L、制品、安装根及实际 W 的 realpath、版本和完整哈希。
5. **新会话实际读入**：在获准临时书中从正常入口启动，记录实际读取的入口/profile/rubric/脚本；按所选一段 profile 读取，不把整份审计或样本正文塞进写作上下文。宿主发现顺序不得靠猜。
6. **旧书按范围迁移**：已存用户文风及冻结 input 优先；只对获准的新 run 使用新默认，需要改既有书级方向时另列差异，不批量覆盖 AGENTS、设定或正文。
7. **作品给出效果证据**：原创留出及连续作品中，用户确实感到人物、相处、声音和后果有所改善。工程层应用完成也只能先报“加载与执行路径已接通”；没有阅读结论，不报“全局达到样本甲水平”。

安装前先审实际差异，原样保留未知用户内容；不修改全局 Git 配置，不用放宽校验器消除行尾/清单问题。以明确审核的制品字节为准构建清单，安装后再验；不能把 C2 的 CRLF 哈希、E 的 LF 哈希和旧安装清单混为一个版本。

## 11. 本轮结论及下一步边界

可以确认：G1 有实质实现，独立工程根现有测试已全绿；样本甲的部分通用品质已进入候选共享链。不能确认：G1 无缺陷、原创质量过门、正式全局已更新、长期作品能力已达到目标。

最值得做的下一步是**修准豁免和标题边界、修正完整输入/快照与审读冲突，然后用少量真正原创的文字检验收益**。不要再以接近原文的句式、规则数、候选文件数或测试数量代替好作品，也不要为了“全局应用”提前部署未经验证的候选。
