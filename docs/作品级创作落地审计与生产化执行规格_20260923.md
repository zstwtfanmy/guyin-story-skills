## 1. 总结：有进展，但没有完成原规格

**已经做成的是候选层修改和探索性校准，不是作品级创作能力的交付。** 实验产生了可核查的正文与用户负面反馈；解除一部分文学配额、承认不同心理与叙述形式有效，这些方向值得保留。但不能把“候选文件已改”解释成 W2–W4 全部到位，也不能把 Y05 原文辅助编辑稿解释成原创生成能力已验证。

三个账必须分开：

1. **实现账**：哪些规则真正修改，实际从哪个入口加载，有无残留冲突，脚本及状态协议是否正常。
2. **阅读账**：用户对哪一稿、哪一范围认可什么；允许继续、偏好某稿、选定方案、发布授权、质量验收不是一回事。
3. **作品账**：同一本原创作品是否持续发展，关系、人物与因果是否累积，最后是否完成并获用户整体验收。

当前没有可据以登记 Y/T-L1–L5 通过的用户验收；没有本实验形成的连续原创作品。工程门也须据实际检查单独报告，不能从文字校准推导。

**下一步不是继续改写《踢馆》，也不是把十二个文件直接合入。** 先清理会误导创作与验证的少量阻塞项、冻结一个可复现候选，再给用户看真正原创、与当前训练题有距离的新稿；值得继续才投入同一作品的长段。

### 4.2 创作级：防止用新的工整替换旧的工整

**C01：细节不是都要兑换为下一拍。** `R-y02-loss.md:10–18` 把动作衔接问题泛化成“细节几乎都当场兑现”；`R-y03-anchor-comparison.md:17` 又把“全部兑现”当进步。应分别处理：

- 真正的事实、物体、动作或时间断裂必须修；例如 `A-y02.md:57–61`，父亲带走袋子后许照又打开同一袋子，缺少交接。
- “喝水—水烫—漱口”至少存在衔接不清，但不能仅凭省略判为绝对生理不可能，再推导所有感官都要配反应。
- 蒜、烟灰、铃声可以仅贡献生活、关系、注意或余味，不要求人物解释、立即反应、后文回收。是否做作由全文体验判断。
- 没有具体阅读损失，不为“每个细节有功能”补一句意义说明。否则正文将重新成为信息验收表。

**C02：幽默不是 Y 路线的唯一回报。** 松弛、亲近、牵挂、私人偏见、羞惭、悲伤和迟来的理解都可使读者愿意相处。不能把《踢馆》的闹剧机制升级成“挑战者可爱前摇→围观倒戈→赢后去认证”的逐章任务表。能力公开有效、他人真诚认可、肃静或伤感场景也可能成立。

**C03：跨时代语言不一刀切，但要区分话是谁说的。** 场景物件及客观条件守时代；普通人物知识依其经历；重生者依前世可知范围；叙述者可跨时代评论、致敬、比喻，仍服从书级叙述约定与阅读效果。不用“哪年的梗”机械禁用，也不用“非此叙述者不可”淘汰一切共享口语。

促狭、轻度成人双关并非天然错误；但当前校准人物有儿童，不能把允许成人幽默解释为允许性化未成年人。具体作品还须遵守已约定内容边界。

**C04：追求语言收益，不追求原文轮廓。** Y05 有更紧凑的概述、叙述语气和喜剧节奏，但它沿用人物、桥段顺序与典型回应，并受到原文和既有稿的辅助。这证明存在一种有辅助条件的编辑产物，不证明独立创作或可稳定复现。

`R-y05-banan-details.md:63` 称结尾“不判词、不升华”，实际 `C1-y05-optimized.md:129` 仍有总结式回望；这种结尾未必坏，问题是审读按规则给它贴了通行标签。`C1-y05-optimized.md:127` 的“自己那个是咸的”也值得检查是否突兀；不能一边报“悬空细节绝迹”一边停止读具体文字。

**C05：不把人物的内在因果误叫配额。** 重要的是人物此刻为什么在意、对方按自己的尺度怎样理解，以及读者为何想留下，不是每章补一个爱好、一次自嘲或一段非事件时间。Y02 的“至少 200 字”和“手艺只显一次”仅是一次实验干预，不能升级为生产默认。

## 5. 研究与原创迁移的落地边界

### 5.1 W1 只补当前缺口，不再抄一个名场面的功能队列

保留现有开篇研究，新增范围须另获研究及成本授权：

1. Y 生活链：读足一次共同经历如何改变双方理解及其后续表现的连续区间。
2. Y 压力链：读足能力介入、当时各方所知、事后生活/责任/关系后果；不能只有一次比试和下一节开头。
3. 每路线至少一个有证据的有效反例；例如不搞笑但好读、能力被认可仍成立、概述/直陈有效、普通细节不当场回收。这些是选取方向，不是逐链必齐清单。已有证据够用即复用，其余记未覆盖，不阻塞无关试写、不编造原文章段。
4. T 在独立预算下补利益/信用链、资源/制度/组织执行链；小说不是历史、医学或技术事实的权威来源。

研究产物沿用原规格布局或实验文件，不新增全量台账。每条写清“原文版本与定位、必要前情、选择、阅读效果、依赖条件、反例、迁移边界”。完整原文、私人同题稿及其逐句对照不进入生成上下文、技能包或公开仓库。

现有 `W1-research-y03.md:28–30` 把被低估、反向能力、唯一胜绩去认证、结尾加一个纠缠者整组列为可迁移，粒度仍太接近这场戏。应抽象为**能力与生活愿望的牵制、各方解释不一致、经历改变后续相处**；允许完全不同的事件与结果。

### 5.2 新故事先能站住，再测试措辞

brief 只需让执笔者知道：具体人珍惜什么、既有生活/关系、当前处境、必要前情与已发生事实、真正的用户锁、篇幅、POV。作者自己作出故事选择，不向用户追讨人物问卷。

发布到生成侧前，出题侧做一次短审查：是否预写解法、情绪回应或结尾；是否换名仍是武馆踢馆；是否必须靠配角降智或不可信专业条件才能成立；是否给出了足够让人物不只剩工位的背景。发现问题先改题，不靠给正文增加文风义务弥补。

专业条件只有影响选择时才定向核实。例如 Y01 不能仅凭冰盒仍硬和包装完好就证明药物在整个过程中符合储运要求；Y03 报告称动作“符合自由式摔跤常识”，也尚不能替代可追溯依据。这里不判定全部描写错误，而是不能把作者自信当事实验收。将客观前提、角色相信、模型待核假说分开，必要事实摘要对 A/X 等量提供，不附送剧情解法。

这是实验输入质量控制，不新增每章必填场景卡，也不要求完整细纲。

| X | 本批最终冻结的 C0/C1/C2 中一个方案；两道留出题不得分别换方案 |

`shared/profile-y03.md` 已不同于 W0 的完整定义，因此 Y03 的“C1”不能用于证明“只改流程、profile 不变”的净效应。保留历史文件名，另记真实谱系、差异与哈希，不改写实验历史。

冻结内容至少包括完整技能树或可验证的底座加覆盖层、实际入口、完整 profile、实际调用冷文件白名单、生成/修订指令、模型及可控参数、A/X 共用材料、字数计量方式和成本上限。不能以一张文件哈希表代替可重建快照。

冷方法只在真实问题需要时读取，记录原因。不得为了测 C0 而每章强塞五份 consult，再把这种超额加载的坏处算成正常框架的必然表现。

### 6.2 留出题的隔离

- 本轮调参开始前，由用户或未参加调参的独立会话制作并封存两题；调参者只知测试范围。校准结束并冻结 X 后，才向隔离生成会话解封。题目封存以真实可见范围及执行记录为据，文件名写“封存”不等于隔离；无法满足时序则如实标非独立验证，不追认过去已见题为留出。
- 冻结后各生成会话只读获准输入，不读旧样稿、原文章段、逐句编辑报告、对手稿、预设 review 结论。
- 同模型隔离会话是实验控制，不是恢复默认多代理创作架构；不自动更换模型。宿主隐藏提示或继承上下文不可控，必须披露，不能宣传严格双盲或绝对无训练记忆。
- 研究得到的通用机制可在封题前固化进 X；不是所有研究都只能给评读侧。原文及针对题目的答案不得进入生成侧。
- 每题默认一个独立原创故事的第一章；两个 X 各用独立沙盒，`chapter=1/mode=append`，题号 2 不是章号 2。
- 至少一题改变核心关系类型、社会环境或压力来源；两题均不得换皮复演《踢馆》及既有驿站/验配/跤社样本。
- 任一题用于调整方案后即退为校准题；后续需重新封存未暴露题，不能反复刷同一留出集。

### 6.3 原始稿与修订稿分账，不强禁编辑

主目标是作品品质，但必须看清品质来自哪里：

1. A/X 都保留第一次完整成稿，登记哈希，先不覆盖。
2. 同预算允许各至多一次有主导假说的实质修订，保留 review、变化与得失；两组修订侧看到同等来源，不给 X 单方面的原文辅助。
3. 先比较同一阶段：初稿对初稿、修后对修后。用户不必一次读八篇，先读获准批次的最终匿名稿，初稿供追溯和差异审查。
4. 若要测独立编辑，将其设为另获授权的实验条件，不混入本批；禁止主执行者见过双方稿后只精修其中一边再称盲测。
5. 原文辅助编辑可以是私人学习，但不进入原创留出条件。若离开原文就失效，报告来源依赖，不报“已经九成”。
6. 当轮结构失败不靠改 run 名清零修订；按原规格另获目标、范围和追加预算，累计成本不断档。

### 6.4 校准、留出与用户验收

三类场景为相处、受阻交锋、事后反应。旧稿只有在条件、版本、来源和修订预算均符合相应比较时才能复用；不因题材中“出现过相处”就自动抵扣，也不要求每个新章塞齐三种场景。

正式 L1 仍需上位规格规定的校准覆盖与两个新完整章。默认所有适用的 Q1–Q5、S 都评，Q6/Q7 未测就明确未测；若实际涉及局部积累也须评其适用范围，不能借“单章”免责。**至少 3 的绝对质量标准、相对 A 无未解决明显退步、用户愿继续读、用户明确本阶段通过、实质事实/授权/POV 问题处理完成，缺一不自行升档。**

先匿名随机读稿，问哪里想停、记住谁、何处有感受，再使用功能/篇幅/前情/POV 匹配的原文锚校准。用户可用明确文字结论代替逐格评分；执行者不能代填。来源可能被认出就披露，不声称完全双盲。

只更喜欢 X，不等于 X 达到目标；只允许继续，不等于验收通过。审读版本变化后，旧结论不能平移。

### 6.5 失败时的下一步必须由证据决定

| 观察 | 优先核查 | 禁止的捷径 |
|---|---|---|
| A/X 都乏味 | 设想是否有吸引力、输入是否预写结果、必要前情、容量与展开 | 马上增加心理/幽默配额或断言模型不行 |
| A 好而 X 明显差 | 实际多加载了什么、流程是否挤压创作、规则是否替人物作决定 | 给 A 的成稿事后补 session，宣称框架生成通过 |
| X 初稿差、同预算编辑后好 | 审读是否抓对主导损失、编辑贡献和累积成本 | 抹掉初稿或声称已经具备同等初稿能力 |
| 短稿好、整章差 | 事件预算、详略、叙述中心与信息分配 | 延长一倍篇幅或挑最好局部拼验收 |
| 单章好、后章退化 | 分支、旧文/关系/知情召回、阶段方向、记忆消费 | 再开一本第一章掩盖长期失败 |
| 同类调整连续两轮无净收益 | 暂停加规则，查输入、加载、模型条件与编辑方式 | 无限新设定、自动换模型、反复原文陪跑 |

### 7.1 字数及修订成本算清楚

采用上位规格的“汉字”范围，不再写“汉字（含标点）”。工程字数检查若采用不同字符口径，双列统计并在开测前约定映射，不能看完偏短稿后改口径。

| 批次 | 初稿量 | 若每稿重出一轮完整修订的新增量 | 用户阅读控制 |
|---|---|---|---|
| 三类校准全新补齐 | 六份 × 1000–1800 汉字＝6000–10800 | 至多再 6000–10800 | 每次先一对；没有必要不补全六份 |
| 两题留出 | 四份 × 2500–3500 汉字＝10000–14000 | 至多再 10000–14000 | 可按题分两次，但第一题反馈不得用于改冻结 X 后继续称第二题同批验证 |

研究、输入制作、工程、review、失败重试和用户读稿都计入总成本。“研究另计”必须有获准的独立上限，不是无限额度。生成默认最多六/四次、修订默认最多六/四次；工具调用与研究时间另列，不能把一次会话内多次生成藏在“一次调用”里。

G1 只把文件压在预算线上并不证明上下文负担已降低；应删除冗余并记录实际每章加载量。不得调高已有预算，也不把“净增必等量删”误当文学规律：先守真实文件/路径上限，再以不重复、不误导为删改依据，不另造一个硬数字。

## 8. 连续作品协议：把长期后果真正写下去

### 8.1 同一个故事，不重新开篇冲等级

G3 的两个独立首章只测 L1。W6 接入后，另开一个未用作校准的新原创故事，获准后按 **三章→约十章的实际故事单元→至少约三十章且完整主要故事弧及余波→约定作品体量** 延续同一本。

十/三十章是观察容量，不是要求强制高潮或结案。弧尚未闭合就按真实范围报告，追加体量须另获授权。另一新故事可以验证泛化，但不得继承旧故事的 Q6/Q7 和 L3/L4。

用户可允许未达标稿继续探索，此时只推进授权范围，不提升质量等级。第三章及约定段末停靠；不要求用户每章填全量表，也不越过已经触发的检查点。

### 8.2 章前消费：不是“材料在盘上”就算记住

每个 X/正式 run 在 `start` 前完成：

1. 核实际书根、候选分支、未完成 run、发布在途状态、用户锁与读者检查点。
2. 读紧邻承接正文及本章相关人物完整角色视图，特别是关系、知情、未结事项。
3. 旧承诺、旧误会、重新同场、旧物或组织行动影响选择时，先定位逐章记录/实体/时间线，再读决定回应的旧正文。
4. 读取相关阶段回看，核其范围和来源哈希；回看是解释，不能覆盖事实或用户锁。
5. 书内合法来源及真实哈希进 `input.sources`；事实进 `facts`，真锁进 `locks`；设想不伪装成已经发生的事。完整实际 profile 冻结进 `effective_features`。

停止于足够支持本章选择，不凑文件数量。热卡仍守 12288 字节、六活跃角色/八伏笔/近三章；单角色 8192 字节、章摘要 900 字节；长期约束六项、风险五项。用定向冷召回，不假退役重要事实或抬容量。

### 8.3 章后与阶段回看

- 从最终正文提取事实，不反过来改正文凑表。受影响角色提交完整当前快照，旧关系/知识不能因本章未写而丢失。
- 稳定相处可以有价值而无状态变化；相关数组可空，但正式事务仍需合法 delta 和非空 result。
- 正式段回看放 `追踪/运行记录/第NNN章.md`，标范围、各来源路径及哈希、截至 state revision、已验/待验；未发布链放 R/实验目录。
- 下一章实际读取回看再回查关键原文，留消费证据，不仅“生成了一份回看”。不手填派生金字塔“待生成”。
- 来源章被 revision 后，旧回看标待复核，另记新版本；revision 基于最新全局状态合入变化，不把后章关系回滚到旧貌。后续冲突入待审，不自动重写后章。
- 至少一次新会话只凭磁盘资料接续，核未完行动、关系理解、知情、声音和旧后果。不能依赖主会话一直记得前情。

这些协议不新增人格仿真、情绪字段、每章卡或默认内部 agent。若实际消费失败，先修检索与材料，只有反复可证的数据表达不足才另提 schema 工单。

## 9. 接入、验收记录与结项权限

### 9.1 授权至少记录哪些区别

文档认可、实验生成、研究提取、候选修改、方案选定、追加修订、live 改码、部署/旧书迁移、本地 publish、网络发布、质量验收各按真实范围记录；不是必须让用户签十一张表，而是不能互相推定。

记录日期、用户原话、允许的操作与路径/章节/批次、预算、相关版本。已明确授权一批沙盒章本地发布，可按范围执行，不机械重复追问每一章；不超范围、不开新模型、不把本地 publish 当 git push。

### 9.2 最小验收记录

沿用实验台账、`追踪/读者信号.md` 与运行记录，不改 input/state schema，也不向现有十四列表私加列。复杂附件放运行记录。

每次至少绑定：路线与 L 阶段、作品及章段范围、稿件路径及完整哈希、方案/profile/加载版本、用户原话和日期、适用维度、明确结论、剩余问题、下一授权。A 只在实际配对实验中登记，连续作品验收无 A 则标不适用，不补写对照；原文锚按预先约定范围使用，不新增逐章配锚任务。执行者计算哈希，不让用户处理机器字段。

没有用户明确结论标“待用户验收”；用户说未达到则标“未达标”；普通肯定、选稿、允许继续不登记“通过”。模型及其他读者意见单列，不能代用户签字。

### 9.3 合入及发布文件白名单

只合通过验证且获准的源码/文档/测试差异。禁止顺手纳入实验小说、同题私人练习、参照原书或临时提取、整目录未知文件。`arena` 在未跟踪状态尤其不能用 `git add .` 打包；本次不提交也不推送。

profile 实质定义变更才按选中路线升版、同步机读声明及断言；未验证路线不能借共享文件一起宣称提升。旧 run 保留冻结值；模板更新不等于旧书迁移。

### 9.4 最终报告只认三项

1. 框架到底合入了什么、工程结果与真实加载是否通过，哪些路径仍未处理。
2. 用户已确认的 Y/T 各自证据等级、对应版本/范围、待验及未达项。
3. 约定作品写成多少、是否完成、用户是否明确整体验收。

**好的作品是目标，工程与实验只负责排除自欺、支持创作。** 如果流程使作品更呆，应保留安全底座、撤去无收益的创作负担；如果当前条件仍达不到目标，就诚实交付证据与投入选项，不靠新规则、百分比或“测试全绿”宣布成功。

### 11.6 start、ready、preview、publish 的执行顺序

**K**=本批冻结的完整技能根，**W**=`$K/guyin-write`；**B**=已获准初始化的独立书根；**RUN**=该 run ID；**R**=`.guyin/work/$RUN`，相对 B。K、W、B 均用实际绝对路径，不能从 cwd 猜测。下面是接口示意，不代表本次执行授权：

```bash

  --project "$B" --run "$RUN" --input "$B/$R/input.json"
python "$W/scripts/guyin-author-session.py" checkpoint \
  --project "$B" --run "$RUN" --input "$B/$R/checkpoint.json"
python "$W/scripts/guyin-author-session.py" status --project "$B" --run "$RUN"
python "$W/scripts/guyin-tracking-commit.py" preview \
  --project "$B" --input "$B/$R/publish.json"
```

1. start 前完成取材、真实哈希和 input。书内来源在 B 内；W 的 profile/脚本在 K 侧冻结，实际完整特征入 input，不能塞书外路径进 sources。
2. 每次 checkpoint 文件只表达本次动作。完整稿先登记、证据另次登记；内部指针相对 B 且带 R 前缀。首次/换稿清证据，同次附带证据不接收。
3. ready 的机器状态主要证明必需文件与版本锚存在，**不证明机器证据内容全部通过，更不证明认真读过或用户质量通过**。执行者须核真实候选检查与全文审读，不能只展示 status 截图。
4. preview 不写正式正文、追踪或发布账本；首次可在 R 写机器证据。必须同时检查退出码、`candidate_checks.status` 和 `candidate_checks.evidence_match`；可能 exit 0 但 evidence_match=false（tracking:3335–3374），这种状态不可报最终就绪。
5. 补来源或发布授权时另存 input 修订，由 checkpoint.input_path 接入；重核基线并清四证据，重新生成受影响证据。候选换稿亦然，原文件保留。

7. 连续作品只有另获本地 publish 授权才执行下列命令；发生在途或异常账本时先按恢复协议处理，不改成新 run 绕过。`recover` 修发布事务，`author-session repair` 修坏 session，不能互换。


以上命令按状态选择，**不是要求每次成功 publish 后再调用 recover**。input schema v1、事务 schema v1、state v7、发布清单 v2 各按真实协议处理，不混称“v2 事务”。

原计划阶段 D 的工具对象有误：`guyin-deploy.js install --dest` 部署的是**书根脚手架**，不是向宿主安装技能包。G5 分别执行与验收：

- **技能安装/加载**：使用当前宿主支持的安装方式，把获准制品安装到真实技能发现根；报告源 K、安装根、实际读入 W、入口/profile/脚本/rubric 哈希及包校验。repo 存在、环境列出 skill 名或主会话说“我用 C1”都不能证明实际加载。
- **书根部署**：另获权限后，按 `guyin-setup/SKILL.md:48–65` 部署到 B。AGENTS/用户内容逐文件 create-if-absent；hook 与 OpenCode command 会刷新，settings 会合并，部署标记会更新。不能把整个命令描述成只补缺件、绝不修改现有文件。
- **旧书迁移**：模板更新不会覆盖旧书设定/文风/AGENTS；需要迁移时提供具体差异与独立授权，不因为部署成功就宣称旧书已经升级。
- **实际恢复**：用新会话确认解析同一书根、分支和冻结材料。未执行真实加载验证，只报候选脚本可调用，不报 L0 或生产就绪。
