## 1. 结论速览（先给确定答案，不绕）

1. **都市爽文中的"隐杀型"（都市异能／重生藏拙／能力反差）**：v4 完整对症——L0 管结构、L1 管声音参数、隐杀锚示范手感。这就是用户说的"都市爽文按隐杀来"。
2. **其他类型**：走各自 profile＋各自锚。锚就位时质量路径完整；锚缺失时**只靠 profile 文字，质量标"未验证"**，不借隐杀锚顶替（借了就是污染）。
3. **一个必须避开的坑**：同为"都市"，隐杀型（回报＝藏拙/关系，胜绩去认证）与纯升级打脸型（回报＝当众认证）机制相反。**锚的注册键是 profile，不是题材标签。**
4. **整改能到此为止的机制**：盲验通过后**冻结框架核心**；以后增加新类型＝加数据（profile＋锚＋注册行），核心一行不改。新类型写不好，先查锚和执行，不再改框架。

## 2. 三层架构（v3 已定，此处压缩复述）

```
L0 框架通法层   风格中立、零剧情内容：空槽落差模式＋欠账＋具体性＋代理权＋视角＋编排者不入戏
L1 profile 层   品类声音参数（已存在的 11 profile）：认证方式/舌头密度/细节纪律/节奏/收尾
L2 书级层       本书引擎三行（X 带着什么／Y 处境施加什么／Z 摩擦产出什么）＋人物事件
```

数据流单向：用户前提 →（L0 协议）→ 本书引擎 →（L1 参数）→ 行文。L0 不填内容，L1 不规定剧情。

**L0 六条（框架核心，稳定不再膨胀）：**
1. 落差空槽模式：主体带着 X／处境施加 Y／摩擦产出 Z——落差须保持张开，不许靠巧合降智填平；
2. 信息欠账：先使用后命名，按期偿债、新开活账；
3. 具体性：可感细节承载判断情绪；
4. 代理权：关键转折主角自判自选自担；
5. 视角一致：不泄露 POV 外信息；
6. 编排者不入戏：分隔线、加粗判词、设定定义句、全知预告、排队陈列一律非法——**删横杠/加粗的框架级理由**。

## 3. 声线锚注册制（v4 核心，用户方案的工程化）

### 3.1 为什么锚必须按 profile 注册

实验证据链（0928 §1.2）：Y05 持原文可逼近九成、Y04 见过锚章的盲写最佳、破隐抽掉锚只留抽象 profile 立刻僵硬。**手感参数（幽默的时机、去认证的分寸、白描的密度）无法靠规则文字可靠传递，锚是这些参数的真正载体。** 所以：

> **profile 决定"该长什么样"，锚负责"示范怎么长"。一个 profile 至少配一个锚，该 profile 的质量路径才闭合。**

### 3.2 目录结构（重组现有私有资产）

```
声线锚库/
├── README.md            # 重写：注册制规则、法律边界、出帖
├── REGISTRY.md          # 注册表：profile → 锚书 → 状态/覆盖场景/来源
├── relationship-payoff/
│   └── 隐杀/             # 由现 声线锚库/隐杀/ 整体移入（内容不变）
│       ├── 00_README.md
│       └── NN_*.md（五段）
├── historical-causal/    # 空，待建锚（如《晚明》《铁血残明》合法切片）
├── adventure-growth/     # 空，待建
└── {其余 profile 按需建}
```

REGISTRY.md 格式：

```markdown
| profile ID | 锚书 | 覆盖场景 | 来源 sha 前缀 | 状态 |
|---|---|---|---|---|
| relationship-payoff | 隐杀 | 开篇/共同生活/误认/踢馆/群戏 | 9c74d8a2 | 就位 |
| historical-causal | — | — | — | 待建 |
| adventure-growth | — | — | — | 待建 |
```

允许一个 profile 配多个锚（不同子味道）；首章默认读主锚。

### 3.3 解析协议（写章时唯一生效的找锚流程）

1. 从本书 `设定/题材定位.md` 读 profile ID＋版本；
2. 查 `声线锚库/REGISTRY.md`，定位 `声线锚库/{profile}/{锚书}/`；
3. 就位：首章通读该锚全部切片＋`叙事通法.md`；其后按本章场景选 1–2 段同型切片；
4. **缺失：一句话告知用户"该 profile 锚未就位"，在 `追踪/上下文.md` 标「锚未就位」，按 profile 文字继续写；绝不跨 profile 借锚；**
5. 出帖：本书 ≥3 章用户认可稿后，锚降级为漂移回炉，声线以本书正文为准。

锚的使用边界不变：只迁移声音不迁移内容、不整句搬移、不连续复用独特词组；时代物件以本书为准。

### 3.4 与用户原话的对照

| 用户方案 | v4 落点 |
|---|---|
| 都市爽文按隐杀来 | profile＝relationship-payoff 时注册到隐杀锚，自动生效 |
| 其他类型按其他类型走 | 每个 profile 独立锚目录，解析协议隔离 |
| （v4 补充） | 注册键用 profile 不用标签——都市升级打脸型不进隐杀锚，需配打脸流锚 |

## 6. 执行、验收与冻结（整改循环到此为止的设计）

### 阶段 A：框架核心（需授权）

F0 新建 → F1→F2→F3→F4→F8 一次改全。自检（纯工程）：`check-doc-budget.js`；grep `四问|四个声音问题` 应只剩冷路径旧概念（关键节点四问/感知四问）；交前后字符数。

### 阶段 B：模板与锚库（需授权，可与 A 合并）

F5、F6 改模板（只影响新书）；F7 重组锚库。

### 阶段 C：跨 profile 盲验（唯一质量门）

1. 甲题：relationship-payoff 新故事盲写一章（非隐杀角色、非归鞘）；
2. 乙题：另一个 profile（用户指定，如历史/悬疑）盲写一章；**乙题只持其本 profile 文字（锚大概率缺失），不持隐杀锚**；
3. 各 2000–4000 字，无编辑润色，只走三问一轮；匿名随机序交用户。

判读：
- 甲题优于旧稿（摩擦/冷热交替/活账/非他不可的说法，≥2 条）→ 核心在隐杀型成立；
- 乙题**没长出隐杀腔**、且按其 profile 文字该有的回报基本成立 → 隔离成立；
- 甲失乙不染 → 结构对、手感靠锚：先给甲建/补锚再复测；乙被污染 → 修 L0/L1 边界，不加症状规则；
- 两题全失 → 归因模型能力/两段法，停改框架换模型。

### 冻结条件（关键）

盲验通过后：
1. **冻结 L0＋SKILL 协议＋模板**，版本化锁定；此后新类型＝①选/建 profile 数据 ②建该 profile 锚 ③REGISTRY 加一行——**核心零改动**；
2. 新类型出问题，排查顺序：锚是否就位→三问是否执行→引擎三行是否空话；三步排除后才允许动核心，且须重新盲验；
3. 这条纪律保证"写更多书"靠**扩展资产**而不是**反复重构框架**。

回滚：全部为 git 可 revert 的文档/文件移动；旧书不读新文件，行为不变。

## 7. 诚实边界

- L0 是对商业连载小说的归纳，非文学通则；
- 三层＋注册制目前只通过静态自洽：解释了 v2 的污染与历次成败；**隔离与提质的证据等盲写**；
- 只有隐杀锚就位：隐杀型之外的品类，手感质量一律标"未验证"；
- 用户是唯一验收者，模型不做任何质量自我宣告。
