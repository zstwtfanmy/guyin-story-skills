## 〇、总判词与三条新根因

v2 报告四层诊断：规划层（卷纲）健康、细纲层模板三代最优但缺输入校验、执行层质感全书最高、**状态层最薄弱**。框架侧把 F1-F7 与 E1-E8 的生成期成因归并为三条新根因：

### 根因一：高保真无输入校验（细纲即代码，但没有编译期）

新管线细纲执行率接近 1:1（06 批次一的效果），于是**细纲的质量上限就是正文的质量上限**：ch61 细纲把「柳含烟送别」排在驿亭夜宿之后，正文忠实执行，产出时序倒错（E1）。旧管线的执行层偏差曾自行消化这类排序 bug；高保真管线里 bug 原样传导。**高保真流水线必须配输入校验**——细纲落盘前查时序、查承诺可交付性，如同代码上线前跑编译。
→ 派生：P 系列（时序自检 / 偏差回填 / 解密位归属）。

### 根因二：发现机制靠人工（打地鼠的结构性原因）

v2 报告 2.4 的三层诊断已经点破：防重复需要三层，现状只有半层。更深一层：**tic 的发现本身靠人工**——旧 tic 靠复盘报告点名（滞后一批）、新 tic 靠下一份复盘报告（永远慢一拍）、台账登记靠随写随更的自觉（62/63 供给线空转的根因三复发）。穷举式黑名单（报告 A4/L1）只能防已知 tic，结构性追不上生成器的复读冲动（E7 实证：旧的清掉、五类新的顶上）。
**治理对象应该是「复读度」本身，而不是具体短语清单。**修法是把发现环节自动化：n-gram 跨章复读雷达（N1）自动发现新 tic，台账自动沉淀（N2），写前自动注入（N3），黑名单降级为「已确认 tic 的精确限额通道」。
→ 派生：N 系列。

### 根因三：软约束无卡点（纪律跑不过执行率）

三个实证：① W2 开卷刷新纪律（06 接线）在 61-63 开卷时没有触发——气韵卡坐标仍停在卷2（F5）；② 术语锚点 advisory 无正文层卡点——「勘合」锚定连续两章「细纲有、正文无」（F7，v1 报告 B8 复发）；③ O3 字数区间解析失准——细纲目标「3000-3300」被截为 3000 再打九折＝2700 达标线，实绩 2712-2754 全部「擦线过关」，0/3 真达标却零警报（F 级发现，报告 2.6 规格偏差的机制根源）。**纪律只对自觉的会话生效；执行率越高的管线，软约束的失守越无声。**修法：能机械的升级为预检/章检项（advisory 也比纯纪律强——至少会出声）。
→ 派生：S 系列（状态时滞预检 / 坐标覆盖预检 / 承诺交付检查）+ J1（字数口径修正）。

## 一、A4 专项评估：黑名单不是终点，是闭环的一环

**结论：报告的三层方案（L1 黑名单 / L2 台账扩域 / L3 写前注入）方向正确，但 L1 单独作为主方案确实如作者直觉——是穷举，是打地鼠。采纳报告三层并把它们串成自动化闭环，黑名单从「主方案」降级为「仲裁通道」。**

| 层 | 报告定位 | 本计划处置 | 理由 |
|---|---|---|---|
| L1 短语黑名单 | 主方案（F3） | **保留，降级为仲裁通道**：作者确认的 tic 用它做精确限额（三档：每章/近5章/相邻章） | 已知 tic 的限额比雷达阈值更精确；06 的 I2 机制（脚本计数 advisory）已建成，项目侧只需填词表 |
| L0 复读雷达 | **报告没有** | **新增 N1**：n-gram 跨章复读检测，自动发现未知 tic | 治本：不再依赖「下一份复盘报告」发现新 tic；机械确定性，符合框架智能替代模型智能 |
| L2 台账扩域 | 治本（F6） | 采纳并自动化（N2）：台账加「类型」列，N1 高频短语自动沉淀 | 报告设想「先手工」——手工正是 62/63 供给线空转的老路，不走 |
| L3 写前注入 | 待 L2 数据 | 采纳（N3）：N1 高频 top + 黑名单近限条目 → beat 卡 {{禁止}} 确定性取数来源 | 生成端控制，在 tic 发生前注入，而非写后清理 |

闭环链路：**N1 发现 → N2 沉淀 → 作者仲裁（进黑名单限额 or 豁免台账）→ L1 精确管控 → N3 写前注入 → 章检复扫**。

N1 的机械判据（防误报，全部 advisory 宁报不拦）：

- 统计口径：4-8 字滑窗 n-gram，当前章＋最近 5 章正文；跨章窗口内同 n-gram ≥3 次 → `phrase-echo-cross` advisory；同章内 ≥2 次且末次出现在章尾 20% 区域 → `phrase-echo-ending` advisory（治 E6 章尾同图重复）；
- 过滤：角色名/地名从 `_tracking-state.json`（characters/geo）取，命中即跳过；含「的了着是在和就被」等虚词占比 >50% 的组合不报；
- 与段落指纹库的关系：粒度互补——指纹库管段落级（≥40 字、bigram Jaccard），雷达管短语级（4-8 字精确计数）；同源同文件（指纹库 JSON schema 升 3，加 phrases 节），同在 `guyin-check-repetition.js` 内实现，不新增脚本。

**N3｜写前注入**（落点：`cards/README.md` 占位符取数表 {{禁止}} 行）


- 纪律：未落实项涉及后续章兑现的，同步登记 `追踪/伏笔.md` 或卷纲待办——堵「细纲与正文漂移 3 处且不可见」（报告 2.5）。

### S 系列：状态闭环（治 F1/F5/F7/E2）

**S1｜追踪时滞预检**（落点：`guyin-write/SKILL.md` 场景路由预检 + `guyin-tracking-commit.py check` 扫描扩展）
