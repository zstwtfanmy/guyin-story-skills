## 0. 设计原则（为什么 V6 不再加规则）

1. **抽象 > 穷举。** 文本缺陷是开放集合，规则永远追不上。框架提供可推导的结构模式，不提供症状清单。
2. **分层隔离。** 框架通法、品类参数、本书内容三层不混。任何一本书的写法（包括《隐杀》）不得提升为框架通法。
3. **零门单模型。** 只有当前会话一个创作主体；不恢复执行层 agent、检查链 gate、风格 lint；流程强制靠"默认动作＋留痕＋用户验收"。
4. **新东西必须过两关**：① 不破坏既有成果（逐条兼容性审计）；② 跨品类盲验不污染。
5. **扩展靠资产，不靠重构。** 框架冻结后，支持新类型＝加 profile 数据＋锚＋注册行，核心零改动。

## 1. 三层架构（框架总纲）

```
L0 框架通法层   风格中立、零剧情内容
L1 品类 profile 层  同一模式在不同品类中的参数（现有 11 profile）
L2 书级层       本书引擎＋人物事件，从用户前提推导，只属于这本书
```

数据流单向：**用户前提 →（L0 协议）→ 本书引擎 →（L1 参数）→ 行文**。L0 不填内容，L1 不规定剧情，L2 不反向修改通法。

### 1.1 L0 通法（＝0928 六条原理的结构表述，文字以 0928 为准）

1. **落差空槽模式**：主体带着 X／处境施加 Y／摩擦产出 Z。X、Y 为空槽，框架不填；落差必须保持张开，不许靠巧合/降智填平，只能由选择与代价弥合。
2. **信息欠账**：先使用后命名；按期偿还旧疑问、新开一笔活账。
3. **具体性**：可感细节承载判断情绪。
4. **代理权**：关键转折主角自判、自选、自担；判断可以错，不能被代办。
5. **视角一致**：不泄露 POV 外信息。
6. **编排者不入戏**：分隔线、加粗判词、设定定义句、全知预告、排队陈列——作者跳上舞台打字幕，任何品类非法。

### 1.2 L1 profile（现有资产，不新建）

`skills/guyin-write/references/默认叙事风格.md` 的 11 profile 即参数表。关键参数对照：

| 参数 | relationship-payoff（隐杀型） | 升级/冒险流 | 悬疑推理 |
|---|---|---|---|
| 认证方式 | 去认证（俗眼看错、不纠正） | **认证即回报**（打脸围观合法） | 不适用，回报是谜底 |
| 叙述者舌头 | 促狭腹诽常态 | 可让位热血 | 克制让位紧张 |
| 细节纪律 | 允许纯闲置生活细节 | 服务获得/升级 | **细节优先做线索** |
| 节奏密度 | 情绪推进即回报 | 每 2000–3000 字一爽点 | 章末强钩 |
| 收尾 | 动作/物件，禁判词 | 金句预告合法 | 倒扣悬念 |
| 落差两极常见形态 | 成年意识／少年身体 | 野心／资源匮乏 | 理性／诡异规则 |

**模式是框架的，两极永远是书的。**

### 1.3 L2 本书引擎（每本书开书时从前提推导，框架不供货）

三行：**主体带着 X／处境施加 Y／摩擦产出 Z**。判废标准：三行换本书仍成立＝空话，重推。落点在书内 `设定/题材定位.md`（见 §7 F6）。允许写"未定"，写着长出来再补。

## 2. 声线锚注册制

**判据**：Y05 持原文逼近九成、Y04 见锚章盲写最佳、破隐抽掉锚立刻僵硬。手感参数（幽默时机、去认证分寸、白描密度）无法靠规则可靠传递，**锚是手感的真正载体**。

### 2.1 锚库结构（私有资产，除 README/REGISTRY 外不入 git）

```
声线锚库/
├── README.md        # 注册制规则、法律边界、出帖
├── REGISTRY.md      # profile → 锚书 → 覆盖场景/来源/状态
├── relationship-payoff/
│   └── 隐杀/         # 现 声线锚库/隐杀/ 整体移入（内容不变）
└── {其余 profile 按需建，不预置空目录}
```

REGISTRY 行格式：`profile ID | 锚书 | 覆盖场景 | 来源 sha 前缀 | 状态（就位/待建）`。一个 profile 可配多锚；默认读主锚。

**注册键是 profile（读者回报结构），不是"都市/历史"表面标签**——隐杀型都市与升级打脸都市机制相反，共用锚即污染。

### 2.2 解析协议（写章唯一生效流程）

1. 从书内 `设定/题材定位.md` 读 profile ID＋版本；
2. 查 REGISTRY 定位锚目录；
3. 就位：首章通读锚全部切片；其后按本章场景选 1–2 段同型切片；
4. **缺失：一句话告知用户、`追踪/上下文.md` 标「锚未就位」，按 profile 文字继续；绝不跨 profile 借锚**；
5. 出帖：本书 ≥3 章用户认可稿后，锚降级为漂移回炉，声线以本书正文为准。

使用边界不变：只迁移声音不迁移内容；不整句搬移、不连续复用独特词组；时代物件以本书为准。

## 3. 变化导向（章不走偏的核心机制）

**旧病复盘**："替剧情办事"的病根是细纲规定**事件清单**，人物变成完成动作。V6 的机制是全链路只认"**变化（delta）**"，不认事件清单。

### 3.1 变化的定义与判据

- 章末比章初，**唯一**不同：一个关系/处境/信息位置的 delta；
- **假变化判废**："他懂得了一个道理"不改变后续选项＝没变。变化必须改变他接下来能做/会做的事，或改变别人对他的动作；
- **变化必须配阻力**：场内"什么东西不让它发生"。变化＋阻力成对，就是这场戏的引擎；
- 刻意停留章：明写"本场无显性变化"及理由，不许糊里糊涂什么都没发生。

### 3.2 一处干预，两个时点

- **卷纲分配（最早，根因）**：一章只分一个主变化；一章装两个变化就拆章；
- **写前一问（零产物）**：动笔前心里答——"这一章唯一的变化是什么？什么在顶着它？"不写文件；
- 写后由三问复读核验，偏离在 `追踪/上下文.md` 留半句理由，不无声偏离。

### 3.3 跨品类形态（不污染）

悬疑＝信息位置变化；历史＝资源/名分得丧；日常＝关系温度位移；热血流＝实力/地位台阶。delta 是空槽，品类填法由 L1 决定。

## 4. 章长机制：默认 3500

- **默认章长 3500 左右（3000–4000，2026-09-29 用户指定）**；细纲填具体值即覆盖默认；
- 写后流程必数字数：**超 4000 原地删减至区间（删同质内容不砍戏），不足 3000 不注水**；
- 实际字数每章记入 `追踪/上下文.md`；
- 不恢复字数脚本/hook。这是流程级强制（必做＋留痕），不是物理拦截。

## 5. 百章连续性：卷边界审计

百章错乱的本质是**档案管理问题**（资产找不到、账龄无人看、压缩无规程），不是写法问题。V6 不加门，加一个周期性只读保养。

### 5.1 审计节奏

每卷结束（或约 20–30 章）一次；产出单一文件书内 `追踪/连续性审计.md`，固定五段：

| 段 | 内容 | 防什么 |
|---|---|---|
| 时间线锚点 | 章号→故事日期/主角年龄/季节 | 年龄季节错乱 |
| 角色名册 | 角色／末次出场章／状态（活跃·休眠·退场） | 休眠角色回归事故 |
| 伏笔账龄 | ID／开章／账龄／决定（续期·计划回收·正式废弃） | 伏笔静默死亡 |
| 能力与代价 | 已展示能力、旧伤、债务、资源约束 | 战力前后矛盾 |
| 读者已知 vs 作者真相 | 里程碑信息位置 | 信息差穿帮 |

两条规则：
- **账龄红线**：开放伏笔超 50 章必须显式三选一，不许无声挂着；
- **休眠重激活**：写休眠超约 20 章的角色前，先读其状态＋末次出场正文；找不到全文搜姓名，不凭印象写。

### 5.2 压缩规程

`上下文.md` 滚动时：只滚动"近三章速记"等窗口信息；长期事实（承诺/约束/人物底色）不许在压缩中删除，只能移入对应档案。**压缩是搬运归档，不是扔掉。**

### 5.3 对用户可见

审计结果连同发现的矛盾点作为交用户内容的一部分；不拦写、不偷偷修历史、不偷偷宣布没问题。

### 5.4 能力边界（不夸大）

零门架构下审计可被跳过——强制只能上 hook，已共同否决。审计是定期抽查不是全量录像。目标是**矛盾能被周期性发现，不是永不发生**；最终防线仍是用户。

## 6. 唯一生效写作流程

```
读（前文＋锚＋档案）
 → 写前一问（零产物：唯一变化＋阻力）
 → 直接写正文
 → 写后：三问复读＋数字数（3500/3000–4000），原地改一轮
 → 记账（上下文/伏笔/角色状态）
 → 交用户（卷末另交连续性审计）
```

**写后持锚三问（统一文本，取代旧四问）：**
> ① **引擎问**：本书落差 {X／Y}——这场摩擦发生了吗？处境起反作用了吗？在选自己的事还是交差？
> ② **声音问**：声音配比合本书 profile 吗？重压以该 profile 允许的方式释放了吗？有没有大段镜头在替心理？有没有编排者字幕（横杠/加粗/定义句/预告/排队）？
> ③ **欠账问**：章末留下想追的活账了吗？该留的疑问有没有被讲完？

四问→三问覆盖不缩小：旧①④并入声音问，旧③并入引擎问，旧②并入声音问（"有没有大段镜头在替心理"）。三问结论＋实际字数各写一行进 `追踪/上下文.md`，可查不拦写。

### 9.1 章级盲写（决定机制存留）
