## 1. 实验事实档案（本文件所有项的证据基础）

### 1.1 实验设置

同一份大纲（两项目的 `大纲/细纲_第036章.md` 经 git diff 验证**逐字一致**）分别由两个框架独立跑完整写作流水线：`test-read`（oh-story-claudecode）与 `test-read-new`（隐笔，含作者性八件、.guyin-review、R1-R6 修改记录、full 四视角审查）。控制变量成立——正文层差异全部归因于框架，细纲层差异归零。

> 勘误：`report/双版本对比审查报告.html` 中两框架标签互换（报告把 test-read 标为隐笔、test-read-new 标为 Story）。报告的**文本级证据**（句子引用、findings 数据）经抽查属实仍可引用；**框架归属结论**以文件系统实证为准。归档修正见 A1-c。

### 1.2 关键事实（后续引用锚点）

- **事实一（源头在细纲层）**：ch36 细纲内部存在未被仲裁的矛盾——情节点 6 写全盘否定（「这局不是破出来的，是送出来的」，且标注"推理≤3步落到此句"），行动成本字段写部分动用（「如今认它**一半**是送的」）。正确答案就躺在细纲里，但没有环节去锁定它。
- **事实二（两框架初稿同病）**：`test-read` 正文 ch36 至今是全盘否定版（「我看见的每一步，都是他们想让我看见的」）；`test-read-new` 初稿同病，其 full 审查 findings（B3-architect）将其标记为 S1「反转自我否定 ch27 高潮」。
- **事实三（审查体系有效）**：`test-read-new` 的 4 个 S1 全部由审查体系抓出——ch36 由 architect 视角、ch39/ch59 由多视角+预检脚本 grep 实锤、E046 由 consistency 视角。对照组 `test-read` 仅 R1 一轮 solo 审查，ch36 型 S1 从未被发现。**S1=0 是漏报不是免疫**。
- **事实四（修复通道失守）**：`test-read-new` 的 ch36 正文由外部模型修复（"真破+被利用"版），但 `追踪/逐章记录/第036章.md` 与时间线 E036 至今登记旧定性（"认被喂：拆神局是送出来的"）。修复绕过了框架管线，账本与正文漂移——事故只修了一半。
- **事实五（既有章检存在事故盲区）**：ch39（全文塌缩 2 行 2624 字、代词叠复"他他"）与 ch59（84 个「个」占位错字）均为**全程带伤运行**，R6 收口才发现。漏因：wordcount 只查总量（2624 字在 2000-6000 合格带内）、degeneration 只查占位符/拒绝语（"他他"与错字风暴不在规则空间）。
- **事实六（正确设计已存在但未接线）**：`追踪/契约对账矩阵.md` 登记着「卷2 智性危机 = 误信干净账」（叠加式）。护栏数据早就在台账里躺着，流水线没有任何环节去对照它。

### 1.3 ch36 事故因果链与护栏映射

```text
①细纲源头定性失控（内部矛盾未仲裁）
   → ②卡片取数丢掉正确答案（{{必须发生}}只从情节点序列取数，"一半"永远进不了卡）
   → ③beat 局部忠实放大（执行层不持全局）+ 外选单维判词（决绝句在气句维度单调胜出）

   → ⑥审查兜底抓住（full 四视角）→ 修复通道失守（外部修复绕过管线 → 追踪漂移）
```

| ③ | G4 | 多采样外选时 |

## 2. 叙事资产护栏（G1-G5）

**核心概念：叙事资产**。高潮/爽点章向读者兑付的情感是已支付的资产（ch27 拆神 = 已全额兑付）；伏笔是未兑付的债。追踪系统只记债不记资产，没收资产（否定前文高潮）时账本不留痕——这是结构性的盲区，G 系列护栏补的就是这个科目。

**叙事学判据（G 系列的共用理论基础）**：全盘否定已兑付资产 = 读者信任账户立即记负，合法做法只有一种——没收当章即兑付等值或超值补偿（当场掀出更大的局）；部分动用（重定价）不需要支付，因为资产仍在，只是换了估值。这是「叠加感」与「被欺骗感」的分界线，本实验修复版（「赢是真的，但线没丢，是我被人引着没去追」）与初稿（「戏是人家排的，他是登台的」）的差距就是这条线。

### G1 细纲资产影响三档声明

**动机**：事实一。正确答案（"一半是送的"）就在细纲辅助字段里，但情节点序列（卡片的唯一取数源）是全盘表述，没有任何环节仲裁这个矛盾。

**方案**：

1. 细纲模板（guyin-setup `templates/long/大纲/`）加一行强制字段：

| 档 | 定义 | 本实验实例 | 支付条件 |
|----|------|-----------|---------|
| 0 纯叠加 | 既往关键事件定性不变，新信息叠加 | —— | 无 |
| 1 部分动用 | 事件部分维度重估，资产重定价不没收 | 「赢是真的，被利用的是专注度」（修复版） | 无 |
| 2 全盘否定 | 事件定性被推翻，资产没收 | 「不是破出来的，是送出来的」（初稿） | **同章补偿声明 + 作者确认**，缺一阻断 |

2. 仲裁脚本（新 `guyin-check-outline-verdict.js`，细纲落盘前跑）机械判档：

| 检测 | 规则 | 判定 |
|------|------|------|
| 翻转句+既往事件 | 情节点含「不是A，是B」句式且引用既往章号/已登记事件名（G2 实体） | 至少档 1 |
| 全称量词共现 | 「从头到尾/每一步都/全是/都是」+ 事件关键词共现 | 判档 2 |
| 档位冲突 | 行动成本/人心节拍字段含限定语（一半/半是/某种程度）而情节点为全盘表述 | 冲突报警，升级作者仲裁 |
| 缺声明 | 触发上述任一而细纲无档位行 | 落盘拦截，补声明 |

3. 触发范围**不靠意图词表**（识破/复盘/反转这类词 flash 会漏判），靠**引用检测**：细纲文本引用既往章节编号或登记事件名 → 必须有档位声明。引用是机械可查的，意图不是。

**落点**：`skills/guyin-setup/templates/long/大纲/`（模板字段）、`skills/guyin-write/SKILL.md` 补纲场景 +2 行（预算评估见 §8）、新脚本进 `skills/guyin-write/scripts/`。

**验收**：黄金样本回归——跑 test-read 初稿细纲（全盘否定+「一半」矛盾）必须报「档位冲突」；跑修复版定性（真破+被利用）必须静默判档 1。

**成本**：1 会话（含脚本）。

### G2 事件定性追踪实体

**动机**：因果链环节④。ch27 逐章记录登记了物证与伏笔，但"拆神=真破"这个定性资产不是任何实体；ch36 登记角色变化"认被喂"时零报警——没收资产在账本上不留痕。

**方案**：

1. tracking-commit 加实体类型 `event_verdict`，Muse 判据章（guyin-write SKILL.md 既有判据：章号 1-3/卷首/卷末/大高潮、细纲标签、关系节点）追踪提交时**强制登记**：

```json
{ "id": "V027", "chapter": 27, "event": "拆神",
  "verdict": "真破：夹层真银+流水账双起获，物证坐实换银",
  "status": "active", "keywords": ["拆神", "夹层", "流水账", "换银"] }
```

- `verdict` 存**从正文摘出的定性句原文，禁概括**（与 P4 场景锚点同构：低模型补全具体名词的能力远强于从抽象生成具体）；
- `status`：`active`（已兑付）/ `repriced`（已重估，档 1 事件落此态）/ `nullified`（已没收）——供收线审计（P3）与完书复盘消费。

2. 章检新增共现检测（并入 G1 仲裁脚本或独立 `guyin-check-narrative-asset.js`）：当前章正文/细纲含「否定模式（不是真的/原是/送出来的/做戏/演的/排好的）× 登记实体 keywords 共现」→ advisory 报警升级作者；该章已有 G1 档位声明且档位一致 → 静默。

3. **误报控制**（不过拟合单书样本）：否定词表裸扫必误伤（"不是"在对话中高频），必须**双层共现**（否定模式 + 事件关键词）才报；只报不拦，升级作者判读。

4. 存量书迁移：tracking-commit 提供 `--backfill` 对既有项目回溯登记高潮章（编排层列候选章清单，作者确认定性句）。

**落点**：`skills/guyin-write/scripts/guyin-tracking-commit.py`（实体 schema + backfill）、章检序列。

**验收**：ch36 初稿文本对 V027 共现报警、修复版静默；误报抽查：正常含"不是"对话不触发（无关键词共现）。

**成本**：1 会话（与 G3 同批）。

### G3 契约矩阵接线

**动机**：事实六 + 因果链环节⑤。正确设计（卷2 智性危机=误信干净账，叠加式）在契约对账矩阵里躺着，ch36 细纲越界时无环节对照。这也是 M1 修正案的落地件（§7）。

**方案**：

1. 契约矩阵模板结构化：`追踪/契约对账矩阵.md` 每条登记项加机械可读字段（卷号 / 契约类型[危机|反转|资产|口径] / 定性关键词 / 方向[叠加|否定]）；
2. 细纲落盘前，G1 仲裁脚本顺手对照：细纲的反转/危机定性关键词命中本卷登记项 → 方向一致放行、方向相反报「契约越界」、命中未登记的危机定性 → 报「未登记契约」提醒补录；
3. **第一版诚实边界**：矩阵是自由文本起步，粗对照必有漏报——级别 advisory（只提醒不拦），Arena 验证误报率后再收紧。宁可漏不可拦错。

**落点**：guyin-setup 追踪模板（矩阵字段化）、G1 脚本扩展。

**验收**：ch36 细纲「送出来的」（否定方向）对「误信干净账」（叠加方向）登记项 → 报「契约越界」；同书正向细纲零误报。

**成本**：半天（数据已有，只缺接线）。

### G4 反转 beat 外选判词升维

**动机**：因果链环节③后半。多采样外选只问「哪版更接近气句」——决绝的句子（「戏是人家排的，他是登台的」）在气句维度**单调胜出**，打磨轮次越多、否定强度越高。外选机制本身成了事故放大器。

**方案**：反转/复盘/识破 beat（判定：所在章 G1 档位 ≥1 的 beat，或 beat 任务含否定翻转句式）多采样后，外选先机械筛——候选版含**超档表述**（超过该章声明档位的否定强度，判据复用 G1 词表）→ 标「超档」出局或降权；再在合规候选里问气句。判词仍是编排层动作，不加执行层 token。

**落点**：`skills/guyin-write/SKILL.md` 执行层调用协议节 +1 行、`cards/README.md` 多采样节 +1 行。

**验收**：构造 A/B 候选（A=超档金句版、B=合规版），外选必须落 B 或标 A 超档。

**成本**：1 小时（纯编排层规则）。

### G5 S 级修复管线协议

**动机**：事实四。审查抓住了 S1，但修复由外部模型裸改正文完成——追踪账本（E036、逐章记录）至今登记旧定性，下次写 ch37+ 或收线审计时账本会撒谎。审查兜底抓住了问题，修复通道失守放走了半个事故。

**方案**：

1. 协议条文（guyin-write 大修场景 + guyin-review 衔接表）：

| 修改类型 | 唯一合法通道 |
|---------|-------------|
| S1 全部；S2 中影响追踪登记的（事件定性、伏笔、角色状态、时间线变化） | guyin-write 大修：读原章+追踪 → L2/L3 分级 → 改写卡 → 落盘 → **tracking-commit 重提交**（含 G2 实体状态翻转） |
| 纯文字 S2/S3（AI 味、句式、复读） | guyin-deslop |
| 禁止 | 会话裸改正文（上述范围内） |

2. hook 兜底（guyin-hook.js post-write 扩展）：正文文件 mtime 晚于 `_tracking-state.json` 最近提交 / 正文与 state 的 last_committed 章号脱节 → session 注入提醒「正文与追踪账本可能不同步；若为 S 级修复请走大修场景完成重提交」。**诚实边界**：hook 分不清合法外部编辑与事故，只提醒不拦截；主体靠协议纪律。
3. 按用户决策：`test-read-new` 的 E036 漂移**不做数据修复**（本路线只动框架不动项目数据），留作 G5 落地后的首例管线演练素材——正好用大修场景走一遍完整重提交，验证协议。

**落点**：`skills/guyin-write/SKILL.md` 大修场景、`skills/guyin-review/SKILL.md` 衔接表、`skills/guyin-setup/templates/long/.claude/hooks/guyin-hook.js`。

**验收**：run-tests.js 加 hook 断言——构造「正文新于 state」负载，session 注入必须含提醒文案。

**成本**：协议 1 小时 + hook 半天。

## 3. 生产线完整性护栏（F1 落盘前格式门）

**动机**：事实五。ch39/ch59 两类 S1 文本损坏全程带伤运行；既有四脚本全部漏过（wordcount 查总量、degeneration 查占位符——事故形态不在规则空间）。Story 框架是 R6 事后发现，隐笔做成**落盘前拦截**。

**方案**：新脚本 `guyin-check-integrity.js`（纯 Node 零依赖），五规则：

| # | 规则 | 阈值依据（实证） | 级别 |
|---|------|-----------------|------|
| 1 | 平均行长 | 总字数/非空行数 >400 → 塌缩报警（ch39：2624 字 / 2 行） | blocking |
| 2 | 单段超长 | 单段 >800 字无换行 | blocking |
| 3 | 叠字 | 连续相同汉字对（他他/我我），白名单排除合法叠词（慢慢/渐渐/往往/看看/试试/想想/刚刚/层层/微微/天天 等） | blocking |
| 4 | 同字风暴 | 停用字表（的了是他我你个在是有和就不人都一）外任一单字频次 >1%（ch59「个」≈2.8% 但本身是停用字——**改判**：风暴检测改用「停用字频率显著超出常态带（如 >3.5%）或非停用字 >1%」双通道） | blocking |
| 5 | 引号配对 | 「」与 "" 计数奇偶失衡 | blocking |

**执行点**：写章循环第 4 步拼接后、第 5 步落盘**前**（gate：不过不落盘，回执行层重拼）；同时排进章检序列兜底存量文件。

**落点**：`skills/guyin-write/scripts/guyin-check-integrity.js`（新）、`skills/guyin-write/SKILL.md` 写章循环第 4 步 +1 行（预算评估见 §8）。

**验收**：真实坏样本回归（A1-a）：ch39 塌缩版、ch59 错字版必报 blocking；正常章（60 章抽样）零误报。

**成本**：半天。

## 4. 质检规则与收敛协议增量

### L1-L3 lint 规则增量（并入 P1 文字视角）

**动机**：实验审查发现的三个 AI 味形态不在现有 ai-patterns 规则库（现有库已覆盖否定排比/微动作复读/比喻密度/引号强调/预告式章尾——报告样本大部分命中，以下三个是漏网）。

| L1 科普腔 | 引号内台词的定义句式密度（「X就是Y」「所谓X」「X的意思是」） | ch1 柳含烟科普「会票就是商号开的借据式票据」——挤兑现场给读者上课（info-dump） | advisory |

**验收**：三样本命中、60 章正常文误报 ≤2 处（advisory 容忍度高）。

**成本**：半天。

### C1 打磨收敛协议

**动机**：双向实证——隐笔 R1 即停（首轮 8.5/10 但打磨不足，文本完成度输六轮版）；Story R6 越改越偏（ch36 否定强度随轮次单调递增）。**打磨深度与打磨方向是两回事，缺一不可**，框架目前两者都没有判据。

**方案**：

1. **机械可停条件**（review 分批 state 追加）：S1=0 且 S2 连续两轮零新增 → 报告附「建议收敛」；
2. **方向校验（每轮必做）**：每轮大修完成后强制合问一次（「这章更**合**还是只是更**合格**」）——合问已存在于 guyin-review P4，缺的是接进修改循环的强制点；大修场景收尾加一行；
3. **轮次上限**：默认 R4 停靠待作者显式续期（经验默认值：R1 不足 / R6 过度的折中，**无强依据，可配置**，过限停靠不禁止）；
4. **solo 降级底线**：降级 solo 时至少保留文字 + 一致性两视角——一致性纯脚本零 token；架构视角的缺口由 G3 机械契约对照补位，**不由 flash 语义判断补位**（M1 的执行面）。

**落点**：`skills/guyin-review/SKILL.md`（可停判据 + solo 底线）、`skills/guyin-write/SKILL.md` 大修场景（轮后合问）。

**验收**：模拟三轮 findings 序列（S2 持续新增 → 停），判据在第 3 轮触发「建议收敛」。

**成本**：半天。

## 5. 追踪系统扩展（T1 / T2）

### T1 物证实体 + 能力跃迁登记（并入 P6，M3）

**动机**：双向实证——反面：小窦 ch28/29/31 描形状 → ch32 突交数值解码（能力空降，B3-character 抓的 S2）；正面：隐笔版验票/拆神的物证链细节密度是最大胜出维度，但这个优势目前靠运气，无机制供给。**追踪系统记事不记物**——推理章组卡时执行层看不到"本案已有什么证物、各自状态"。

**方案**：

1. tracking-commit 加 `evidence` 实体：名称 / 属性 / **状态变迁链**（底座缝细深 → 金漆磨损 → 起获账册——与 G2 定性资产同构的链式登记）；锚点存正文原句禁概括（P4 纪律）；
2. 推理/查案章组卡时自动贴「本案物证清单」行（写作卡新占位符或并入 {{背景}}，预算评估见 §8）——细节密度的机制化供给端；
3. 角色状态实体加「能力/知识获取」字段：角色使用未登记来源的能力 → 一致性章检报警（拦 ch32 型空降）。

**落点**：`guyin-tracking-commit.py`、cards/README.md 占位符表、章检一致性规则。

**验收**：构造小窦型样本（使用未登记能力）报警；物证清单行进卡后 Arena 盲评细节密度不降。

**成本**：1 会话（与 P6 显影器同批）。

### T2 地理台账实体（并入 P4，M2）

**动机**：实验中 4 处矛盾全是同一类——ch1 通州 vs 全书临清、ch2「顺水往南往通州」（通州在临清以北）、ch15 往西 vs ch16 往东。**性价比全场最高**：机械可查、零语义判断。

**方案**：tracking-commit 加 `geo` 实体：规范名 / 别名表 / **相对方位断言**（临清 在 通州 以南）/ 当前所在。章检规则：① 新地名未登记提示；② 方向词与方位断言冲突报警（往南 ≠ 到通州）；③ 行程连续性（上章往西、本章无转折词却往东 → 报警）。

**落点**：`guyin-tracking-commit.py`、章检一致性规则。

**验收**：ch2「往南往通州」样本报警；正常行程章零误报。

**成本**：半天。

## 9. 明确不做（延续 01 §10 / 04 §6 风格）

| 项 | 不做的理由 |
|----|-----------|
| **自动改正文的护栏** | 一切护栏只报警 + 停靠作者，与不变式 4（脚本报的问题永不自动删）同源；机械规则对叙事的误判成本高于漏报 |
| **叙事质量语义评分器** | 「这个反转够不够高级」归合问与作者。本实验本身即实证：flash 初稿写崩了 ch36，flash 判不了叙事哲学——护栏管**支付条件**（档位与补偿），不管**艺术价值** |
| **收编整本作品** | 无切片外消费端；doc 冷路径虽不限体积，仓库体积与维护成本仍真实存在 |
| **基于单书样本收紧阈值** | 60 章单书是全部实证基础，词表/阈值一律标注「Arena 验证后收紧」；G1/G2 的否定检测必须双层共现（否定模式 × 事件关键词），防裸词表误伤正常叙述 |
| **修复 test-read-new 项目数据** | 用户显式决策：本路线只动框架不动项目数据。E036 追踪漂移留作 G5 首例管线演练素材（走大修场景完整重提交，验证协议本身） |
| **推翻 P1 架构降级** | 见 M1：单样本反例不推翻「flash 语义判断不可靠」的论证，只催生该子域的规则化 |
