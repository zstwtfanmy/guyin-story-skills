1. **方向和部分基础设施已落地，完整工程链不能签收。** 单模型写作入口、11 个 profile、运行助手、候选解析、发布 v2 入口、受管 agent 退役均存在；但“代码中有 before/after 字段”不等于精确窗口能恢复。P2.1/P2.2/P2.3 必须重新打开核验。

3. **入口、分发协议和检查消费仍有遗漏。** review/deslop 保留旧行为；实际加载的 tracking-transaction 仍教 v1；短篇路由、hook、显式候选检查和 hard/verify 处置链不完整。不能仅把检查器改为“全绿”来解除阻断。

5. **安装损坏已证实，根因和宿主覆盖未证实。** 本机全局 guyin-write 的 100 个源树跟踪文件中缺 **68 个（29 scripts＋39 references）**；若宿主加载此根，相关流程会阻断。不能断言所有宿主都加载它，也不能归咎某一次 update；“只补 29 个脚本”不足以修复，见三-F。

2. preview 首次允许目标证据路径尚不存在，其他审读证据须存在；仅写 R 内机器证据，不能代写回看。相同输入/稿件/脚本重复运行证据字节稳定，不因无意义时间戳漂移；变更后旧 ready 必失效。
3. “零新增写入”比较受保护文件的成员、字节哈希与存档变化；不能只断言退出码或 revision。prepared 前失败不写正文/追踪/存档；已有在途失败则按 journal 判断，不承诺所有 exit2 都零写入。
4. 精确中断用独立夹具子进程的同步点触发，父进程确认已到目标窗口再终止该子进程；不靠固定 sleep 猜时序、不杀宿主或无关进程。保存终止点、journal、before/after 和两次 recover 的结果。
5. v1 兼容用固定旧版 journal 夹具，保留缺失字段，不用当前发布器临时补齐。v2 新发布测试不得降回 v1 来避开授权/检查；短篇也必须走 v2，不以长篇通过代签。
6. 安装验收包括 scripts、lib、必要 references、默认 profile 与解释器；可选私人作者性素材缺失不阻断。清单按固定发布版本校验，不把源码文件数永远写死 29。
7. 框架自动化运行入口不变，不使用上游 npm test 代替：

```bash
node tests/run-tests.js
node scripts/check-skill-contracts.js
node scripts/check-doc-budget.js
```

测试从仓库根运行，逐条记录实际 cwd、解释器、源码版本/哈希、退出码、pass/fail/skip 与日志；Python 不可用的 skip 不能算发布安全通过。Windows 和 LF/CRLF 夹具必须覆盖；Linux/其他宿主只有真实运行后才写已测。不得修改 git config、绕钩子或抬预算上限换全绿。

### 6.4 真实创作实验的可执行约束

- **先冻结共同输入再生成。** 每个题材 A/C 获得同字节事实、真实硬边界、篇幅、阅读目标和有效文风特征；把共用资料分别复制到各自 B 的实验来源目录，使用书根内 `kind=file/path/sha256/locator` 引用。不能用 B 外相对路径躲开来源校验，也不能将整份事实卡全部升级为逐字锁。
- **一次只比较框架流程。** 首轮仍用同一组事实卡的 A/C，不强制另拆“硬事件/留白”两版；如另测剧情自由度，作为独立实验因素另批次运行，不把条件变更混作框架收益。
- **独立作者会话＋读者盲读，不称严格双盲。** A/C 各用全新会话，不互读输出，不 fork 已看过对方稿的上下文；记录会话标识及实际加载根。模型和可见参数相同，不可见写未知；模型变更则不再称同模型对照。
- **保留全部版本和真实过程。** 一次生成，有明确问题时至多一轮实质修订；同预算、同重试规则，保留初稿/选定稿、生成和修订次数、耗时及可见成本。review 由当前会话逐稿真实回看，指出原文依据；允许“未发现主要阅读损失”，不为必填栏捏造缺陷或固定好评。
- **真实授权与状态提取。** 不让脚本生成“用户原话”；生成、选稿、实验书根发布和改纲按各自授权记录。C 从最终稿提事务，逐章核人物所知/关系/承诺，不预填恒定事务或强求非空。A 不加载框架管理流程，后续在自己的隔离项目内承接己方前文，不独占/共享 C 的推演。
- **先两题材完整首章，再连续单元。** 首章真实反馈支持继续且已获授权时，爽文/历史两组的 A/C 各自续后两章或对称自然单元；不要以只有 C 三章声称完成连续对照。A 可作隔离文本承接基线，不用 C 的检查/编辑指导参与生成；若声明 A 的追踪集成也验收，须另留实际过程而非复制 C 状态。
- **真正中断续写。** 至少一次在半稿成功保存后结束作者会话，新会话只凭冻结输入、对应前文/状态、已保存稿和 session 恢复；原会话不得预写后半篇再由脚本搬运。保留半稿/新稿哈希、会话输入及接续记录；跨天自然中断未做就标未测。
- **随机匿名导出，不损坏反馈。** 原实验原样保留，新 experiment_id 的 run/导出目录存在即拒覆盖；映射随机生成并私存，样本正文隐藏条件和报告。读者原话允许平局、都不愿读；不得先给设计解释诱导判断。没有真实反馈时只交工程结果，创作仍待验收。

### 6.5 交付与中断接续

每个工单交付：修改文件与哈希、对应 A—G/T 编号、正反例命令和日志、未测/失败/授权阻断、精确 next_action。最终分五栏签收：**源码工程、安装完整、宿主实际运行、真实创作、活书迁移**；未授权/未做标清，不由其中一栏通过推导其他栏完成。
