## 1. 目标与架构决策

### 1.1 最终交付物是作品，不是更长的规则

目标不是“减少 AI 词”“多写心理”“比旧样稿好一些”，而是让读者愿意持续跟随具体人物：日常值得读，交锋有各方立场，能力有真实分量，经历留下后果，高潮能兑现此前积累，语言在长篇中仍然自然、有辨识度。

两条路线分别验收，不合成一种万能口吻：

| 路线 | 阅读承诺 | 作品级要求 | 不能当作成功证据 |
|---|---|---|---|
| Y：关系生活与能力反差 | 既想和这些人相处，也想看他们如何应对事情 | 私人愿望与能力并存；关系有各自尺度；共同经历改变后续理解；高压不吞没生活，日常不只是等下一次显能 | 校园、隐瞒身份、吃饭拌嘴、旁人误会等表象齐全 |
| T：市井人物与社会因果 | 人在生计、面子、责任、利益和制度中作选择 | 私心与情感同时成立；资源与组织真正限制办法；成功、损失与信用改变后续选择；规模扩大后仍看得见具体人 | 官名、钱粮数字、粗口、现代知识或沉重语气齐全 |

两书只提供质量标尺和可迁移机制，不复制人物组合、桥段序列、招牌表达或句法指纹。当前证据仅覆盖《隐杀》楔子及前三节、《铁血残明》前三章；战争、组织建设、长线关系与全书结构必须另行取证，不能从开篇外推。

### 1.2 决策：保留运行底座，重整创作层

**不推倒重写整个框架，也不只给 profile 再补一段“要细腻”。** 采用现有单会话作者架构，重整四个连接：

1. **研究到决策**：从原文中的阅读效果提炼有边界的机制，转为本书人物与处境，而非向模型灌注名作标签。
2. **状态到取材**：把已经存下来的关系、知情、旧事和后果实际召回，不能只读一页热上下文就开写。
3. **规划到正文**：规划管理方向与期待，不预先决定每个动作、心理和解法；写作可以发现新的有效走向。
4. **正文到下一轮**：全文审读提供阅读损失判断，用户本人负责最终质量验收，状态负责真实承接；三者不能互相代替。

保留：授权分层、隔离候选、输入冻结、完整章执笔、至多一轮有假说的实质修订、追踪事务、publish/recover、实际加载根校验。

首期不建设：内部模型路由、多代理写作流水线、逐 beat 打分器、自动文学评分器、向量数据库、人格仿真系统或新的全量台账。现有状态首先按真实语义使用；仅当失败证据表明表达能力或检索成本不足时，才讨论局部数据结构扩展。

**支撑判断：现架构能承载这个设计，但当前实现与执行证据不足以认定已经具备目标创作能力。** 文件齐全、脚本通过和机制合理都不是名作级产出的保证。

**执行优先级**：先授权一个小样批次，看到正文，再决定改哪里；不先批准所有工作包。一个故事设想本身没有吸引力，不能靠文风补丁救；简约直写持续优于框架时，先减负而不是继续加规则。目标保持不变，但下一份交付应是可供阅读判断的样稿，而非再次无证据扩充本规格。

## 3. 目标架构与权威边界

```text
本地参照研究 ──→ 通用机制及适用边界 ──→ 经试写验证的 profile
                                           ↓
用户授权／事实／书级约定 ──→ 当前会话的书级与阶段判断
                                           ↓
正式状态＋定向旧文召回 ──→ input：来源、事实、锁、实际文风
                                           ↓
                                  连续写完整章候选
                                           ↓
                             全文回看＋必要的一次修订
                                           ↓
                    事实事务＋候选检查 → ready → 授权 publish
                                           ↓
                     正式状态＋阶段回看＋真人检查点 → 后章
```

这不是新增六个 agent，而是一个作者会话在不同阶段做不同工作。研究可由独立会话完成，盲测可用隔离会话生成；都不构成框架内部自动调度模型。

### 3.1 只保留一个审美权威链

- 用户真实授权、内容边界与已发布事实优先；改变既有事实走 revision，不能用审美自由解释过去。
- 用户书级叙述约定优先于默认 profile；本 run 使用冻结的实际特征。
- 方法手册只提供当前问题的可选办法，不覆盖书级视角、叙述距离或心理形式。
- 规划是假说，不是已发生事实；确定性检查不创造新的创作义务。
- 最终验收权属于用户本人；模型审读、自评、独立模型意见及脚本通过都不能替用户宣布质量达标。
- 同意文档、允许继续探索、选稿、发布授权与质量验收分别记录，不能互相推定；用户沉默或未提出异议不等于通过。

### 3.2 五个能力模块，共用现有文件

| 模块 | 承担什么 | 现有落点 | 禁止替代物 |
|---|---|---|---|
| 本书阅读承诺 | 为什么值得追、主要人物长期张力、允许何种叙述 | `设定/题材定位.md`、已有角色设定 | 作者名、题材标签或作者性问卷 |
| 阶段方向 | 哪些期待正在积累、哪些后果仍生效、下一阶段可能改变什么 | 已有 `大纲/卷纲_*.md`；无纲则先保留当前工作判断 | 每章高潮表、逐动作解法、固定冷却章 |
| 本章取材 | 本章人物知道什么、彼此经历什么、什么条件限制行动 | 正式快照、逐章记录、相关正文、`input.sources/facts` | 只读近三章速记、只看故事梗概 |
| 场景生成 | 把材料变成相处、交锋、发现与体验 | 当前会话、`R/drafts/` | 逐条把人物标签翻译成动作 |
| 作品反馈 | 找到实际阅读损失并判断跨章稳定性 | `R/review.md`、`追踪/运行记录/`、`追踪/读者信号.md` | 清零报警、作者自评、机械平均分 |

不增加每章必填卡。只有信息将影响当次选择时才补足；没有完整卷纲不阻止试写，阶段方向也不要求先知道全书结局。

## 4. 创作与连续性协议

### 4.1 研究：从“这本书好看”转为可迁移选择

每条研究记录只有以下必要信息：原文版本及章段定位、足够前情、人物面临的处境、作者作出的选择、产生的阅读效果、依赖条件、反例、可迁移与不可迁移部分。分析性转述为主，必要引用至多一句，不将原文打包进技能或发送到外部服务。

首轮在已有开篇证据上定向扩样，不先拆完整本书：

- Y 补两条跨章链：共同生活中的理解变化；压力中的能力使用及事后关系回应。读取起因、变化、后果连续区间，不只读名场面。
- T 补两条跨章链：利益／信用选择及后果；资源／制度／组织限制及执行后果。若区间涉及战争，补对应历史、地理或技术依据，不拿小说台词当史实。
- 两路线都记录至少一个反例：直接心理、较长概述、公开评论、平静相处等如何有效，防止研究只寻找支持禁令的材料。
- 先按目录定位候选区间，再读必要前情和完整区间；缺少证据就标“未覆盖”，不编造章名和结论。

产物沿用 `拆文库/{书名}/章节/第XXX章.md`、`节奏.md`、`情绪模块.md`、`文风.md` 等现有布局；明确标定向覆盖范围，不假报 Stage 2–7 全量完成。可先保存在独立实验目录中，验收后再入库。定向研究是拟补接口，原有黄金三章停靠与全量授权纪律不变。

文风统计留在客观观察区；“选择为何有效、何时无效”写机制分析区。不能从句长均值导出全书句法规范。

### 4.2 书级与阶段：让原创故事持续长出新局面

仅有“想过好日子＋能力有限＋有人阻挠”还不是可持续的故事。开书或阶段陷入重复时，由执笔者提出一小段本书设想：**具体人物珍惜什么，习惯怎样应对事情，这种办法与什么愿望或关系相牵制，其他人各自的选择为何会改变局面**。缺内容先做创作判断，不向用户追讨人物问卷；已有设定够用就直接取用，不新增必填卡。

- **人物不是配置表**：经历影响偏爱、自我辩护与不愿放手的事；矛盾之处可以长期存在，不强制创伤、人格缺陷或每人一个反差。
- **关系不是共同任务**：同一段经历可被各方不同理解；帮助、依赖、竞争各有理由。主角不在场时，别人仍有生活和事务，但不为证明自主性硬插配角视角。
- **能力不是万能答案**：本事可以真正好用，不能靠每次强行削弱制造困难；它解决某件事后，可能改变职责、信用、关系或其他人的选择。新局面来自这些变化，不只是更强的坏人或更大的数字。
- **方向不等于事件队列**：在阶段转折处判断有哪些合理而不同的走向、哪一种最值得展开及其前提，不预写每章解法。稳定相处也可深化已有意义，不要求每章不可逆转折。

书级设想放已有 `设定/题材定位.md`，近期走向放已有卷纲；没有授权写这些文件时只留在实验记录／当前工作判断。它们是假说，不是事实或硬锁；进入配对试写前，两组看到相同的既定背景，不提前分配人物回应、反转答案或结局。若换掉姓名地点仍可套任意同题材书，只能提示设想偏泛，不能据此机械判稿失败。

本书还须知道**读者为何在意、目前在等待什么**：Y 可期待一次被理解、一次能力真正介入生活；T 可期待某个办法在真实人情和执行条件中见效。悬念既可以来自“不知道结果”，也可以来自“知道得比人物多，等待彼此相遇”。兑现方式留给正文，不把所有日常物件升为伏笔。成稿偏离未锁定规划可成立；改正式规划仍须独立 plan-patch 授权。

### 4.3 章前定向取材：从存得下变成用得上

准备段按下列顺序执行，不另加阶段门。新 run 先完成取材、计算哈希并落盘 input，再调用 `start` 进入 `prepared`；不能先 start 再原位补 input。恢复已有 run 先核对冻结输入与现状，需补来源时按 §7.4 另存输入修订，不静默改旧文件。

1. 先按现行协议检查在途发布、未完成 run、state、待审和真人检查点；确认书根、候选分支与实际加载根。
2. 读当前热上下文与紧邻上章必要全文。长心理、误会、交锋未完时读完整承接段，不只读最后几百字。
3. 按本章涉及人物读取完整 `追踪/角色状态/{姓名}.md`，特别查关系、知情、未结事项；群像超六人时按相关性定向读，六人是热卡限制，不是小说登场上限。
4. 对重新同场的人、旧物重现、承诺兑现、组织行动或旧事重估，查对应逐章记录／时间线／实体视图，再回到决定当前回应的原正文。`章节金字塔.md` 是定位索引，不是完整情感记忆。
5. 专业前提影响方案可行性时，取得可追溯材料；区分事实、人物相信的事与叙述者尚未揭示的事，不能把读者已知自动分给所有角色。
6. 用现有 `input.sources` 登记真实读过并将使用的书内文件及哈希、`locator`；`facts` 仅放有来源的事实，`locks` 仅放真实锁。作者的下一步设想不写成事实。选定 profile 的实际定义完整放入 `effective_features`，不只抄速查表。

检索停止条件是“足够支持本章选择与承接”，不是凑足材料数。遇到矛盾或来源缺失就定位核实，不用想象填平。读取清单与哈希只能证明来源可追查，不能自动证明理解正确。

声线承接优先从本书已经认可的正文取证：近期语气、同一关系早先怎样说话、叙述者与人物各自的观察尺度。必要时登记具体章段为参考，不复制惯用句、笑话或段末收束；人物对不同对象、在不同压力下可以说话不同，成长有经历依据即可。冻结 profile 是防止库升级偷换方向，不是要求人物永远不变；研究原书不替代本书自己的声音。

**容量约束不改变**：热卡硬上限 12288 字节，活跃人物最多六人、伏笔最多八条、近三章；单角色视图硬上限 8192 字节，单章摘要 900 字节。长期约束最多六项、连贯性风险最多五项，不能把所有余波塞进去。优先定向读冷材料，不靠扩热卡、隐去重要事实或假退役腾空间。

### 4.4 执笔：把材料变成读者正在经历的事

连续写章前，先决定本段**什么值得读者停留**，而不是先安排若干动作完成信息交付；这属于执笔判断，不另交场景卡。人物知道什么与读者何时知道分开处理：可以让读者误会、预感、等一句回应或忽然理解，但不能藏起已承诺视角本应自然呈现的信息，事后才补关键前提救反转。

详略围绕正在发生的体验选择：一句话为何此刻难以说出口，一个人为何只回答了不重要的半句，一项办法怎样在执行者手里走样。允许回应拖延、行动先发生、感受后来才明白；也允许直陈或概述最有效。不要把“注意→回忆→感受→动作”排成每段固定链；能让人愿意相处的平静段落，不必补一个冲突或状态变化证明价值。

以下只供主导损失出现时诊断，不逐项装入生成提示：

| 阅读损失 | 执笔／修订选择 | 生效表现 |
|---|---|---|
| 心理只有战术判断 | 让同一件事触动个人愿望、自我评价、旧经验或不愿承认的在意；需要时直接展开想法 | 读者理解为什么偏偏此人在意，不是“紧张”换成三种身体动作 |
| 配角总是接任务或给认证 | 回应来自配角自己的所知、损失、责任与相处分寸；允许帮忙而仍不赞同 | 同盟不共享一颗脑，主角也不必次次化解场面 |
| 细节多却没有个人感 | 选择人物此刻会注意、会误读的具体信息；普通生活事实可自然存在 | 细节使关系或体验具体，而非职业比喻与感官清单 |
| 叙述像报告或电报 | 需要停留的回应写开，重复流程概述，必要背景讲清；完整心理、旁白评论与不同句长按已选 POV 使用 | 因果清楚且读得顺，不靠全删说明或机械拉长救稿 |
| 高潮有结果却没分量 | 检查之前让读者在意了什么、当下改变了谁、代价在后文如何继续 | 兑现有积累与余波，不必使用“假胜→崩解→反转”模板 |

Y 允许能力暂退背景，生活与关系本身承载回报；T 让制度进入人的争执、执行与后果，但不禁止必要说明。两路线均允许笑、沉默、直陈和叙述调侃，不规定心理次数、闲笔数量或高低压章比例。

POV 由书级约定决定：第三有限仍需守知情边界，多视角／全知可有清楚的叙述中心转换。不是先选择深度限知，再用“一次配角短拍”冒充另一种叙述权限。

### 4.5 章后记录：先有正文，后提真实变化

不新增 state schema，按现有字段表达：

| 已发生的信息 | 放在哪里 | 不应放什么 |
|---|---|---|
| 私人愿望、近期身心状况 | 角色 `goal/state`；持久背景在已有角色设定 | 为“有人味”临时造出的爱好配额 |
| 关系的当前理解与未解决经历 | `relationships/open_threads`；必要时短记来源章号，回查正文 | 好感度自动增长、双方未表达却被写成共同认可 |
| 谁相信／知道了什么 | `knowledge`，必要时注明误信、怀疑；事件区分客观事实与读者已知 | 将猜测写成真相、将全知叙述泄漏给角色 |
| 实际发生的组织行动与资源后果 | `timeline_events`，并按需关联人物资源、现有实体；规则背景在世界观 | 把组织伪造成角色以套快照；凭空建立经济模拟账 |
| 真正形成的期待和未结事项 | 已埋伏笔、角色未结事项、下一章承诺各按其语义 | 把所有吃食、闲聊、旧物登记为必须回收 |
| 跨章体验、阶段阅读判断 | `追踪/运行记录/第NNN章.md` 的阶段回看节 | 塞进 `delta.result` 或手改 `章节金字塔.md` |

快照更新是受影响角色的完整当前快照，不能因本章没写某段关系就漏掉旧关系。一次稳定相处可以有阅读价值而没有人物／关系变化，不为填表强造变化；**正式事务仍必须提供 delta 及非空 result 章摘要，相关变化数组可以为空**。现实因果已变但文字没有登记时，从正文补事实，不反向修改小说迎合表格。

revision 始终以最新全局状态为基础：重算被修章的完整连续性记录，只并入修订造成的当前变化，不把后续关系退回旧貌；上下文当前条目须保留，退役仅 append。后续正文冲突登待审，不自动改后章。工具能防部分结构错误，不能替作者判断快照是否语义倒退。

### 4.6 阶段回看：让长期后果进入下一次选择

在获准的连续段检查点、重要关系／局势变化后，或取材显示旧摘要不足时，做一次阶段回看，而不是每十章强制制造转折。

- 读该段正文；除了记录期待与代价，还判断哪些选择真正改变了后续可能性、哪些关系让人更愿意继续跟随。若反复是“受轻视→证明本事→众人认可”，应改变处境与选择，而非再换台词或反派姓名。
- 在阶段规模扩大时回查具体人：主角是否学会或失去了什么，配角是否仍有自身生活，组织行动有没有执行者的理解与偏差；下一阶段不必提高灾难烈度，也可以深化既有关系与责任。收尾看核心人物选择和读者最在意之事是否获得回应，不以伏笔账全部清空代替作品结束。
- 正式已发布段的回看附在 `追踪/运行记录/第NNN章.md`，标明范围、逐章来源路径与哈希、截至 state revision、已验／待验。未发布候选链的回看只放 R 或实验目录，不混入正式追踪。
- 下一章 prepared 按范围读取最近相关回看，再查当前状态与关键原文；回看只是带来源的解释性摘要，不能覆盖状态、正文或用户锁。
- 某来源章被修订，相关阶段回看即待复核；先读修订内容与受影响区间，另记修订版。不得继续把旧摘要当权威，也不得从摘要重建已删除的事实。
- 不手动填写派生金字塔中的“待生成”。首期不实现自动聚合器，正式消费以上回看与原文；以后若需自动索引，先测检索成本再立工单。

## 5. 审读与质量验收

### 5.1 两种门分开

**运行门**只判断授权、版本、材料、事实与发布完整性，沿用现有脚本；工程通过可以据实报告，但不等于用户验收通过。**质量门**判断正文是否值得读，必须由用户本人阅读后明确验收，不新增脚本判文学好坏。模型负责写作、诊断、修订建议与证据整理，不拥有最终验收权。

`R/review.md` 至少包含：候选完整哈希、实际读到的内容、值得保留的位置与原因、最主要阅读损失及证据、采取或不采取修订的理由、修后收益与损失。保留项须指出**语言或叙述带来了什么正面体验**：例如某种观察使人亲近、接话的分寸让人发笑、信息的迟到改变了前一句的意味；没有这样的收获便如实承认，不能用“无明显错误”代替精彩，也不强迫每章制造金句。

审读先读正文并记自由阅读反应，再对照创作目标与材料，避免“已包含所有机制，所以好读”。先分清主导损失在故事选择、场景展开还是措辞；前两者失败，不靠补心理、改同义词或加生活细节修饰。事实与知情仍需语义审查；有效直陈、评论、稳定相处不因形式自动报错。局部修订后复读承接，结构／POV／跨场因果改变重读整章；换稿重提事务与重跑检查。

**一次修订不是作品终身只能改一次**：默认限制的是当轮常规审读，配对实验双方同预算。若结构性失败未解决，停在未达标，不以“宁留糙”替坏结构开脱；另获明确的修订目标、范围与追加预算后再回炉，保留原稿与累计成本，不能靠改 run 名清零次数。未发布候选在现 run 另存版本并按需修订 input；已发布章才新开 revision run，跨章影响先查明、逐章授权处理，不自动改后章。实验追加回炉属于新轮次，不能混入原来的公平对照结果。

最小工程保护仍是证据绑定与缺件拒绝。不把阅读栏目升级成必填评分 schema；它不能防伪读。研究、生成、评读分别留证，若实际是同一会话自评，应明示其局限，不能换一个角色名冒充独立阅读。

### 5.2 项目质量标尺

| 编号 | 验收问题 |
|---|---|
| Q1 人物 | 此人是否具体可感，能否理解其在意、偏见与变化？行为是否来自经历与处境，而非性格标签？ |
| Q2 关系 | 对方有没有自己的尺度与记忆？对话、合作或沉默是否显露关系，而非总为主角解题？ |
| Q3 语言 | 除了顺畅无错，具体的观察、语气、信息次序或句段节奏带来了什么亲近、趣味、张力与余味？不要求每段出彩，但应能定位实质语言收益，而非只报没有套话。 |
| Q4 追读 | 本段本身是否值得读，愿不愿继续？不能只靠未揭谜底或危机拖读者。 |
| Q5 因果与世界 | 人物所知、资源、时间、制度和专业前提是否可信地限制选择，后果有没有被兑现？ |
| Q6 积累与余波 | 后章是否承接前章的关系经历、损失、信用和期待？情绪兑现有无积累，赢后是否一键清空？ |
| Q7 长段组织 | 阶段目标是否发展而非换皮循环？多线、压力和日常是否共同服务本书阅读承诺？ |
| S 路线成立 | Y 的生活／关系与能力是否共存，或 T 的具体人／制度／社会后果是否互相作用？不是靠外壳识别。 |

分档采用项目约定，不冒充客观文学量尺：0=未成立，1=机械或断裂，2=部分成立但与匹配原文有明显距离，3=仍有差距但阅读体验接近，4=本次观察范围相当或更好。短场景未涉及的 Q6/Q7 标未测，不能因此算通过。

**最终验收由用户本人作出，覆盖正式 L1–L5 各阶段和整部作品。** 模型自评、独立模型审读、规则符合度、工程测试及其他读者意见均不能替代用户认可；即使全部给出正面结论，也不得自行标记“质量达标”“验收通过”或“已达到用户目标”。其他真实读者可提供参考，除非用户另行指定，不设其必须参与、共同签字或拥有否决权的条件；没有其他读者不阻止用户验收。

评读时先隐藏方案标签、随机顺序看稿，不展示自评分；先问哪里想停、记住了谁、什么地方真的起了感受，再做维度判断。用功能、篇幅、前情与 POV 匹配的原文锚校准；读过原书可能认出来源，记录这一点，不宣称完全双盲。初期小样只需用户的真实阅读反馈来决定是否值得追加，不逐稿填全套评分表，不宣告 L1。

正式过门条件：用户确认本阶段所有适用维度达到至少 3 所对应的标准，愿意继续读（完结时为认可整体阅读体验），并明确认可本次验收通过；所有实质事实／授权／POV 问题已处理。用户可评分，也可直接给出针对这些标准的明确结论，模型不得代填分数或将普通赞许推断为通过。其他评读意见有分歧时，提供具体段落与理由供用户裁决，不以票数或均分替代用户判断。原文锚、维度适用范围与标准在开测前约定，不能看完差稿后自行降低；事实正确也不得抵销不好读。

验收记录必须关联用户实际审阅的稿件路径及完整哈希、路线、章节／阶段范围、用户原话与日期。不要求用户提供哈希，由执行者绑定其审阅版本；范围不清时不得扩大解释。尚无用户明确验收结论时标“待用户验收”，用户指出未达标则保留“未达标”；可以另获授权继续探索，但不得因此升档。换稿后旧认可只适用于旧版本，新版本重新提交用户确认，不能继承验收结论。

### 5.3 证据阶梯：不能用三章宣告作品级完成

| 级别 | 验证范围 | 可作出的结论 |
|---|---|---|
| L0 工程可用 | 契约、检查、发布、恢复、加载验证 | 系统能安全工作，不涉及文学能力 |
| L1 文笔与场景 | 每路线三类校准场景＋两个新完整章 | 已测新内容具有目标阅读品质；尚未证实持续性 |
| L2 连续开篇 | 每路线全新的连续三章 | 短期承接成立，不能外推长线 |
| L3 故事单元 | 同一作品延续至约十章，完成实际的铺垫—变化—后果单元 | 本单元在完整阅读中成立；若单元未闭合，证据仍不完整 |
| L4 长段／卷 | 每路线至少约三十章，并覆盖一个完整主要故事弧及余波；弧更长则读完实际弧 | 有长段稳定性证据，不宣称整个长篇或未测阶段已达到 |
| L5 作品 | 完成约定作品体量及整体验收，检查开端承诺、发展、主要兑现与结尾后果 | 仅对这部作品作作品级结论，不外推所有模型和题材 |

L0 仅据实际工程结果报告；L1–L5 的“可作出的结论”均以用户对相应版本与范围明确验收通过为前提，满足篇数或证据齐全不自动升级。十章／三十章是观察容量，不是章数配额或结构公式；不得为验收截短故事弧。不同路线分别评级，达到 Y-L3 不能写成 Y/T-L4。用户愿意保留未达标稿并继续，照实登记授权，质量等级不因此上调。

## 6. 实施工作包

研究、框架维护与执笔可由模型执行，最终验收由用户本人负责，不以四个默认 agent 代替。所有包当前均未执行；后续明确授权哪些包，就只实施那些包。

**先小样、再定向修改、最后合入**：W0 保存不可变的 C0 基线，先按 §7.2 做简约直写 A／C0 小样；发现主导损失后，才从同一快照建立候选副本，按需执行 W1–W4。表中修改路径均指候选副本；记录真实入口、文本和哈希，不改安装目录或宿主配置，不只口头声称“使用 C1”。W6 才合入有证据支持的差异，未取用的清单项留“未处理”，不冒报全量整改。

两路线目标都保留，但逐条推进；默认先 Y，因为已有 Y 三章诊断可定位问题，并非声称 Y 更容易。先取得第一路线的小样与连续性反馈，再扩大到第二路线，避免首批同时维护两本长篇。共享修改只在一条路线测试过时，其他路线仍标未验证。

| 包 / 优先级 | 依赖 | 修改或执行落点 | 交付与完成条件 |
|---|---|---|---|

## 7. 验证执行设计

### 7.1 直写、基线、候选与归因

- **A：简约直写**：同一模型拿到相同事实、真锁、必要前情、完整所选 profile、篇幅与 POV，只省去框架工作流及方法指令，在独立实验文件成文；不是不给方向的弱基线。A 不运行发布链、不触碰正式书、不伪造 ready。初探与 C0 配对用当前 profile，最终与 C2 配对则使用 C2 同一完整候选定义。
- **C0**：W0 固定的当前框架与完整 profile，历史文档冲突作为原基线条件如实保留。
- **C1**：只含本轮已明确选用的 W2–W4 规则／取材／审读修正，profile 与 C0 相同；未改项不算在方案里。
- **C2**：C1 加经研究的候选语言定义，仅替换所选 profile 文本；下列两段提供可执行起点，须经 W1 修正后冻结，不能直接标“已验证”。

**Y 候选（`relationship-payoff` 实验覆盖）**

> 从人物当下在意的生活进入，让经历影响注意、好恶和对人的理解；能力是这个人的一部分，不必每场证明。想法可以直写、转述或融入人物语气，依书级视角选择。关心与嫌麻烦可以并存，不必立即说透或换成计划。熟人按各自尺度回应，亲近不等于总能理解。重复日常可概述，关键相处与感受允许停留；急事写清行动，事后生活按处境继续。对白与叙述可有幽默，不靠固定误解或旁人赞叹证明能力。细节属于此人此刻，句段随注意变化，不反复用判词封口；相处本身可以是回报，无需另插脱离主线的闲戏。

**T 候选（`historical-causal` 实验覆盖）**

> 从具体生活和社会处境写人：同一笔开销、承诺或争执，在各人眼里分量不同。生计、责任、面子、私心与旧交情共同影响选择，有本事也可能碰到办不成的事。按人物所知接话，允许岔开、顶回和改变语气，不轮流汇报方案。背景讲到能理解得失，重点交锋展开，重复工序略过；物资、信用、人员和制度真正限制办法。语词按时代、人物来源和叙述层次区分，不堆官话，也不一刀切禁用现代说法。叙述评论与落差可以好笑，但损失和后果不因此消失。动作与心理均可直写，不把历史写成账本，也不靠满篇沉重冒充厚实。

这些是通用创作指引，不是两书独特表达的复刻；生成只读所选一段，不连带加载本文、作者名或参照原文。只在实验 input 中覆盖，C1 所用 profile 原文保持不变。

先做 A/C0 小样，再按发现的问题比较 C0/C1；只有语言方向仍缺失时才追加 C1/C2。C0 已接近且更轻可以保留；C1 只比 C0 好、却仍明显不如 A，不能宣布成功。多个改动一起生效只能归因为整体方案，不从少量偏好票推断某条规则的因果效应，也不声称统计显著。

最终留出比较使用**冻结的同一框架方案 X（C0/C1/C2 三选一）与匹配的 A**，不再四方案全排列。若 A 持续更好，暂停合入，定位可去除的生成负担；可以从 A 的简约创作上下文重新设计 C1，但事实、授权、隔离和发布底座不删，仍须用新题验证。不能把 A 成稿事后套一个 session，就称框架自主生成已通过。

配对控制同一模型及可控参数、事实材料、前情、篇幅、POV 与修订预算；用于文笔比较时实际提供的材料也须一致。检索协议的测试另记来源选择差异，不把多给剧情答案算作文笔增益。宿主隐藏提示、模型版本或参数不可控就如实记录；若无法隔离框架自动注入，不把该稿称为干净的 A 对照。生成会话互不见稿，执行器不预写人物回应或 review 结论。

C2 的实验覆盖仍沿用基础 ID／版本，把实际候选段完整放进 `effective_features` 字符串数组；实验记录保存完整文本及哈希。仅真实获准选用候选时填 `selection_basis=user-selected`，不新增 input 字段，不冒称新 profile 已发布。

### 7.2 分批验证与成本上限

**第一批只看两份短稿，不先产生几万字待评文本。** 每次追加前登记总输出预算、调用／时间预算、最多实质修订次数及用户可读篇数或时数；研究、弃稿和重试也计入实际成本。未获追加预算就停，不自动把“小样授权”扩成全套实验或两本连载。

| 顺序 | 最小执行 | 决策与停止点 |
|---|---|---|
| ① W0 小样 | 一条路线、一个能同时观察事情与人物关系的原创处境；A/C0 各一份 1000–1800 汉字初稿，总计约 2000–3600 字；先交初稿不自动润色 | 用户先读正文，指出实际感受；只定位下一步，不宣称稳定能力或 L1 |
| ② 定向处理 | 两稿均乏味：先查故事设想、必要材料与输出条件；A 好而 C0 差：先查生成负担；只在具体语言／关系等缺口上选 W1–W4 必要项 | 一次只针对一个主导假说或不可拆分的小组改动，不为完成清单遍改框架；没有明确假说就暂缓改码 |
| ③ W5 校准 | 该路线覆盖相处、受阻交锋、事后反应三类场景，两方案通常共六份短稿；仍 1000–1800 字。C0/C1 为主，C0 足够好可继续 A/C0；C2 仅另获追加时比较 | 每稿至多一次实质修订，保留所有初稿与弃稿；与冻结条件完全相同的 W0 稿可复用，不算新的独立证据；两轮同类调整无收益即停 |
| ④ W5 留出 | 冻结 X 与匹配 A，每路线两个未暴露的完整章 brief，每题各一份，共四份 2500–3500 字完整章 | 用户按 §5.2 确认 X 两章通过，且相对 A 无未解决的明显退步，才具备进入 W6 的质量前提；改码／加载仍另行授权，不能逐题换方案或挑最好稿拼通过 |
| ⑤ W6/W7 连续 | 选定方案接入后，另开一个原创故事，从三章延续至实际故事单元和长段 | 新内容不得把校准故事换名；按真实反馈逐段继续，不先授权无限连载；另一条路线随后独立完成同样验证 |

调参开始前，由用户或不参与调参的独立会话封存两个完整章 brief；调参者只能知道测试范围，不能提前见题。至少一题实质改变关系类型、社会环境或压力来源；暴露就降为校准题，调整提示后不能再称旧题为留出。无真正隔离条件时照实标非独立验证，不假装封存成功。

brief 只给足处境、必要前情、既定背景、真锁和篇幅／POV，不预写心理反应、解法与结局。原文锚由研究侧按功能选定，供评读侧校准，不给生成侧逐句仿照；匹配不上就报告未测，不拿原书高潮压新稿过渡段。

两道完整章题默认各是一个独立原创故事的首章，X 各用独立沙盒 B、`chapter=1/mode=append`，不把题号 2 当正式章号 2；背景可来自授权的原创设定，不伪造“已发布前章”。A 不共享或修改 X 的状态。跨章能力留给后续连续验证，不从单章设定中虚构证明。

短场景只比较生成条件，**不是完整框架 run**，不伪造 session、事务或 ready；结论只限该取样条件。留出 X 的完整章应从指定入口实际生成、回看并到 ready，A 保持普通隔离文本；至少一次验证恢复与换稿证据失效，不把事后补协议当框架生成。L1 后仍须走新故事连续验证，初稿、修订稿和总成本分别报告。

### 7.3 连续链与授权

- **未发表样稿链**：明确选定父稿，记父稿哈希并读必要全文；只能证明文字承接，不能声称生产追踪／发布验证完成。原正式 state 不因样稿链推进，不伪造 append 事务绕过章号约束。
- **完整框架链**：在独立沙盒书取得写作及本地 publish 授权，逐章提交正式状态再续写。这里的 publish 是本地安装正文，不是网络发表，也不含 git push。
- L3/L4 的“框架长段稳定性”必须使用第二种证据；仅第一种只能报告文本长段结果。用户未授权沙盒发布就停在该验证边界。
- 至少在一个获准连续段内换新会话续写，按恢复协议只凭可追溯材料承接同一分支；记录关系理解、人物知情、语气与未完行动是否接上。不能只在保有完整聊天记忆时测试后宣布磁盘记忆有效。
- 第三章后以及后续约定段末使用现有读者检查点；不得为赶实验跳过反馈。正式反馈版本锚由现有工具计算，复杂评分附件放运行记录，不给 14 列表格私加字段。

### 7.4 工程执行与接口约束

`F`=仓库根，`W`=实际加载的 guyin-write 技能目录，`B`=已初始化的独立沙盒书，`RUN`=新 run ID，`R=.guyin/work/$RUN`（相对 B）。以下为后续执行示意；先按环境确认 Python 解释器，不指向用户正式书。W5 中 W 必须指向当次选定的基线或候选副本，W6 后再核正式交付的加载根。

调用前先在 B 下创建获准的 R，完成取材并写好 `R/input.json`；每个 `kind=file` 来源都保存实际计算的完整 64 位 sha256。`start` 只读取现存 input、记录哈希并建立 prepared，不生成输入，不把计算值回填原文件；缺来源哈希即使通过 start，也会被 v2 preview/publish 拒绝。

```bash
python "$W/scripts/guyin-author-session.py" start --project "$B" --run "$RUN" --input "$R/input.json"
python "$W/scripts/guyin-author-session.py" checkpoint --project "$B" --run "$RUN" --input "$R/checkpoint.json"
python "$W/scripts/guyin-author-session.py" status --project "$B" --run "$RUN"
```

`checkpoint.json` 按阶段重建，不重复调用同一份伪装进度。**所有文件指针相对 B，不是相对 R。** 首次完整稿登记形如 `{"phase":"drafted","draft":{"path":".guyin/work/<RUN>/drafts/v0001.md","complete":true}}`；换稿或首次登记会清空证据，同一次提交的证据不被接收。随后另次用带完整 R 前缀的 `review/transaction/check_evidence` 指针登记对应阶段；review 和检查证据内含当前候选 hash12。阶段能否登记取决于目标阶段产物是否齐备，不靠逐级空调用证明进度。`status` 不加 `--json`。

`input` 沿用闭集 v1。书内文件来源必须在 B 内；框架 profile 在 W 外部来源侧核版本，实际特征冻结进 input，不把 W 路径塞进书根 sources。专业资料或研究要点若需入书内来源，先在获准范围内保留可分发的事实摘要及出处，不把整本参照原文复制进热路径。所有来源、授权原话、哈希和锁都必须真实；`selection/publish=null` 合法，缺发布授权停 ready。

运行中补来源、事实或发布授权，先另存 `R/input.vNNNN.json`，再以 `checkpoint.input_path` 指向书根相对路径。该操作会重核旧完整基线、要求 target 不变并清空四类证据；重新审查受影响内容、生成证据后才能回到 ready。正式基线已变或无法证明则按恢复协议处理／另开 run，不能改旧 input 或借输入修订抹掉漂移；也不因库更新替换旧 run 已冻结的文风。

事务 schema v1、state schema v7、发布清单 schema v2 是三种不同版本。`commit.context` 只收 position、long_term_constraints、active_character_names、continuity_risks；近期摘要与下一章承诺由本章 delta 派生。preview 与 publish 按 [追踪状态协议](../skills/guyin-write/references/consult/tracking-transaction.md) 的真实清单执行，低层 commit 不是日更正式化捷径。

在 F 下运行既有工程检查并留退出码：

```bash
node scripts/check-skill-contracts.js
node scripts/check-doc-budget.js
node tests/run-tests.js
```

实际交付包再执行 `guyin-check-package.js verify --root <实际 skills 根>`。有意源码修改后，先审差异、通过工程检查，再按已有流程重建版本清单；不能以旧清单报错为由跳过校验。部署另行授权，create-if-absent 不会覆盖旧书文风／AGENTS／设定，旧项目需要具体建议补丁，不能声称模板更新已自动迁移。

新增或调整测试应覆盖以下行为，不只检查某个词还在不在：

- 文档契约：实际调用路径不复活普适心理／句长／冷却配额；原有不变量仍存在。静态扫描只发现疑点，不能自动判文学。
- 输入／快照：完整特征可冻结；来源漂移阻断；快照中的关系、知情、未结事项 round-trip 不丢；关系不变允许零变化。
- 阶段记忆：相关旧场景能定位；来源章修订后旧回看不被当成事实；金字塔占位不被冒称已聚合。这些消费行为用实际会话记录验收，不伪造脚本已实现。
- 恢复／发布：半章续写、换稿证据失效、缺授权不发布、revision 不回退最新状态、在途发布恢复、沙盒连续章号推进。
- 回归：其余九个 profile 的路由不变；共享 author-session／tracking 对短篇单元 1 的流程不退化；不新增默认内部模型或代理。

热路径文件执行现有文档预算，新增内容优先替换重复说明；长解释留 consult。不得为了塞本规格而调高预算，本文件本身不进入每章生成上下文。

## 8. 失败处置与结项

每轮只记录可核查的结果：差在哪段、主要假说、改了什么、得到什么、损失什么。无需输出模型私有推理过程。

- 同类调整连续两轮无净收益，停止加规则；检查材料、输入密度、输出容量、实际加载、模型可用能力与编辑方式。换模型只能在用户选择后用同条件新实验验证，不自动切换、不归咎低模型了事。
- 短稿好而整章差，先查详略和事件预算；完整章好而后章退化，先查来源、候选分支、关系经历与阶段方向。不能靠延长一倍篇幅或只保留高分稿掩盖。
- 规则更全但阅读更呆，保留更好旧稿，撤下无收益实验增量；正式版本回退另留明确差异，不覆盖用户改动或历史 input。
- 当前条件不能达到目标，就交付“用户已确认等级／待验与未达项／现有证据／后续投入选项”，不降低 Q 标尺，也不承诺下一条提示必然解决。

执行台账统一放本次实验目录，逐包记录：状态（未开始／进行中／待用户验收／本阶段通过／未达标）、实际差异、输入与产物路径及哈希、基线与加载根、模型和可控参数、已读范围、全部初稿／修订稿、工程结果、用户验收原话与日期、验收版本及范围、用户已确认的质量证据等级、下一动作和授权边界。模型审读与其他读者意见单列为参考，不混入用户验收记录；工程结果与质量状态分账，质量“本阶段通过”只能依据用户明确结论登记。

**结项必须分别报告三件事：框架改造的实际完成情况与工程结果；用户已确认的 Y/T 实写证据等级及待验项；约定作品的成稿情况与用户整体验收结论。** 最终交付是否验收通过由用户本人决定；没有用户明确认可，只能报告已完成的工作及“待用户验收”或“未达标”，不得自行宣布目标达成或验收结项。任何一项未完成，不用另外两项代替。本次交付仅为技术规格与架构支撑判断，所有 W0–W8 和 L0–L5 验证均待后续执行。
