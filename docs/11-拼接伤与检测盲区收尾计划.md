### 根因七：检测规格滞后（契约先行，验证器没跟）

v7 首次出现「机制在场但规格滞后」的失效形态，与前六轮的「机制缺失」性质不同。两条实证：

1. **契约→检测器版本差**：Y1 已拍板新章统一直引号 `"`（2026-09-02），normalize 归一已接线并实测生效（61-63 直引 96/108/124、零弯引号）——但以引号字符判定对白/叙述/引语边界的检测器，字符集仍停在 `「」／“”`。实测确认三处：`outline-deliver.js` 的 `inQuoteAt` 不认 `"`（v7 实报：术语首现判定误报）；`repetition.js` 的 `isNarrative`／`ECHO_SPLIT` 不认 `"`（对白全部误判为叙述段——台词口头禅会被当 tic 报、n-gram 跨对白边界成词）；`beat.js` 的 `stripQuoted`／`isDialogueLine`／`PSYCH_VERBS` 负向断言不认 `"`（心理独白计数的引号外判定失效）。**契约变了，验证器没跟**——08 纪律「输出形态必须进契约」的镜像缺口：契约形态变了，验证器必须同步。
2. **阈值形态盲区**：N1 复读雷达的两个报告项——`phrase-echo-cross`（跨章窗口合计 ≥3 次）／`phrase-echo-ending`（同章 ≥2 且末次落章尾 20%）——都不覆盖 A1' 的实际形态：**同章中段 ×2**（ch62「踏平的灰地」L79/L83，隔一拍逐字重复）。定性修正：v7 称「检测器对叙述行重复存在盲区（不扫叙述行）」——不准确，`isNarrative` 明明扫叙述段，短语计数也含本章次数；真正的盲区在 `scanChapterEcho` 的 **if-else 判据链**：count=2 既够不到 cross（需 3）、末次又不落章尾（够不到 ending），**数据已算出、报告无出口**——落在两项之间的缝里。检测项按历史失效形态（E6 章尾同图、E7 跨章 tic）设计，新病（beat 拼接同拍重复）是旧判据的漏网形态。

## 一、SP 系：拼接伤与复读盲区

### SP1 同章短语复读门 `phrase-echo-inline`（A1' 主治）

**问题**：A1' 形态（同章中段同短语 ×2）落在 `scanChapterEcho` 判据链的缝里——`count=2` 够不到 cross（需 ≥3）、末次不落章尾（够不到 ending），短语计数已算出但无 finding 出口。

**实现**（`scripts/guyin-check-repetition.js`，三处改动）：

1. **常量**：`const ECHO_INLINE_RUN = 2; // SP1：同章复读门（A1' 同拍重复形态）`

2. **判据链第三分支**——`scanChapterEcho` 的 if-else 链现状与改后对照：

```js
// 现状（两个出口）：
if (count + winLib >= ECHO_CROSS_RUN) {          // 跨章窗口合计 ≥3
  candidates.push({ ..., type: 'phrase-echo-cross' });
} else if (count >= ECHO_ENDING_RUN
  && 末次落章尾 20%) {                            // 同章 ≥2 且落章尾
  candidates.push({ ..., type: 'phrase-echo-ending' });
}
// SP1 追加第三分支（else-if 链保证互斥，重级优先）：
else if (count >= ECHO_INLINE_RUN) {
  candidates.push({ phrase, count, winLib, total: count + winLib, type: 'phrase-echo-inline' });
}
```

互斥关系由 else-if 链天然保证：够 cross 的不报 inline；落章尾的报 ending（形态更重）；剩余的同章 ≥2 全部落 inline。**零双报**。

1. **白名单跳过**（复用 Z7 资产，防签名物件误伤）：候选短语进入过滤区时（`echoNoisy`/`isEntityPhrase` 判定旁）加一条——

```js
// SP1 白名单：追踪/复沓锚句.md 登记的签名实体（与 ai-patterns Z7 同源同语义）。
// 候选短语含任一登记实体 → 跳过（有意复沓的仪式资产，非复读）。
if (anchorWhitelist.some((w) => phrase.includes(w))) continue;
```

白名单加载函数 `loadAnchorWhitelist()` 新增于函数区：解析 `追踪/复沓锚句.md` 表格实体列（与 ai-patterns.js Z7 的 registry 解析同型：剥表格语法、滤 `<br/>` 残渣与 `{{}}` 占位符）；无文件/空表 → 返回 `[]`（静默，fail-open）。**登记与豁免的消费闭环**：未登记短语被报后，确认有意复沓 → 登记复沓锚句.md → 永久豁免；或走五测试豁免台账；或改写卡修。**与批次公约锚句频次禁令的分工**：公约管已登记锚句的额度（全章 ≤2），SP1 管未登记短语的复读——登记过的有主，未登记的归雷达。

1. **防噪零新规则**：N1 既有三规格全部自动继承——①不跨标点边界（ECHO\_SPLIT 切段，SP2 补 `"` 后对白也不跨）；②子串归并取最长形（`merged.some((m) => m.phrase.includes(cand.phrase))` 既有逻辑）；③`echoNoisy` 虚词过滤＋`isEntityPhrase` 角色名/地名跳过＋top10 截断。**SP1 不新增任何防噪规则，只新增一个出口。**

2. **报文文案**（三型分支的第三条，格式同型）：

```
phrase-echo-inline (advisory)
「{短语}」本章出现 {count} 次（非章尾形态）——同拍重复疑似 beat 拼接伤或新 tic；
处置：确认有意复沓→登记 追踪/复沓锚句.md（签名资产）或豁免台账；否则改写卡删一处/换形。
```

1. **USAGE 头部**同步加 `phrase-echo-inline` 判据说明（三行以内）。

**存储不动**：phrases 节 `--commit` 沉淀逻辑零改动（「窗口复现 ≥2」既有门槛已覆盖 inline 形态的数据）。

### SP3 口吃标点模式 `stutter-punct`（B2'）

**问题**：「这：这」——中文冒号误作口吃分隔，正确形态「这……这」。低模型批量生成的复发性错字（B2' 实证在对白内：「客官，这：这是正经路数来的」）。

**实现**（`scripts/guyin-check-ai-patterns.js`，两处改动）：

1. **新函数** **`findStutterPunct(fullPath, input)`**（置于 `findPhraseQuota` 与 `findSensoryRepeatTic` 同级函数区）：

```js
// SP3 口吃标点（docs/11 §一 SP3）：同一汉字 + 冒号（全角/半角）+ 同字——
// 「这：这」应为「这……这」。确定性错字：正常中文「X：X」近零出现（冒号后接同字
// 的口吃是唯一高频形态）。扫描全文（对白内外都扫——B2' 实证在对白内）。
const STUTTER_RE = /([\u4e00-\u9fa5])[：:]\1/g;
```

逐 match 生成 advisory finding（出现即报，非密度型——确定性错字不做阈值）。

1. **主循环接线**（与 Z7 同型一行）：

```js
findings.push(...findStutterPunct(fullPath, input).map((finding) => ({ file, ...finding })));
```

1. **报文文案**：

```
stutter-punct (advisory)
「{字}：{字}」同字夹冒号——口吃/重复应作「{字}……{字}」；确定性错字，改写卡直接修。
```

**为何只收这一种形态不扩标点族**：单发低频的错字形态（顿号误用/逗号粘连等）走 lint 与 review 即可，为偶发微瑕扩检测器是过度工程；「同字夹冒号」是唯一「复发性＋确定性极高＋零误报」三者兼备的形态（§六不做清单登记）。

**测试 fixtures**（+2）：

| ------ | -------------------------------------- | ------------------------------- |
| SP3-正例 | `"客官，这：这是正经路数来的"`                      | 报 `stutter-punct`，excerpt=`这：这` |
| SP3-反例 | `他心里只有一个念头：这事没完。`（冒号后接「这」但前字是「头」——非同字） | 零报                              |

### PV1 批次公约模板加「视角规格」行（B1' 声明位）

```markdown
- 视角规格：POV={人物名}（第三有限）；对手/配角内心禁直写，每章 ≤1 处且须外部可见锚（动作/表情先行）；值「全知」或「多视角」时本行检测静默
```

**双通道传导**（零热路径增字的设计关键）：

1. **检测源通道**：PV2 直接读公约此行（章检层）——不经过写作卡；
2. **执行层通道**：编排层组卡时把 POV 约束翻译进既有 `{{禁止}}` 段（占 ≤3 条名额，如「禁直写燕衡外任何人的内心，对手心理一律外部可见动作」）——Z5 感知模式的「核心 2 条进禁止段」同型通道，**不新增卡字段、不动 cards/README 取数表**。写作卡规格行 30 字名额不强制加 POV（引号＋比喻域已是 15 字上下，POV 走禁止段更稳）。

**存量项目衔接**：白银案录下一批建批/补纲时补 `POV=燕衡`（建批硬前置既有流程自然覆盖，同 Z5 感知模式区的补建路径）。

### PV2 `pov-drift` 检测（B1' 消费端）

**问题**：B1' 实证形态是「代词回指的对手内心」（「他忽然拿不准眼前这位」「他备好了一肚子的话」——「他」指书办非 POV 燕衡）。纯显式人名判据抓不到，纯语义判断不可机械——方案取**两档判据**：显式人名形态（机械稳）＋一跳代词回指（启发式，advisory 容错）。

**实现**（`scripts/guyin-check-ai-patterns.js`，三处改动）：

1. **POV 解析**（fail-open 三静默态）：

```js
// PV2：读 大纲/批次公约.md 视角规格行。无该行／值「全知」／「多视角」→ 静默
// （多视角书不受此检，同 consistency 对 _tracking-state 的 fail-open 约定）。
const m = /视角规格[：:]\s*POV=([^\s（(，；;]+)/.exec(pact);
if (!m || m[1] === '全知' || m[1] === '多视角') return [];
const pov = m[1];
```

1. **扫描算法**（逐句状态机，`stripQuoted` 剥对白后只扫叙述层——依赖 SP2 的 `"` 迁移先行，实施顺序见 §七）：

```
prevSubject = null  // 上一叙述句的显式主语人名（一跳回指锚）
for 句 of 按句切分(叙述层文本):        // 。！？\n 切句
  names = 句内显式人名（_tracking-state.json characters 全员名表匹配）
  if names 非空: prevSubject = names 最后一个
  for 每处心理动词命中:
    主语 = names 含非 POV 人名 ? 该人名
         : (句首为「他/她」且 prevSubject 非 null 且 ≠ POV) ? prevSubject   // 一跳回指
         : 跳过（POV 人物合法/无法判定——宁漏不拦错）
    if 主语 ≠ POV: driftCount += 1
```

**心理动词词表**（与 beat.js `PSYCH_VERBS` 同源＋B1' 实证补收）：

```js
const POV_PSYCH_RE = /拿不准|纳闷|琢磨|寻思|暗想|思忖|盘算|心里(叫苦|发慌|打鼓|没底|叫苦)|暗自|犯嘀咕|打定了?主意|备好了?|心道|暗忖|心想|觉得/g;
```

（beat.js 词表的「知道/明白/清楚/疑惑」不搬——太泛，叙述层正常使用率高；PV2 词表收窄到「内心活动标记」高置信形态＋B1' 实证三词「拿不准/备好/打定主意」。）

**弱信号补充**（自由间接引语标记，B1' L37 形态）：`/[他她][^。！？]{0,6}哪(是|要的是)/`——「他要的哪是引，是要个凭据」。命中计入 driftCount。此形态无心理动词也能抓到 L37，三处实证覆盖 2.5/3。

1. **阈值与报文**：`driftCount >= 2` → advisory（**1 处静默**——v7 判「书办心理是喜剧拍，部分成立」，给合理技巧留空间；B1' 实证三处即报）：

```
pov-drift (advisory)
对手/配角内心直写 {N} 处（POV={POV}）：{逐处句位+首 10 字}——第三有限视角越界。
处置：喜剧拍/合谋拍有意为之→豁免台账（五测试）；否则改外部可见动作（表情/小动作/语气）。
机械判据覆盖显式人名与一跳回指形态；自由间接引语的深层形态归走查/review。
```

1. **主循环接线**（同 SP3 一行）：`findings.push(...findPovDrift(fullPath, input)...)`。

**与 Z3 的关系**：Z3 角色卡「自我叙事」字段是认知落差的**设计**载体（编排层用）；PV2 是视角纪律的**执行**检测（章检层用）——设计层鼓励写对手的坚信，执行层拦直写对手的内心，两者正交：自我认知差要靠外部可见证据累积落差，恰恰不该直写内心。
