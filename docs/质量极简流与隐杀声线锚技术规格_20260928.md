# 质量极简流与隐杀声线锚技术规格

> 日期：2026-09-28｜状态：生效规格（写作流与发布链部分）。
> 与此前规格（作品级创作架构/落地审计/执行复核三份 20260923–24 文件、01–12 整改计划）冲突处，**以本文为准**；历史文件保留留痕，不删不改。
> 本文只动两件事：**写作流程**与**声线来源**。目标只有一个：让模型写出来的章节本身好读。
> 触发背景：破隐《熄锋》第 1 章在 C2 框架（815/0/0 全绿）下产出 ready 稿，用户直读判定僵硬、与《隐杀》差距大；且因隔离/发布机制，"写完正文"文件不在正文目录。

## 1. 结论（先回答两个问题）

### 1.1 P0 工程整改是否必要、是否影响质量？

**怀疑成立。绝大多数工程项与文章质量无关，应删除而非修复。**

五轮 Y 实验＋G2＋破隐首章给出的事实是：工程门全绿（815 pass、overall=pass、字数达标、零泄漏）与"稿子好不好看"零相关。破隐首章带着全套 pass 证据产出，主病（替剧情办事、叙述者缺席、关系真空、碎镜头）与 Y01 完全相同。工程体系的真实作用有三个，没有一个是提升质量：

1. **制造虚假信心**：检查链与自检 review 给僵硬稿发放通行证；
2. **消耗唯一一轮修订**：v0001→v0003 的两轮修订全部用于消警（破折号 8→3、复读删六处、补道具街景），没有一轮针对阅读感受；
3. **反向损坏内容**：semantic 锁门与伏笔编号门互斥，逼执行者撤锁、丢掉 F001–F003 三条首章伏笔。

因此本规格对工程项的处置原则是：**机器能把复杂机器拆掉，就不去修复杂机器**。具体分三类：

| 类别 | 处置 | 项目 |
|---|---|---|
| 对质量有害 | **删** | 风格类 lint（碎化率/破折号密度/复读计数/情绪平直定罪）；检查链 gate；自检盖章式 review；正文直写物理拦截；模型句当 exact 锁 |
| 零质量价值 | **删** | 发布状态机、事务 JSON、候选隔离 run 目录、三种授权分层、hash12 版本锚、待审/豁免八列台账、trial-gate、模板 CI、缺陷台账、版本号治理 |
| 对长篇有用 | **留，但减重为 markdown** | 写前读前文、上下文/伏笔/角色状态的连续记忆；"规则变更须经盲写对照"这一条纪律 |

仅存的两个真 bug（semantic 锁互斥、伏笔编号正则互斥）**不修了——它们依附的门整体拆除，bug 随机器消失**。

### 1.2 能不能直接用《隐杀》原文作为默认声线？

**能，而且这是五轮实验数据指向的唯一正确答案。**

项目自己的证据链：

- Y05：编辑手持原文逐句校准 → 用户判"很接近了"（非盲写，不计能力证明，但证明方向）；
- Y04：生成侧可见锚章研究的 C1 甲稿 → 用户判"比乙自然、像小说"，为五轮最佳盲写；
- 破隐 ch1：抽掉原文、只留一段抽象 profile（末尾自标"非作家风格复刻"）→ 僵硬，主病复发。

模型是模式机器：**示范 > 规则**。旧框架的做法等于把名画收走、给学生发一张"色彩理论要点"然后要求画出名画水平——profile 里"叙述者促狭的落差幽默"一句话，永远不如让写作者亲眼看一遍"他认为这比杀人难"。

用户提出的"先能写出这个级别，才有创作资格"，按写作训练传统就是正路：**临摹 → 对帖 → 出帖**。先求近，再求出；书自己的声线以用户认可的本书章节为准，逐步接管。

诚实边界：声线锚抬高的是方向与下限，不保证模型上限。若多轮对照仍差距明显，按旧规格 §8 归因到模型能力/写作方式（Y05 已验证"写完持锚再改"的两段法有效，本规格将其固化进流程），不靠继续加规则掩盖。

## 2. 质量第一性原理（全部规则只保留这六条）

以下六条从 W1 锚章研究与 Y01–Y05 反馈中提炼，是声线锚之外唯一允许存在的"写作知识"。不做成检查脚本，只作为写前自读与持锚自审的内容。

1. **先给人，再给事。** 读者先愿意跟这个人相处，才愿意看他办事。开书允许大段无事件日常（吃饭、当差、闲笔），日常本身就是回报，不兑换成剧情收益。
2. **事件服务于人的选择，不是资产清单。** 一章里主角做的每件事必须是"他此刻想做/不得不做"，不允许为了交付台账（人头、地名、物证、伏笔）而行动。判断标志：删掉这场，人物有没有损失；只有台账损失的场，删。
3. **叙述者必须在场。** 允许并鼓励促狭、调侃、自由间接体、跨时代设喻；场景内物件与常识合时代，叙述者的舌头不封年代。注意：在场≠每章搞笑——高压/阴冷章的在场是判断与口吻，闹剧章才是包袱；全章完全听不到叙述者声音才是事故稿。
4. **心理直接写，不用身体短拍顶替。** 私人的怕、得意、自嘲、牵挂、委屈可以直接展开成句，句长随体验起伏。禁止通篇 ≤15 字镜头切碎。
5. **配角各带算盘，关系有摩擦。** 配角不为成就主角存在；主角的能力不向读者汇报式展示，胜绩主动去认证（行家看得出、俗眼看错、主角配合误读）。
6. **结尾不收判词。** 允许落在动作、半句对白、一个物件、一句玩笑上。模型自创的"点题宣言句"没有资格当锚句锁。

## 3. 隐杀声线锚协议

### 3.1 锚包构成

从用户合法持有的 `linkbook/隐杀 (愤怒的香蕉) (Z-Library).mobi`（sha256 前缀 `9c74d8a2`）提取 **4–6 段原文**，覆盖本书前几章实际会遇到的全部场景类型：

| # | 取材 | 学什么 |
|---|---|---|
| 1 | 楔子/第一节《回到过去》 | 重生开篇的进入方式、日常先于履历、孩子身体与成年灵魂的温差 |
| 2 | 第二节《家明与灵静》 | 共同生活、关系错位（护他也管他）、无事件停留的合法密度 |
| 3 | 第三节《柳怀沙》 | 误认而不纠正、主角不被当场认证、雪地里孩子世界的自有规则 |
| 4 | 第四节《踢馆》 | 概述带段子、书内梗复用、人带算盘、反表演动作、胜绩去认证、生活结构收尾 |
| 5 | 中后期任选一段日常群戏（备选：第187节《蹩脚组合》，已封存于 `arena/.../sealed/q1-yinsha/anchor.md`） | 长段滚动叙述、促狭腹诽、多人物调度 |

每段附一行标签（这段供什么场景调用），不写分析长文——分析在 W1/R-y05 已做过，锚包只放原文。

### 3.2 使用方式（每章）

1. **写前**：首章通读锚包全部；其后各章只读与本章场景同型的 1–2 段，加上本书已被用户认可的最近一章全文。
2. **写时**：直接写。锚包学的是节奏、气口、叙述距离、心理密度、对白处理，**不是剧情**。
3. **写后持锚自审**：稿子与锚段并排复读一遍，只问四个声音问题——
   - 叙述者在不在？（有没有一句非他不可的说法）
   - 有没有大段镜头在替心理？
   - 人物是在选自己的事，还是在替剧情交差？
   - 有没有道具排队陈列、配角排队等场？
   
   至多一轮修订，原地改。改完即终稿。

### 3.3 边界（防止学偏与侵权）

- **只迁移声音，不迁移内容**：人物、姓名、世界观、情节序列、标志性桥段全部全新；
- **不整句搬移，不连续复用原文独特词组**；时代物件与常识以本书 1999 年为准（锚书为 1992 年前后，物件差异写前自查）；
- **锚段供声音机制（节奏、心理密度、去认证、叙述距离），不供情绪基调**：踢馆是闹剧温度，阴沉章/高压章只学其"叙述者在场"的方式，不照搬包袱密度；当章基调以本书细纲与处境为准；
- 锚包为**用户合法持书的私人临摹用途**：存仓库外本地目录（建议 `D:/readbook-workspace/声线锚/隐杀/`），不入 git、不分发、不随产物传播；首章只需前三节＋踢馆共 4 段即可起步，不必一次凑齐；
- 验收口径＝**阅读质感**（愿意继续读、记住了谁、有句子想划下来），不是字面相似度；终判只在用户。
- 书一旦积累出用户认可的本书章节（≥3 章），锚包降级为"声音漂移时回炉"用，日常声线以本书自己的正文为准——这就是"出帖"。

## 4. 极简写作流（唯一生效流程）

```
读 → 直接写正文 → 持锚自审改一轮 → 顺手记 markdown 账 → 交用户
```

1. **读**（一次，不全库扫描）：上一章全文（首章换锚包）＋`追踪/上下文.md`＋本章相关角色卡＋细纲（若有；细纲是设想不是考卷）。
2. **写**：**直接写入 `正文/第NNN章_标题.md`**。写完即是正文，无候选区、无草稿版本号、无发布动作。
3. **自审**：按 §3.2 四问持锚复读，至多一轮，原地修改。
4. **记账**（一分钟，markdown，给下一章的自己看）：更新 `追踪/上下文.md`（位置＋一句话本章＋承诺）、`追踪/伏笔.md`、`追踪/角色状态/`中受影响角色。其余台账（场景/地理/物证/金字塔/复沓句）想记才记，不记不拦。
5. **交用户**：用户是唯一验收者。要改就原地改、要重写就原地重写；没有"发布授权"这一步。前三章完成后停一次，听整体感受，但这不是机械门。

修订旧章同样直接改 `正文/` 文件；改完顺手核对受影响的后续设定与伏笔，靠阅读不靠 hash。

## 6. 框架变更的唯一验收门

工程 CI 以后只允许测纯工程事项（文件存在、部署成功），**测试输出与文档中禁止再出现任何文学性背书措辞**（"质量通过""创作就绪"类）。

任何改动写作规则或热路径文档的变更，验收只走一种方式：

1. 同一 brief 出两稿（旧条件/新条件各一），生成者不看对方稿；
2. 匿名随机序交用户直读，用户给真实感受（哪里想停、记住谁、愿不愿继续）；
3. 无用户反馈不得合入。模型审读永不顶替。

这条是 G3 用破隐首章的代价换来的唯一硬教训：**未盲验不合入**。

## 7. 破隐（练手书）处置

1. 首章不发布、不补丁：`ch001-v2` 候选整体作废归档；按新流程在 `正文/第001章_报时.md` **重写**（病在细纲设想层，改措辞无收益）。
2. 重写前做两处降压：细纲第 1 章事件拍减半（码头侦察保留一条主线，其余留白），补一场真正的关系戏（与母亲/邻里/许知夏之一，配角带自己的事）；删除模型自创锚句锁，章尾允许不写那句话。
3. 先建锚包（§3.1）再动笔。
4. 重写稿直接落 `正文/`，用户对照锚段直读验收。
