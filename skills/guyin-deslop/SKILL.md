# guyin-deslop：隐笔去AI味（隔离修订，不碰正式稿）

> AI 味的最终定义是"装"——过度圆滑、工整、解释充分；改味不改错。

## 前置：先有隔离 revision 候选

去味走 guyin-write/short-write 的 **revision run**：现稿复制进 `R/drafts/v0001.md`（revision，目标/硬锁不变），改写只在 drafts 新版本。「去味」＝授权改候选，**不等于授权覆盖正式正文**；正式稿只由 `tracking-commit.py publish` 凭独立发布授权安装。**不默认多加一轮**：至多一轮有假说的实质修订，净收益不足留较好初稿。

## 原则

1. **改味不是改错**；**改最少**：能改词不改句、能删句不重写段，人名/地名/数字/专名优先保留。
2. **只改怎么说，不改说什么**：剧情、人设、走向、逻辑不动。
3. **保留有功能的语气**：质问的「？」、峰值「！」保留；犹豫/打断用动作、短句、换行——功能正常的 `……/——` 逐字保留。
4. 不整段删；删前确认不含伏笔/钩子/角色特征/因果；删除上限 15%/25%/35%（轻/中/重），拿不准标 `[需复核]`。

## 两步流程（都对候选，不对正式稿）

### 第一步：lint（脚本只读不改盘）

```
node <guyin-write路径>/scripts/guyin-check-ai-patterns.js R/drafts/vNNNN.md
node <guyin-write路径>/scripts/guyin-normalize-punctuation.js R/drafts/vNNNN.md   # 默认逐字只读
```

ai-patterns 报警＝**待审清单**，永不自动删改；停顿/打断是 editorial，功能标点保留。仅独立分隔线、用户明确的引号规格可用 `normalize --write`（只收 drafts 候选、另存 vNNNN+1，旧版与正式正文原位不动）；风格报警进第二步。候选一改旧证据立即失效（换稿分支）。

### 第二步：陌生化改写（段落级，人在候选上手改）

按 [../guyin-write/cards/改写卡.md](../guyin-write/cards/改写卡.md) 组卡定向，改完存新版本：

| 问题 | 方向 |
|---------|---------|
| 失真/成套话 | 命名无信息才补事件支撑 |
| 公共比喻 | 人物之眼：焦点物→角色行当（读 `设定/角色/`）→ 行当经验重写 |
| 重复信息 | 合并或删其一 |
| 对话公式 | 标签降频：动作引对话，普通"说"可留 |
| 段落均匀 | 按 beat 功能调长短 |
| 视角越界 | 外部可见锚先行 |
| 解释充分 | 删解释留行为 |

## 收尾：重检 → 授权 → publish

最终候选**重跑完整候选检查链**（candidate-context 汇总，证据绑新哈希）：hard/verify 逐条合法终态，editorial 留审读记录。复读改动区与承接，具体问题已消即可，**不以报警计数验收**（零报警=过度打磨），不承诺检测分数。拿到用户对**该稿哈希**的发布授权才 publish；未授权停 ready，正式正文一字不动。结构性生硬（>50% 段报警）走 L3 章改。
