# guyin-deslop：隐笔去AI味

> 斋：删掉一切毁真之物。AI 味的最终定义是"装"——过度圆滑、工整、解释充分；改味不改错。

## 四原则（承自上游，逐条有效）

1. **改味优先，别当改错**：AI 味是风格问题，不是语法错误，不存在"修正"。
2. **改最少，效果最大**：能改一个词不改一句，能删一句不重写一段；人名/地名/数字/专有名词优先保留。
3. **只改怎么说，不改说什么**：剧情、人设、走向、逻辑一概不动；原文逻辑问题不是本 skill 的活。
4. **保留有功能的语气**：质问的「？」、爆发峰值的少量「！」保留；犹豫/打断用动作、短句、换行处理。

**删除保护**：不得整段删；删前确认不含伏笔/钩子/角色特征/因果锚点；删除上限轻度 ≤15%、中度 ≤25%、重度 ≤35%；拿不准标 `[需复核]` 不删。

## 两步流程

### 第一步：lint（确定性，脚本）

```
node <guyin-write路径>/scripts/guyin-check-ai-patterns.js <正文文件>
node <guyin-write路径>/scripts/guyin-normalize-punctuation.js <正文文件>
```

- ai-patterns 报警 = **待审清单**，永不自动删改（例外：标点规范化允许自动修）；
- 报警逐条分诊：确定性错误（标点/碎句/重复词）→ 修；风格性报警 → 进第二步。

### 第二步：陌生化改写（段落级，走改写卡）

对 lint 定位的问题段，按 [../guyin-write/cards/改写卡.md](../guyin-write/cards/改写卡.md) 组卡定向改写：

| 问题类型 | 改写方向 |
|---------|---------|
| 失真（命名与场景事实脱节、成套话无信息增量） | 命名可保留可补事件支撑——只有命名无信息时才改，不强制外化（v3-B1） |
| 公共比喻（"如潮水般/仿佛静止/像刀子一样"） | 人物之眼三步：焦点物→角色行当（读 `设定/角色/`）→ 用该行当经验重写 |
| 重复（同一信息出现两次） | 合并或删其一：对话同信息未推进、复读短语 |
| 对话公式（每句带"说道/问道/笑道"） | 标签降频：动作/上下文引出对话，普通"说"可保留 |
| 段落均匀（通篇同长度） | 按 beat 功能调长短——均匀本身是问题，取向对照题材定位与场景功能，不是「爽点必须短」 |
| 视角越界（POV 外内心直写） | 回到视角规格：外部可见锚（动作/表情）先行 |
| 解释充分（说明替代了必要戏剧） | 删解释留行为：动机让读者从动作里读出 |

每类改写卡附**一对好坏对照例**（exemplars 取或现场构造）。

## 铁律

- **只改具体问题（v3-B1）**：去味只在重复、失真、视角越界、说明替代戏剧等具体问题上改；心理、情绪命名、解释本身不是改写理由。书级明确写法（题材定位/作者性）不越过——不擅自改用户个性；
- **宁留三分糙，不磨十分滑**：语法松但语感活的句子明确保护——打磨本身就是 AI 味来源；
- 改后**重读改动段**：所报具体问题已消除、未引入新问题即可；**不以报警计数升降验收**（零报警=过度打磨）；
- 不承诺任何检测分数；外部检测分只作 Arena 参考曲线，不作主判据；
- 大面积工整（>50% 段落报警）时建议走 guyin-write 的 L3 章改（重新切 beat），逐段修补救不了结构性生硬。
