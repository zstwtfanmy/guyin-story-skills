# guyin-deslop：隐笔去AI味（原地改，改味不改错）

> AI 味的最终定义是"装"——过度圆滑、工整，把没发生的感受和没把握的判断写成流水线成品；改味不改错。**"解释充分"本身不是问题**：必要因果、背景、想法该讲就讲，只删重复的、夺走体验的解释。

## 原则

1. **改味不是改错**；**改最少**：能改词不改句、能删句不重写段，人名/地名/数字/专名优先保留。
2. **只改怎么说，不改说什么**：剧情、人设、走向、逻辑不动。
3. **保留有功能的语气**：质问「？」、峰值「！」保留；功能正常的 `……/——` 逐字保留。
4. 不整段删；删前确认不含伏笔/钩子/角色特征/因果；拿不准标 `[需复核]` 交用户。

## 两步流程（原地改，无候选区、无重检门）

### 第一步：复读找味

按阅读顺序完整读一遍目标章，标记：

- 公共比喻（"像一只受惊的兔子"类，谁都会这么写）；
- 成套话、流水线形容词（"深邃的目光""修长的身影"类）；
- 重复信息（同一件事讲两遍）；
- 对话公式（"他说道""她问道"成串）；
- 段落均匀（每段一样长，读不出呼吸）；
- 视角越界（按本书锁定 POV：第三有限落回可见可闻）；
- 解释过头（提前把体验讲完，不给读者留）。

不跑任何 lint 脚本、不计数、不按报警比例定罪——AI 味是读出来的，不是数出来的。

### 第二步：陌生化改写（段落级手改）

| 问题 | 方向 |
|---------|---------|
| 失真/成套话 | 命名无信息才补事件支撑 |
| 公共比喻 | 人物之眼：焦点物→角色行当（读 `设定/角色/`）→ 行当经验重写 |
| 重复信息 | 合并或删其一 |
| 对话公式 | 标签降频：动作引对话，普通"说"可留 |
| 段落均匀 | 按功能调长短 |
| 视角越界 | 落回可见可闻；不擅自给全书改视角 |
| 解释过头 | 只删重复解释与夺走体验的提前说明；必要因果、背景和人物想法保留 |

## 收尾

改完原地存稿（就改 `正文/` 里这一章），自己复读一遍改动区与前后承接，没问题即终稿，交用户。至多一轮——净收益不足就留较好初稿，宁留三分糙，不磨十分滑。用户读着还嫌 AI 味就再定点，不自动进入新一轮。
