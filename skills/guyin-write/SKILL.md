# guyin-write：隐笔写作（你是编排层）

你负责取材组简报、维护状态、判定与验收。有执行层 subagent 时**正文由执行层按场景简报（写作卡）连续写**，组装规则见 [cards/README.md](cards/README.md)；solo 直写，卡为**可选脚手架**（Fw-08：卡形态不增追读拉力），闸门不豁免。方法论按需查 [references/consult/INDEX.md](references/consult/INDEX.md)（永不下发）。

## 不变式（先于一切流程）

1. 对话要么推进事件，要么揭示人物；两者都不占的对话删掉。
2. 执行层永不见全局，只见当前场景简报（一卡一场，承载得住一卡整章）。
3. 每步产出落盘，下一步读盘——不依赖对话记忆。
4. 检查脚本报的问题**永不自动删**，一律拦为待审——**hard/verify 逐条登 `追踪/待审台账.md`（U1；editorial 留审读记录），终态严格五选一＋证据（修复=版本+复检/豁免=豁免台账/契约修订=偏差/顺延=伏笔+章号/不适用=位置+理由）；「升级作者」=等待态须用户转结；旧版本行只记录，当前版本未决即阻塞**。
5. 宁留三分糙，不磨十分滑；lint 只清确定性错误。
6. **契约改动二分**：补缺（无样本可做）／**提分**（必须引正文样本：章号＋原文证据＋试读或检测数据）；纸面结论不得推翻样本证据，A/B 负结果照单认，不许重测到好看（Fw-08）。

**停靠纪律**：裸调用（/guyin-write 无意图）只做项目状态诊断并列出选项；开书默认停在细纲，正文必须由用户显式点名。匹配优先级：大修 → 写指定章 → 补纲 → 日更 → 完书 → 结构手术/人物诊断/读者信号 → 开书。

**落盘硬门**：① 细纲落盘前依次跑 `scripts/guyin-check-outline-slots.js`（四组齐备+保留行，字段权威=细纲协议）、`guyin-check-authority-leak.js`（作者性字面，含复沓锚句字段——锚句洗白在此抓）、`guyin-check-outline-verdict.js`——引用既往章/事件必须有「资产影响档位」声明，档位冲突即停作者仲裁；**ch001-003 加跑 `guyin-check-opening-retention.js`（开篇入口声明：第一组「读者承诺」行非空且非空话，Fw-01）**；② 拼章后落盘前跑 `guyin-check-integrity.js`，不过回执行层重拼；③ S 级修复禁止会话裸改正文，唯一通道 = 大修候选 + publish revision 正式化（D2）。（`guyin-check-hook-rotation.js` 仅旧格式存量细纲用。）

## 写章循环（每章必走）

1. **读盘**：本章细纲 + 上一章结尾 300 字（声线锚）+ 涉角色卡 + 追踪状态 + 作者性四件（选切片定禁令，精神件禁字面 H1）+ `大纲/批次公约.md`（B1 取数源；缺→补纲场景补建后再写）+ `设定/题材定位.md`「读者契约/终局底牌」（v3-A3：第一组读者承诺的对照源，缺件先补 A）。四件为默认档/未定稿：照常写，附升级提示（同章一次）。
2. **组简报**：按细纲四组组装场景简报[写作卡](cards/写作卡.md)——三类权限（不可擅改/这一场/必要材料），一卡一场、承载得住一卡整章；取数与组装纪律见 cards/README.md。缺因果前情先补取材（角色状态/承诺/相关原文），不把全书和检查词表塞给写手；上一段 100/300 字只是声线锚，不替代因果。
3. **连续执笔**：执行层按简报连续写完整场/整章（beat 只是节奏标签，不再逐 beat 拆卡/字数桶/逐拍验收）；solo 同权限直写（新题材首章/卡壳再借卡，Fw-08）→ 收正文（「材料不足」控制结果→补材料重发，不伪装正文）→ 跑 `guyin-check-beat.js`（确定性预检，零 token，**任何执笔路径不豁免**）→ hard/verify 不过直接[改写卡](cards/改写卡.md) → 过则进下一场。输出上限不足按场景自然边界拆（档位见 `作者性/粒度配置.md`）。
4. **拼接**：按序拼章，检查场景衔接；过硬门②＋落盘前过 `guyin-check-strip.js`（成稿剥离门 K3）；对本章新文件跑 `guyin-normalize-punctuation.js`（Y1 按批次公约引号规格定向，零存量写入）。产物只落隔离工作区 `.guyin/work/{run_id}/`（候选 candidate.md＋事务/证据；D2，不直接写正式正文；安装唯一通道=第 7 步 publish，废弃候选零污染）。
4a. **完整章审读（摘要与追踪提交前）**：拼章落盘后编排层**完整读一遍本章**——不得用摘要、多票投票或脚本信号替代；无法完成全文审读时在章记录标「本章审读未验收」，不伪装已读。两段式：**先初读**（只读正文：读者获得什么、记住谁、想不想往下看；审读辅助卡=[自检卡](cards/自检卡.md)——三步证据与 L1/L2/L3/工程路由），**再对照细纲**（防把「想写」误当「已写到」）：因果与收益兑现、人物是否仅配合剧情、重复铺垫有无新作用、读者为何继续。报告**引用前后句**；问题按路由进改写卡（L1 段改/L2 场景重写/L3 回设计）或登待审台账（拿不准），修复后重读改动区；涉及结构或跨场承接重读整章；**主要阅读失败未处置不标合格；用户明示保留失败稿→记录「用户保留，质量未通过」，不改写成质量认证**。审读全文与路由结论落 `追踪/运行记录/第NNN章.md`（D1：重提交不覆盖）。
5. **摘要**：组[摘要卡](cards/摘要卡.md)→checker 填空→`delta.result` 章摘要（≤900 UTF-8 字节，与近章速记同额；超限删引文冗余不删事实——D1）。
6. **章检（发布前·对工作区候选）**：首跑 `guyin-tracking-commit.py check`（时滞预检，V2）→ 依次跑 `guyin-check-strip.js`（成稿剥离门，K3）、`guyin-check-degeneration.js`、`guyin-check-integrity.js`、`guyin-check-ai-patterns.js`、`guyin-check-narrative-asset.js`、`guyin-check-consistency.js`、`guyin-check-outline-copy.js`、`guyin-check-outline-deliver.js`（S3+S4/R1：锚句落地/术语兑现/跨章签名句归属——偏差二选一：改写卡对齐契约或登记细纲执行偏差区）、`guyin-check-authority-leak.js`（作者性字面，兼拦声线锚复读）、`guyin-check-wordcount.js`（J1 双口径下限，缺省 3000；缺则修设计勿注水）、`guyin-check-rule-conflict.js`（editorial，Fw-04，判据见脚本 USAGE）、`guyin-check-foreshadow-id.js`（verify，Fw-09 C2：伏笔重号/空号/正文与大纲引用未登记）；报警按 handling 处置（契约 §2.4）——hard/verify 登台账（U1）、editorial 留审读记录；终态五选一＋证据回填（升级作者=等待态，D3）。修复改候选重跑、证据重绑候选 hash12；台账当前版本未决不清零，不进第 7 步。
7. **正式发布（publish 唯一通道，D2）**：组清单（state hash12＋`正文/` 成员基线、内容含候选 hash12 的审读/检查证据、第 5 步事务——实体当章登/锚句原句、expected revision 取当前值）→ `scripts/guyin-tracking-commit.py publish --project <书根> --input <清单>`：prepared 全检（revision 自动留发布前存档）后机械串行 安装正文→追踪事务→指纹（持锁调 node `--commit --under-lock`）→终验，正文/摘要/追踪/指纹同版。**exit 3=中断：只跑 `… recover --project <书根>`**（绑定同 run 续跑；不重章、只补指纹、坏库隔离重放＋复检不冒充通过、超基线外部变化停用户裁决禁回滚）；exit 2=违约按报注重建清单，不手改正文/状态。日更/大修/去味共用，不再手工「原子双命令」。
8. **灵感登记**：正文里长出的细纲外新元素（道具/习惯/闲笔）登 `追踪/灵感台账.md`，下批细纲时决定转正。

**卷末附加**：卷末章提交后提醒**口述重说气句**（非抄旧，标当前档位），刷新气卡，旧句入魂档案；核对豁免台账与消化度；气卡默认档、一生之问/私人切口未定稿或延期到期者**主动询问**，二选一落字（补/再延期至某卷末），不得静默滚入下一卷（Fw-09 C3）。

## 执行层调用协议（solo 与 subagent 同权限，任务书 §2.2）

- 写作 subagent：`guyin-beat-writer`（定义见 [agents/guyin-beat-writer.md](agents/guyin-beat-writer.md)）——按三类权限连续写场景；
- 检查 subagent：`guyin-checker`（定义见 [agents/guyin-checker.md](agents/guyin-checker.md)）——审读（只给正文＋必要前文＋读者定位，不给细纲/设计解释/自评）/分诊（单次判断带证据）/摘要（原文锚点）；
- 无 subagent 环境（或 Codex 报 unknown agent_type、model 占位）降级 **solo**：主会话扮演执行层，声明「solo 执行，声线节奏由编排层兜底」，守三条（Fw-08）：**①允许读细纲直写，卡可选**（新题材首章/卡壳才借卡），省卡不省闸门（check-beat＋完整章审读＋章检链照跑）；**②笔法文件只取规格行进工作记忆**，不照抄整篇；**③追踪提交后在 `追踪/运行记录/第NNN章.md` 追加：模式=solo｜原因｜兜底项**（D1：重提交不覆盖，脚本只重写 逐章记录/）；分诊/摘要卡卡头加「保持确定，不要发挥」（审读卡不加——初读要诚实，可答没感觉）；
- **调用留痕（T12）**：宿主、实际调用方式、模型与可见参数**分开记录**（写进运行记录）；不可见写「未知」，不以提示词「高温/零温」冒充实际参数；
- **默认单稿**：不默认峰值多抽、五感入口、固定丢弃前两项和逐 beat 语义问答（已废除）；增加候选必须先与用户约定数量与成本。已约定的多候选外选判词见 cards/README.md 纪律 6（证据制：机械筛＋三问引证，允许平局/都差）。
