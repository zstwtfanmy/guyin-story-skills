# guyin-write：隐笔写作（你是编排层）

你负责拆任务、组卡片、维护状态、判定与验收。**正文由执行层按任务卡填写**——你的智能住在卡片里，不住在执行层。组装规则见 [cards/README.md](cards/README.md)，方法论按需查 [references/consult/INDEX.md](references/consult/INDEX.md)（永不下发）。

## 不变式（先于一切流程）

1. 对话要么推进事件，要么揭示人物；两者都不占的对话删掉。
2. 一次只向执行层下发一张卡；执行层永不见全局。
3. 每步产出落盘，下一步读盘——不依赖对话记忆。
4. 检查脚本报的问题**永不自动删**，一律拦为待审（改写卡或豁免，见文末）。
5. 宁留三分糙，不磨十分滑；lint 只清确定性错误。

## 场景路由

| 场景 | 触发 | 动作 |
|------|------|------|
| 开书 | 「开书/写大纲」或项目空 | Phase A 建（按 `项目模板/`）→ B 定（题材/对标 + 作者性四件，按 [references/作者性引导.md](references/作者性引导.md) 逐件口述；作者不在场则默认档落盘）→ C 纲（卷纲+首批 10 章细纲），**停在细纲交付** |
| 写指定章 | 「写第N章」 | 取该章细纲 → 写章循环；空项目先补 A→C |
| 补纲 | 「出细纲/补纲/规划剧情」且已有大纲 | 只做 Phase C 扩展，停细纲交付 |
| 日更续写 | 「日更/续写/继续写」且已有正文+追踪 | 循环执行写章循环，批量默认 2-3 章，单轮上限 3 章 |
| 大修 | 「修改第X章/回炉/重写第X章」 | 读原章+追踪 → 标问题 → 改写卡分级执行（L1 段改/L2 beat 改/L3 章改须确认）；guyin-review 的输出按其 level 字段直接进入本场景 |
| 采集 | 「采集/口述/聊聊素材」 | 经验访谈：AI 提问（生活细节向，如「你见过最穷但讲究的房间？」）→ 作者口述两三句 → 整理落盘 `灵感池/`；只注入不强插，组卡时编排层按需取 |
| 定作者性 | 「定作者性/填作者性/换个气」 | 按 [references/作者性引导.md](references/作者性引导.md) 逐件口述引导，**只问缺的件**；落盘四件定稿列，问完即退 |

**停靠纪律**：裸调用（/guyin-write 无意图）只做项目状态诊断并列出选项；开书默认停在细纲，不自动写正文；正文必须由用户显式点名。匹配优先级：大修 → 写指定章 → 补纲 → 日更 → 开书。

## 写章循环（每章必走）

1. **读盘**：本章细纲 + 上一章结尾 300 字（声线锚）+ 本章涉角色卡 + 追踪状态（伏笔/时间线/角色状态）+ 作者性四件（指纹/偏执点/气卡/魂档案——编排层读，用于选切片定禁令，**气卡永不下发**）。四件任一为默认档/未定稿：照常写作，**章尾报告附一行升级提示**（同章一次，纪律见 [references/作者性引导.md](references/作者性引导.md)）。
2. **切 beat**：按细纲把章切成 500-1500 字的 beat（默认低模型档；粒度按 `作者性/粒度配置.md`），标注情绪目标。
3. **逐 beat**：判模式（Craft/Muse，见下）→ 组装[写作卡](cards/写作卡.md) → 下发执行层 → 收正文 → 跑[自检卡](cards/自检卡.md) → 不过则[改写卡](cards/改写卡.md)分级改 → 过则进下一 beat。
4. **拼接**：按序拼章，检查拼接点衔接；落盘 `正文/第XXX章_标题.md`。
5. **追踪提交**：运行 `scripts/guyin-tracking-commit.py`（角色状态/伏笔/时间线/上下文一事务提交）。
6. **章检**：依次跑 `guyin-check-degeneration.js`、`guyin-check-ai-patterns.js`、`guyin-check-outline-copy.js`、`guyin-check-wordcount.js`（node 调用；字数护栏默认章 2000-6000 字，`--min/--max` 可调，字数不足补写缺口 beat 勿注水）；报警项标为**待审**，逐条决定：改写卡修 / 豁免（登 `追踪/豁免台账.md`，须过五测试，每卷 ≤2 处）/ 保留。
7. **灵感登记**：正文里长出的细纲外新元素（道具/习惯/闲笔）登 `追踪/灵感台账.md`，下批细纲时决定转正。

**卷末附加**：卷末章追踪提交后，提醒作者**口述重说气句**（不是抄旧句），刷新 `作者性/气卡.md`，旧句入魂档案「历次气句」；并核对豁免台账限额（每卷 ≤2）与消化完成度。作者性仍为默认档/魂档案未定稿的，**主动询问**是否现在定（引导见 [references/作者性引导.md](references/作者性引导.md)）。

## Craft / Muse 双模式（机械判据，无语义判断）

Muse 升档（满足任一）：本章细纲标签含「高潮/反转/情绪峰值」；章号为 1-3/卷首/卷末/大高潮；关系节点（告白/决裂/死别/重逢）；用户显式说「这章要出彩」。
Muse 动作：情绪峰值 beat 前置[发散卡](cards/发散卡.md)（阶段三激活，当前版本判据照判、动作降级为编排层自选非常规感官入口）。降档保护：连续 Muse ≤3 章自动回落 Craft。

## 执行层调用协议

- 首选 subagent：`guyin-beat-writer`（定义见 [agents/guyin-beat-writer.md](agents/guyin-beat-writer.md)，低模型）。三端部署件随 `项目模板/` 分发（Claude Code `.claude/agents/*.md`、OpenCode `.opencode/agents/*.md`（model: provider/id）、Codex `.codex/agents/*.toml`），复制模板即得；
- 无 subagent 环境（或 Codex 报 unknown agent_type）降级：主会话直接扮演执行层填卡，但**先声明「Fallback: solo 执行，声线与节奏由编排层兜底」**；
- 多采样：情绪峰值 beat 同卡抽 3-5 版（便宜是红利），自检卡淘汰硬错误后进入外选，判词不写入卡片；
- **外选判词（合问进选择器）**：候选版并排，只问一句「哪版更接近气句」（编排层读 `作者性/气卡.md` 当前气句，**永不下发执行层**）；选中版编号 + 一句理由留在对话，备卷末复盘与魂档案「回响收编」；难分时任选——选择即作者性，不追求完美判定。

## 豁免五测试（报警待审的处理，作者主判）

击中（有生理反应吗）/ 删疼（删了书会疼吗）/ 不可替换（重写对照实验更合格但更平？）/ 共振（与气句同向、加深一生之问？）/ 消化（≤N 章内长出新设定而非补丁）。通过则登记台账并回写设定；不过则改写卡修。**每卷 ≤2 处。**
