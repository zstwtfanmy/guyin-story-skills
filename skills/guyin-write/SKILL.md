# guyin-write：隐笔长篇写作（极简流）

唯一创作主体是当前会话。五步流程：读 → 直接写正文 → 持锚自审改一轮 → 顺手记账 → 交用户。
正文直写 `正文/第NNN章_标题.md`，没有候选区、草稿版本号、发布动作、检查门。用户是唯一验收者。

## 写作知识（全部规则，只此六条）

1. **先给人，再给事。** 读者先愿意跟这个人相处，才愿意看他办事。开书允许大段无事件日常（吃饭、当差、闲笔），日常本身就是回报，不兑换成剧情收益。
2. **事件服务于人的选择，不是资产清单。** 一章里主角做的每件事必须是"他此刻想做/不得不做"，不允许为了交付台账（人头、地名、物证、伏笔）而行动。判断标志：删掉这场，人物有没有损失；只有台账损失的场，删。
3. **叙述者必须在场。** 允许并鼓励促狭、调侃、自由间接体、跨时代设喻；场景内物件与常识合时代，叙述者的舌头不封年代。在场≠每章搞笑——高压/阴冷章的在场是判断与口吻，闹剧章才是包袱；全章完全听不到叙述者声音才是事故稿。
4. **心理直接写，不用身体短拍顶替。** 私人的怕、得意、自嘲、牵挂、委屈可以直接展开成句，句长随体验起伏。禁止通篇 ≤15 字镜头切碎。
5. **配角各带算盘，关系有摩擦。** 配角不为成就主角存在；主角的能力不向读者汇报式展示，胜绩主动去认证（行家看得出、俗眼看错、主角配合误读）。
6. **结尾不收判词。** 允许落在动作、半句对白、一个物件、一句玩笑上。模型自创的"点题宣言句"没有资格当锚句锁。

## 隐杀声线锚协议

- **锚包**：本仓库根 `声线锚库/`，经 `声线锚库/REGISTRY.md` 按本书 profile 解析锚目录（现仅 relationship-payoff 就位：`声线锚库/relationship-payoff/隐杀/`，5 段原文各带一行场景标签：开篇/共同生活/误认不纠正/踢馆/日常群戏）。锚缺失不跨 profile 借锚：一句话告知用户、`追踪/上下文.md` 标「锚未就位」，按 profile 文字继续。只迁移声音，不迁移内容：不整句搬移、不连续复用原文独特词组；时代物件以本书 1999 年为准（锚书约 1992 年，物件差异写前自查）；学声音机制不学情绪基调。
- **写前**：首章通读锚包全部；其后各章只读与本章场景同型的 1-2 段，加上本书已被用户认可的最近一章全文。
- **写时**：直接写。锚包学的是节奏、气口、叙述距离、心理密度、对白处理，**不是剧情**。
- **写后持锚自审**：稿子与锚段并排复读一遍，只问三个问题——① 引擎问：本书落差 {X／Y}——这场摩擦发生了吗？处境起反作用了吗？在选自己的事还是交差？② 声音问：声音配比合本书 profile 吗？重压以该 profile 允许的方式释放了吗？有没有大段镜头在替心理？有没有编排者字幕（横杠/加粗/定义句/预告/排队）？③ 欠账问：章末留下想追的活账了吗？该留的疑问有没有被讲完？至多一轮修订，原地改。改完即终稿。
- **出帖**：书积累出用户认可的本书章节（≥3 章），锚包降级为"声音漂移时回炉"用，日常声线以本书自己的正文为准。
- 锚包是用户合法持书的私人临摹用途：锚库除协议 README 与 REGISTRY 外不入 git、不分发、不随产物传播。锚库或对应书目录不存在时向用户索要，不空跑声线、不代找盗版源。

## 五步流程（唯一生效流程）

| 步 | 做什么 |
|---|---|
| 1 读 | 上一章全文（首章换锚包）＋`追踪/上下文.md`＋本章相关角色卡＋细纲（若有；细纲是设想不是考卷）。一次读完，不全库扫描。读完写前一问（心里答，不落文件）：本章唯一的变化是什么？什么在顶着它？ |
| 2 写 | 直接写入 `正文/第NNN章_标题.md`。写完即是正文，无候选区、无草稿版本号、无发布动作。 |
| 3 自审 | 按持锚三问复读＋数字数（缺省 3500，3000–4000；超 4000 删同质内容至区间不砍戏，不足 3000 不注水），至多一轮，原地修改。三问结论与字数各写一行进 `追踪/上下文.md`，可查不拦写。 |
| 4 记账 | 一分钟 markdown：更新 `追踪/上下文.md`（位置＋一句话本章＋承诺）、`追踪/伏笔.md`、`追踪/角色状态/` 中受影响角色。其余台账想记才记，不记不拦。 |
| 5 交用户 | 用户是唯一验收者。要改就原地改、要重写就原地重写；没有"发布授权"这一步。前三章完成后停一次，听整体感受，但这不是机械门。 |

- 修订旧章同样直接改 `正文/` 文件；改完顺手核对受影响的后续设定与伏笔，靠阅读不靠 hash。
- 写前自查（自己读，不跑门）：POV 一致、时代物件（1999 年）、姓名一致。
- 细纲存在时其"硬锁"只认用户原话与已发生事实；前三组是设想，可被成稿替换，不用先改纲再写。

## 文件契约

```
读：设定/**、大纲/卷纲_*.md、大纲/细纲_第NNN章.md（有才读，不强制创建）、
    追踪/{上下文,伏笔,角色状态}/**、作者性/**（可选，存在才读）、
    references/（方法论按需查 consult/INDEX.md，不照搬成逐条指令）
写：正文/第NNN章_标题.md、追踪/{上下文.md,伏笔.md,角色状态/*.md}
新项目先 /guyin-setup；项目结构按部署模板。
```

## 边界

- 不自动 git commit/push；不删未知来源文件。
- 遇到真正硬锁冲突（用户原话 vs 现实专业依据）停下核实，不等写完再认前提错误。
- 声线锚抬高的是方向与下限，不保证上限：多轮对照仍差距明显时归因模型能力/写作方式（写完持锚再改的两段法），不靠加规则掩盖。
