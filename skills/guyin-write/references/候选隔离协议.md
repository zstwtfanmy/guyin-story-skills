# 候选隔离协议（v3-B3，冷路径——仅作者显式启用整章多候选时读）

> 热路径入口见 [SKILL.md](../SKILL.md)「候选隔离协议」节：整章多候选**默认不启用**。启用条件：作者显式要求 A/B 对照，且事先声明候选数与费用上限（同预算下比较方法，不给新法更多抽卡机会；不默认前三章或 L3 各产 2-3 整章——先按一次明确修订假说产一版，与保留原稿比较）。

## 快照隔离

- 候选放独立临时目录（`正文/_candidates/{候选ID}/`），均从**同一正文/追踪/指纹基线**复制，一候选一目录。
- 依赖提交态的全链检查只在各自快照内执行；失败候选也留记录，不删。
- **不共享正式追踪文件**——永不复制候选整棵追踪树覆盖正式项目。

## 同序组织

仍用 beat-writer 时，编排层为每个候选独立顺序组织各 beat（单 beat agent 不写整章）；更大场景单元另作等预算试验，不在本轮暗换架构。

## 发布事务

选定后编排层先核对正式基线未变（已变则拒绝覆盖，重走对照），按既有存档 → 正文发布 → 追踪重提交 → 指纹提交流程**串行**发布；任何一步失败保持未完成、阻止续写、按原事务恢复规则处理。胜出发布后正文、摘要、追踪、指纹须同版。

## 裁决纪律

- 无净收益不默认覆盖原稿，纯品质润色保留旧版。
- 旧版存在必须修复的事实/安全契约错误时，即使阅读偏好平局仍须单独处理（不用「保旧稿」掩盖硬错误）。
- 达到事先预算或没有新修订假说时停，不机械重写第十几版。

## 验证门

本协议未做实际隔离测试（未选候选不进正式状态、候选失败不改基线、正式基线已变拒绝覆盖）前保持「已定义未验证」——不宣称整章多候选流程可用。
