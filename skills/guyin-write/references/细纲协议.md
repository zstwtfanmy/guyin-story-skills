# 细纲协议（契约层字段权威定义）

> 来源：[docs/06-卷三开局复盘整改计划.md](../../../docs/06-卷三开局复盘整改计划.md) O1——「细纲协议失锚」根因的封堵。
> 本文件是细纲字段的**唯一权威定义**；`references/consult/workflow-setup.md` 的细纲节为历史存档（按 INDEX 纪律不是权威来源，补纲会话不读它），不再维护。
> 部署件 `大纲/README.md` 只放速查表与指针——字段定义不进部署件（create-if-absent 意味着存量项目不会回灌，双源全文必漂移）；老项目读技能库本文件即可。
> 落盘硬门（四脚本，细纲落盘前依序跑）：`guyin-check-outline-slots.js`（槽位完整性）→ `guyin-check-authority-leak.js`（作者性字面）→ `guyin-check-outline-verdict.js`（资产档位仲裁）→ 批次末 `guyin-check-hook-rotation.js`（钩子轮换）。

## 分层声明（置顶，先于一切字段）

细纲是**契约层**——字段协议：钩子／字数／多线／档位／锚点。beat 是**运行层**——编排层写章循环第 2 步「按细纲把章切成 500-1500 字的 beat」的内存动作。

**细纲文件只写字段协议格式，禁止把 beat 切分写成细纲格式。**beat 版细纲不是「新模板」，是分层失守的事故产物：《白银案录》61-63 实证——beat 化后契约字段（章尾钩子/字数预算/多线/术语锚点/契约风险）整体丢失，beat 执行率 1:1，细纲砍什么，正文就缺什么。

## 字段模板（每章一个文件 `大纲/细纲_第XXX章.md`，不允许跳章）

```
## 细纲（第 N 章）

### 第 N 章：{章名}
- 核心事件：{一句话；供日更与导入统一消费}
- 字数目标：{X} 或 {X-Y} 字（区间写法合法；章检下限双口径见「字数与场景下限」细则，J1）
- 场景与对手戏下限：{默认 ≥2 场 / ≥1 对手戏；低压/过场章可声明豁免并写理由}
- 阶段位置：{开篇期/发展期/高潮期/收尾期；第X阶段第Y章；本章在阶段内承担什么}
- 单元ID/位置：{卷纲剧情单元ID；单元内第几拍/承担功能}
- 目标情绪：{具体情绪前状态→后状态；本章推进单元情绪引擎的哪一环；不得只写"热血/悲伤"等标签}
- 主角目标/关键选择：{主角本章要什么；必须做出的判断或选择}
- 章节定位：{高压/推进/修炼试错/关系回收/低压生活/信息整理；可留空，留空按推进章}
- 节奏标记：{蓄力/爆发；可留空}——Muse 判据章（细纲标签含高潮/反转/情绪峰值、章号 1-3/卷首/卷末/大高潮、关系节点、上架前末章/入V首章）标「爆发」，其前 1-2 章标「蓄力」（禁发散、收敛感官、降字数）
- 本章结构公式：{节点1（目的） + 节点2（目的） + 节点3（目的） + 节点4（目的）}
- 章首钩子：{从章首7式中选择} — {具体内容；低压/过场章可写"弱钩子/仅情绪钩子，功能是…"}
- 爽点：{本章爽点；低压/修炼/过场章可写"无显性爽点，功能是…"，但仍须给读者一个往下看的理由}
- 本章禁止提前释放：{后续阶段核心真相/底牌/关系结论/终局矛盾；没有就写"无"}——行必须在，值可"无"：契约层显式声明，防「靠卷纲兜底」的隐性放空
- 契约风险：{契约安全/需补强/契约破坏；判定标准=七检⑥⑦（见文末「契约风险行判定标准」）}
- 资产影响档位：{0 纯叠加：既往事件定性不变／1 部分动用：重估不没收，注事件名／2 全盘否定：推翻定性，须同章补偿声明+作者确认}；引用既往章/事件（含「不是A是B」翻转、全称量词复盘表述）必填，未涉及写 0；落盘前过 guyin-check-outline-verdict.js 仲裁（档 2 无支付条件不落盘）
- 术语锚点：{本批新术语列表，每个首现须带台词级锚定（谁、在什么情境、说出/写出该术语）；无新术语写"无"}
- 涉及场景清单：{本章涉及场景，喂 cards {{场景锚点行}}；无登记场景写"无"}

#### 内容概括（五段式）
- 起因：{本章事件为什么发生}
- 发展：{冲突如何推进}
- 转折：{信息/关系/局势哪里改变}
- 高潮：{本章情绪或动作峰值}
- 结尾：{本章最后落在谁的什么动作/画面/台词上——写具体落点，不写"尘埃落定""一切结束"式状态判词}

#### 情节安排（多线）
- 主线推进：{本章对主目标的推进}
- 辅线推进：{可写"无"，不能凭空制造}
- 事件线 / 任务线：{外部事件链}
- 任务卡点（如适用）：{角色要办什么事 → 卡在哪里 → 卡出什么变化 → 删掉后损失 → 收束动作；没有就写"无"，不强补}
- 感情线 / 关系线：{无显性感情线时写"无显性，但关系变化为…"}——行必须在，值可"无显性"
- 逻辑线：原因 → 行动 → 结果 → 后果/新问题
- 时序自检：出场顺序＝时间顺序？插叙已显式标注？beat 时间轴走查：□通过

#### 人物关系和出场顺序
- 出场顺序：{角色/势力/关键物件按实际出现顺序列出}
- 人物关系变化：{本章前 → 本章后}
- 视角/信息差：{谁知道什么；读者知道什么；主角误判什么}
- 本章唯一解密位：{谁、在哪一点说出关键解密；无解密写"无"}——全批只允许一个人声点破位（P3）

#### 情节细化
- 情节点序列：按字数预算编排，不按数量反推。每个情节点标 密/疏 并给字数预算——密（爽点/打脸/反转/情绪高潮，展开）≥250 字、慢镜头爽点 400-600；疏（过场/赶路/信息交代，带过）≈40 字；铺垫/日常取中约 120-150 字。各点预算求和 Σ 落在 [章目标, 章目标×1.1]：低于章目标则增展开点（爽点拆细节拍、关键节点补具体事例），高于上限则压过场/合并疏点——不靠注水、也不靠无限堆砌爽点凑长。点数随 Σ 落定（通常 10 个以上；目标 <1500 字的短章取 5-8 点，密点下限按目标比例下浮到约 120-250；目标为区间时按区间上限算 Σ 范围）。情节细化末尾写一行 `预算合计：X字（目标Y，范围Y-Z）` 便于核对 Σ。每个情节点写清"谁做了什么 + 功能标签"（功能标签即目的词：铺垫/高潮/爽点/打脸/人物塑造/设定，决定该点展开还是带过），如"主角在账单上发现4800元转出【信息揭示·密250】"而非仅写"发现"
- 任务卡点说明：如果某情节点是"办事被卡住"，功能标签必须写清它服务的是信息揭示、关系变化、代价兑现、伏笔推进、选择压力、节奏喘息或钩子承接；删掉无损的卡点不进细纲
- 复沓锚句：{须一字不差进正文的原话，一行一条并注明落点，如"点3：立此为凭…"；仅限故事世界内实体语句（誓言/面板/旧案原话/契约原文）——作者性语句禁登记为锚句（锚句字段是 outline-copy 的免报通道，免报通道必须与精神件绝缘，见 docs/06 §1.3 H1-3）；没有写"无"}
- 行动成本（可无）/收益归属：{可无行动成本；若有则写谁付出什么成本；收益归谁、如何可见、是否留下后续账}

#### 结尾设定和钩子
- 结尾设定：{收束落到什么具体动作或画面（不写"就这样……""他终于明白……"式状态判词）；未解决问题；下一章推动力}
- 章尾钩子：{危机/反转/期待/悬念/情绪}·{从章尾13式中选择} — 实体：{挂在什么具体物/人/话上}；承接：第X章{事件}（全书完结章可写"承接：无（完结收束）"）；期待度：强/中/弱；低压/过场章可弱钩子或留阶段目标

#### 执行偏差（写后回填）
- 变体：{正文与细纲的措辞偏差，接受则注明；无写"无"}
- 未落实：{细纲承诺未写进正文的项 + 顺延去向章号；无写"无"}——涉及后续章兑现的同步登记 追踪/伏笔.md 或卷纲待办（堵细纲与正文漂移不可见，报告 2.5）
```

> 执行偏差区哲学与「禁止提前释放」同源：**区必须在，值可"无"**。补纲落盘时全区预置；写章循环第 6 步追踪提交前回填；tracking-commit 提交时发现缺区会 stderr 提醒（不阻断）。

## 字段细则（机械判据的语义边界）

### 章尾钩子（blocking：行存在 + 五型之一 + 实体非空 + 承接章号）

钩子必须声明**实体**（挂在什么具体物/人/话上）与**承接**（指向下一章的什么事件）。这是把「钩子不得是情绪收束句」翻译成机械判据的语义边界：

- ✅ **情绪钩子合法**：有实体——「危机·断崖式：账本最后一页撕掉了，只留半行字（实体：撕掉的账页）→ 承接：第X章追查半行字」；
- ❌ **情绪收束句不合法**：无实体——「主角稳住了心神，天塌不下来」（这是状态判词，不指向下一章任何事件）。

「稳住，别慌。天塌不下来」类 mantra 收束双杀：既无实体（不是钩子）又字面命中作者性词源（H2 必拦）。

### 字数与场景下限（blocking：字数目标行含数字 + 场景/对手戏下限行存在）

字数标准是每本书的（细纲「字数目标」驱动章检下限，双口径 J1：**区间 X-Y 取下限 X**——区间下限本身是作者接受的最低值，不再打折；单值 T 取 T×90%；缺省 3000，见 guyin-check-wordcount.js）。场景数/对手戏下限默认 ≥2 场 / ≥1 对手戏——单场景单对话 2000 字是 ch63 双缺事故的槽位；低压/过场章可声明豁免并写理由（豁免写在行值里，脚本查行存在不查值）。

### 复沓锚句与章尾钩子分立

复沓锚句是**签名句**（世界内实体原话，靠重复累积仪式感），章尾钩子是**张力句**（指向下一章的期待）。锚句字段的落点标注不得占用/顶替钩子声明——锚句落在点 3 没问题，章尾仍须独立声明实体与承接。

### 术语锚点（advisory：字段行存在）

本卷新术语密集批次的新术语列表，首现须带**台词级锚定**（谁、在什么情境、说出/写出该术语）——术语首现直接进叙述层就是「社会脸」式工艺词泄漏的正文版（读者视角无人教过他这个词）。落盘后由 `guyin-check-outline-deliver.js` 查兑现（术语未落地/首现非对白 → advisory，S3）。

### 本章唯一解密位（无机械检查，走细纲走查纪律）

同一关键信息/解密**全批只允许一个「点破位」**（人声版：谁、在哪一点说出关键解密），其余载体（数据版/推理版）只做铺垫、不得提前解码——E3「三遍解码、人声版最佳」的细纲层单点声明：解密位在细纲声明后，执行层按声明落点写，重复解码在细纲走查时拦下。逻辑重复判定不可机械化，本字段不做脚本检查（P3）。

> 时序自检行（情节安排节末）是 E1 时序倒错的源头封堵：补纲落盘前人工走查 beat 时间轴，outline-slots 只查行存在（advisory `outline-missing-timecheck`，P1）。

### 契约风险行判定标准（七检⑥⑦判据，逐章填写时用）

批次级答全表（见 consult 存档与卷纲流程），逐章设计时只复答⑥⑦并把风险等级写入本章细纲「契约风险」行：

- **⑥ 阶段位置判据**：本章处在全书哪个阶段（开篇/发展/高潮/收尾期），可释放什么，必须压住什么——对照 `设定/题材定位.md`「终局底牌与升级台阶」；
- **⑦ 契约四项评级**：读者契约（本书承诺的核心阅读快感是否被本章兑现/推进）、主角代理权（因果权：决策/布局/授权/关键信息；结算权：核心收益/认可按承诺回到应得者）、期待债（开篇承诺是否被偿还或至少被喂养）、终局储备（终局底牌/升级台阶是否被提前打光或越级）——四项各评为 契约安全 / 需补强 / 契约破坏，取最劣为行值。

## 写作纪律（细纲层翻译）

### 工艺词翻译纪律（W3）

细纲的叙述层字段（情节点/结尾设定）里出现工艺概念词（题材分析词、框架词、档位词——如「社会脸」「资产」「beat」）时，**必须括注叙述者措辞**：「社会脸（写成：棚区人前一套人后一套的作派）」，组卡时取括注。细纲会被逐字下卡，工艺词必须在细纲层就翻译完——括注漏写，执行层就会把工艺词原样写进正文。

### 强度按章节定位分配

每章细纲按当前章节蓝图直接指导正文（阶段位置、结构公式、禁止提前释放、内容概括、情节安排、人物关系/出场顺序、情节细化、结尾设定齐备），但**强度按章节定位分配、不是每章顶满**：高压/推进章配齐钩子+爽点+悬念；低压/关系/修炼/信息整理章允许无显性爽点、弱钩子或仅情绪钩子，重点是把功能（喘息、关系、铺垫、转场）写到位。底线是每章都给读者一个往下看的理由、相邻章不情绪趋同。字段不完整时先补齐；无法从材料确定的关系或副线写 `[待补充]`，不得杜撰。

## 存量策略

本协议只拦**落盘门场景**（新建/修订细纲落盘前跑 outline-slots 检查）；存量章细纲不追溯（与 hook-rotation 的「存量不追溯」一致）。老项目存量细纲缺槽位，在下次修订该章细纲时按本协议补齐——已写章的既有细纲属锁定件，预检发现缺槽时补的是新增槽位行而非改写既有内容（W4 决策，见 docs/06 §四）。
