# 细纲协议（极简流版）

> 2026-09-28 起以《质量极简流与隐杀声线锚技术规格》为准：细纲是**设想不是考卷**。
> 本文件只保留极简流仍需要的最小约定；旧检查脚本（outline-*/wordcount/authority-leak 门）已停用，历史字段留档不追改。

## 0. 细纲是可选的，不是写章许可

- **没有细纲也可以直接写**：方向与事实从用户原话、上一章正文、追踪账本取。细纲存在时也只读，不跑任何检查门。
- 细纲四组性质：
  - **第一至三组（交付什么／人为何行动／场景如何承接）是设想**：写章前的方向与材料，不是验收答案。成稿可以用更可信的事件、办法、对白、场景**整拍替换**它们——不用先改纲再写，不用登记偏差。
  - **第四组（不能擅改）只认两类来源**：用户当次明确锁定的**原话**（逐字承诺，exact 锁），与**已发生事实**（前章正文已写定的）。模型自己觉得"该保留"的东西进不了第四组；前三组的建议不偷升为硬锁。
- 用户原话锁定格式：一行一条，注明来源（哪次原话＋日期）。**没有用户原话来源的"锚句""签名句"一律不锁**；模型自创的点题句没有资格当锚句。

## 字段模板（每章一个文件 `大纲/细纲_第NNN章.md`，可缺章可整章省略）

```
### 第 N 章：{章名}

#### 一、本章可能交付什么（设想，可整拍删改）
- 核心事件：{一句话方向}
- 读者承诺：{本章可能提供的明确体验——写处境与行动，不填情绪词}
- 字数目标（软建议，首三章不设下限）：{X} 或 {X-Y} 字——写不满不拦、超了不拦；内容撑不起长度就写短，禁止注水凑长

#### 二、人为何这样行动（设想）
- 人物目标/关键选择：{相关人物各自想要什么}
- 逻辑线：{原因 → 行动 → 结果 → 后果/新问题}
- 关系变化：{本章前 → 本章后；无显性变化写"无"}
- 视角/信息差：{谁知道什么；读者知道什么}

#### 三、场景如何承接（设想，可整拍删改）
- 场景序列：{每场一行：起点、意图、行动可能、前后变化、承接。整场可删、可并、可换}
- 章尾落点：{收束方向——具体动作/画面/台词/物件/半句对白，不写状态判词}

#### 四、哪些不能擅改（硬锁，每项必须有来源）
- 已发生事实：{前章已定事实；无写"无"}
- 用户锁定原话：{逐字承诺，注明来源与日期；无写"无"}
- 知情与保密边界：{谁不知道什么、本章不解密什么；无写"无"}
```

- 禁止条款：**不写**资产档位、复沓锚句、执行偏差、工序提示、判词类字段——那些属于旧框架的机械台账，极简流不读不写。

## 写作纪律（细纲层，三条）

1. **事件服务于人的选择，不是资产清单**：一场戏删掉后人物没有损失、只有台账损失——这场就删或并（见 guyin-write SKILL 六条第 2 条）。
2. **工艺词不进细纲**：框架词、题材分析词要写成叙述者能直接用的措辞（「社会脸」→「棚区人前一套人后一套的作派」）。
3. **细纲写完即弃读**：写正文时细纲只是方向提示，剧情细节以成稿为准；成稿完成后细纲不必回头对齐。

## 存量策略

- 既有获批细纲不自动重写：第四组的用户原话锁与已发生事实仍有效，其余字段当方向提示看。
- 旧格式细纲（多线节/情节点序列/章尾钩子等）可直接消费，不要求先补格式再写作。
