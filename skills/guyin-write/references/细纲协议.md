# 细纲协议（变化优先版）

> 2026-09-29 起以《分层写作架构V6技术规格》为准：细纲是**设想不是考卷**，且以「本章唯一变化（delta）＋阻力」为首组。
> 本文件只保留极简流仍需要的最小约定；旧检查脚本（outline-*/wordcount/authority-leak 门）已停用，历史字段留档不追改。

## 0. 细纲是可选的，不是写章许可

- **没有细纲也可以直接写**：方向与事实从用户原话、上一章正文、追踪账本取。细纲存在时也只读，不跑任何检查门。
- 细纲四组性质：
  - **首组（本章唯一变化＋阻力）是方向**：写章前的变化承诺，不是验收答案。成稿可以用更可信的事件、办法、对白、场景**整拍替换**它——不用先改纲再写，不用登记偏差。
  - **次两组（进场／欠账）是支撑**：承接前文与账本的便签。
  - **第四组（不能擅改）只认两类来源**：用户当次明确锁定的**原话**（逐字承诺，exact 锁），与**已发生事实**（前章正文已写定的）。模型自己觉得"该保留"的东西进不了第四组；前三组的建议不偷升为硬锁。
- 用户原话锁定格式：一行一条，注明来源（哪次原话＋日期）。**没有用户原话来源的"锚句""签名句"一律不锁**；模型自创的点题句没有资格当锚句。

## 字段模板（每章一个文件 `大纲/细纲_第NNN章.md`，可缺章可整章省略）

```
### 第 N 章：{章名}

#### 一、本章唯一变化（delta，方向）＋阻力
- 章末比章初唯一主变化：{一个关系/处境/信息位置的位移；换本书仍成立＝空话，重推}
- 假变化判废：{“他懂得了一个道理”却不改变后续选项＝没变；变化必须改变他接下来能做/会做的事，或改变别人对他的动作}
- 阻力：{场内“什么东西不让它发生”——变化＋阻力成对，就是这场戏的引擎}
- 刻意停留章：{明写“本场无显性变化”及理由，不糊里糊涂什么都没发生}
- 字数目标（软建议）：{缺省 3500（3000–4000），细纲值覆盖缺省；写不满不拦、超了不拦；内容撑不起长度就写短，禁止注水凑长}

#### 二、进场（支撑字段）
- 谁／在哪／想要什么／带着什么前文
- 视角/信息差：{谁知道什么；读者知道什么}

#### 三、欠账（支撑字段）
- 新开：{本章新挂的活账}
- 偿还：{本章偿还的旧账}
- 对应卷纲释放点：{有卷纲才填；无卷纲写“无”}

#### 四、哪些不能擅改（硬锁，每项必须有来源）
- 已发生事实：{前章已定事实；无写“无”}
- 用户锁定原话：{逐字承诺，注明来源与日期；无写“无”}
- 知情与保密边界：{谁不知道什么、本章不解密什么；无写“无”}
```

- 禁止条款：**不写**资产档位、复沓锚句、执行偏差、工序提示、判词类字段——那些属于旧框架的机械台账，极简流不读不写。

## 写作纪律（细纲层，三条）

1. **变化优先于事件清单**：细纲不规定"事件清单"，只承诺一个 delta＋阻力；人物不是为了完成动作而存在（见 guyin-write SKILL 六条第 2 条）。
2. **工艺词不进细纲**：框架词、题材分析词要写成叙述者能直接用的措辞（「社会脸」→「棚区人前一套人后一套的作派」）。
3. **细纲写完即弃读**：写正文时细纲只是方向提示，剧情细节以成稿为准；成稿完成后细纲不必回头对齐。

## 存量策略

- 既有获批细纲不自动重写：第四组的用户原话锁与已发生事实仍有效，其余字段当方向提示看。
- 旧格式细纲（多线节/情节点序列/章尾钩子等）可直接消费，不要求先补格式再写作。
