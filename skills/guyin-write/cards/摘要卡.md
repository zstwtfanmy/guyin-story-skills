# 事实提取清单（cards/摘要卡.md）——从事务稿到追踪事务时自取

> 可选，防漏清单。reviewed 后**从选定稿**提取事实填 `R/transaction.json`；schema 以 [consult/tracking-transaction.md](../references/consult/tracking-transaction.md) 与脚本 normalize 函数为准，本卡不另造字段。换稿后整份重提，不改哈希复用。

## 提取对照

- `delta.result`：本章结果速记（≤900 UTF-8 字节，与近章速记同额）；只放事实，不塞审读报告。超限删引文冗余，不删事实——细节进实体字段。
- 人物变化：谁变了什么；**变更的核心角色必须有 character_snapshots 当前快照**，快照 identity/location/goal/state 四个字段非空。
- 伏笔 F／时间线 E／定性 V／物证 W／地理 G／场景 S：按既有 ID 前缀续号，不重新分配；要求存原句的 anchor/verdict 抄原文。
- 人物知情进 knowledge：谁知道什么；**怀疑/误信保留主体**，不升级成客观真相。
- 承诺进 next_chapter_commitments 或真伏笔；普通旧物、吃食不自动登记待回收。
- context 只有 position/long_term_constraints/active_character_names/continuity_risks。
- append：章号=last_committed_chapter+1，expected_state_revision 取当前值；revision：修已提交章，以最新全局状态为基础，不退回早章旧世界。

## 校验

- 不能只 JSON.parse 自查：ready 检查经追踪器纯内存 normalize/merge/preview 验证；错误 revision、空快照、缺核心快照都会被拒。
- 事实量大使逐章渲染超展示尺寸是告警不是拒收：完整事实保留在实体与原文，不靠压缩丢信息。
