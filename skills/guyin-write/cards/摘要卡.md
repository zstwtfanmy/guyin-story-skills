# 摘要卡模板（cards/摘要卡.md）

> 编排层专用：每章拼接落盘后、追踪提交前，组装本卡下发 guyin-checker（零温）。
> **P2 落地件**：开放摘要对低模型 = 废话生成器——字段锚定答案空间 + 原文锚点防敷衍。
> 填好的卡全文 = `delta.result`，随 tracking-commit 入库 chapter_summaries，供金字塔消费。

---

```
【章摘要 第{{章号}}章】从本章正文填空，每个字段必须抄原文锚点：

新事件（≤3 条，每条：谁+动词+结果）：
① ____（锚点原文：「____」）
② ____（锚点原文：「____」）
③ ____（锚点原文：「____」）

情绪走向（各抄一个词或短语）：从____到____

章尾钩子（抄本章最后一句原文）：「____」

伏笔变动（引用 F 编号，无变动写"无"）：____

出场角色（本章有台词或行动的角色，逗号分隔）：____
```

---

## 编排层处置规则

| 摘要结果 | 处置 |
|---------|------|
| 每字段有原文锚点 | 卡全文 = delta.result，随 commit 入库 chapter_summaries |
| 任一字段锚点空缺 | 退回重填——空锚点 = 模型在编 |
| 第 10/20/…章 | commit 后触发 10 章聚合（二叉树两两合并，编排层组聚合卡下发 checker） |
| 卷末章 | commit 后触发卷摘要生成（常驻金字塔顶层） |

- **字段填空 + 原文锚点**是低模型产出稳定性的全部秘密：锚定答案空间，防「本章讲述了主角继续变强的故事」零信息量；
- **零温生成**：摘要要可复现，不高温采样、不做创意；
- 章摘要约 300 字，10 章聚合约 1000 字（二叉树两两聚合，非一次性合并），卷摘要约 500 字常驻；
- 金字塔消费方：review 架构视角（审第N章 = 卷摘要 + 近 10 章章摘要 + 本章全文 ≈ 5K 字，替代 30 万字全文）、写章读盘、P3 收线审计。
