# 细纲协议（契约层字段权威定义）

> 本文件是细纲字段的**唯一权威定义**；`references/consult/` 下旧细纲节为历史存档，不是权威来源。
> 部署件 `大纲/README.md` 只放速查表与指针——字段定义不进部署件；老项目读技能库本文件即可。

## 0. 细纲是可选的，不是写章许可

- **没有完整细纲也可以起笔**：锁、事实与边界直接从用户当次原话和已发布正文提取，冻结进本 run 的 `input.json`。无细纲时 outline-slots / opening-retention / outline-copy 一律记「不适用」，**不造一份四组细纲过门**；开篇体验由全文回看负责。
- 细纲存在时，四组性质不同：
  - **第一至三组是工作假说**：写章前的方向与材料，不是验收答案。成稿可以用更可信的事件、办法、对白、场景替换它们——未锁定差异允许正文驱动，不必先改纲再写；
  - **第四组是硬锁**：只收录有来源、不能擅改的内容——用户当次明确锁定的原话/结果/视角（exact/semantic/forbidden，锁必带 source_id）、已发布事实、知情与保密边界。模型自己觉得「该保留」的东西进不了第四组；前三组的建议不偷升为硬锁。
- 成稿使**未锁定**规划需要改动：写完、发布后走规划补丁（`plan-patch.json`，凭用户改纲授权幂等回写，见 SKILL「发布与规划承接」）；不得篡改历史批准稿伪造「原来就这么设计」。涉及已发布事实的冲突只能走 revision，不静默改历史。

## 分层声明（置顶，先于一切字段）

细纲是**契约层**——四组协议：本章可能交付什么／人为何这样行动／场景如何承接／哪些不能擅改。场景（旧称 beat）是**运行层节奏标签**，不是独立调用、字数桶或逐拍验收单位。

**细纲文件只写四组协议格式，禁止把场景切分写成细纲格式。** 同样禁止情节点逐条字数配额——正文长度由本次冻结的字数约定与场景内容决定，不由碎片配额生成。

## 何时跑细纲检查（条件触发，不是起笔前置）

仅当**实际新建或修订一份完整细纲**并准备落盘时，依序跑：`guyin-check-outline-slots.js`（四组齐备+保留行）→ `guyin-check-authority-leak.js`（工序指令/作者性字面）→ `guyin-check-outline-verdict.js`（资产档位仲裁）。正文落盘后的承诺交付由 `guyin-check-outline-deliver.js` 在 ready 检查链承担（exact 锁逐字；语义关系只输出待人工核对）。`guyin-check-hook-rotation.js` 仅服务旧格式存量细纲。

## 字段模板（每章一个文件 `大纲/细纲_第NNN章.md`，不允许跳章）

```
## 细纲（第 N 章）

### 第 N 章：{章名}

#### 一、本章可能交付什么（假说，可被更可信成稿替换）
- 核心事件：{一句话方向；供日更与导入参考}
- 阶段位置：{开篇期/发展期/高潮期/收尾期；卷纲单元ID（如有）；本章在阶段内的位置}
- 读者承诺：{本章可能提供的明确体验——好奇、能力兑现、关系亲近、惊惧、幽默、生活滋味，或本书题材承诺的其他体验；写产生体验的处境与行动，不填情绪词、不写口号。这是方向不是交货清单}
- 收益归属：{收益可能归谁、如何可见、是否留下后续账；无写"无"}
- 字数目标：{X} 或 {X-Y} 字（区间取下限、单值×90%；本次 run 的字数以 input.json 冻结值为准，细纲缺行不拦写。内容撑不起长度时修设计或请用户调整，禁止填水）
- 术语锚点：{本批可能出现的新术语；可在对白也可在叙述中自然讲清，不强制对白首现；无写"无"}

#### 二、人为何这样行动（假说）
- 人物目标/关键选择：{相关人物各自想要什么；主角本章可能面对的判断——可被成稿中更可信的选择替换}
- 逻辑线：{原因 → 行动 → 结果 → 后果/新问题；行动者凭什么能做（能力/资源/信息）尽量在细纲层交代，但关键因果以成稿与核实为准；信息张力区分读者已知/人物已知/本次新增}
- 关系变化：{本章前 → 本章后；不强制反转；无显性变化写"无显性，但……"或"无"}
- 视角/信息差：{谁知道什么；读者知道什么；谁误判什么——怀疑是人物的，不是客观真相}

#### 三、场景如何承接（假说）
- 场景序列：{每场一行：起点、意图、行动可能、前后变化、与下一场的承接；不预写逐句动作，不要求每场反转、冲突或明确升降——单场长对话、安静日常均可成立}
- 章尾落点：{可能的收束位置——具体动作/画面/台词方向，不写"尘埃落定"式状态判词；未解决问题与下一章推动力；收束位轮换按批次公约}

#### 四、哪些不能擅改（硬锁，每项必须有来源）
- 已发生事实：{前章已定事实；遗留实物/未兑现钩子的处置（本章兑现，或登 追踪/伏笔.md 顺延——无声消失是唯一禁区）；无写"无"}
- 知情边界：{谁不知道什么；无写"无"}
- 保密项：{明确保密项 + 全批唯一人声解密位（谁、在哪一点点破；无解密写"无"）；无写"无"}
- 禁止提前释放：{后续阶段核心真相/底牌/关系结论/终局矛盾；没有写"无"}——行必须在，值可"无"
- 锁定结果：{用户锁定的结局/事件/走向，注来源（哪次原话/哪条已发布事实）；模型建议不得写入本行；无写"无"}
- 资产影响档位：{0 纯叠加／1 部分动用：重估不没收，注事件名／2 全盘否定：推翻定性，须同章补偿声明+作者确认}；引用既往章/事件必填，未涉及写 0；落盘前过 guyin-check-outline-verdict.js（档 2 无支付条件不落盘）
- 复沓锚句：{须逐字进正文的原话，一行一条并注明落点，如"点3：立此为凭…"；仅限故事世界内实体语句（誓言/面板/旧案原话/契约原文）——作者性语句禁登记；没有写"无"}

#### 写作指令（本区内容禁止以任何形式进入正文）
- {本章特有工序提示：如"勘合首现 → 谁问、谁答一句"}——批次不变量（比喻域/引号规格/收束位轮换/批次禁令）上移 `大纲/批次公约.md` 一次声明
- 无指令写"无"：区可以缺、值可"无"；全区块 ≤5 行软上限。本区是给执笔者的工序提醒，authority-leak 会拦它漏进正文

#### 执行偏差（检测驱动回填）
- 变体：{正文与细纲前三组的措辞/做法偏差——假说被替换属正常，注明即可；无写"无"}
- 未落实：{第四组硬锁未写进正文的项 + 顺延去向章号（必填，机械校验）；无写"无"}——只有硬锁未落实才算违约；前三组偏差不是违约
- 弃用登记：{被弃用的保护资产/硬锁承诺 + 理由、替代物与授权来源（必填）；无写"无"}——弃用硬锁的合法前提是用户裁决，弃用假说不需要
```

> 执行偏差区（检测驱动）：**回填不由人凭空手写——outline-deliver 把「硬锁与正文哪里不一致」找出来（exact 锚句未落地/术语缺失），裁决只做「修 or 认」**：修＝改正文对齐硬锁（默认路径）；认＝登记偏差区（契约修订，注明变体、未落实写顺延章号）。硬锁无声消失是唯一禁区——每条检测终态必居其一：正文修复／契约修订／顺延登记／升级作者。自动化裁决规则（V11 后生效）：默认修一次，修不成则认（落偏差区＋顺延登记），仅 hard 级修复失败、涉契约风险/资产档位、同一报警二次复发三种情形升级作者待审。tracking-commit 提交时缺区/未落实缺章号给 stderr 提醒（不阻断）。

## 字段细则（机械判据的语义边界）

### 字数约定（行存在且含数字时机械生效）

字数标准是每本书/每次 run 的：有细纲时「字数目标」驱动章检下限（双口径：区间 X-Y 取下限 X；单值 T 取 T×90%；缺省 3000，见 guyin-check-wordcount.js）；无细纲时以本 run `input.json` 冻结的 wordcount 为准，靠 `--min/--max` 显式传入，脚本不从无关文件猜字数。长度是设计约束不是产出方式：内容撑不起长度时修设计或请用户调整——**禁止填水凑长**。

### 读者承诺（方向行，非交货合同）

回答「读者凭什么读这一章」，但它在第一组、是假说：

- 写**处境与行动**（"读者看到主角用假账目反将一军"），不写情绪词（"热血""爽"）、不写口号；
- 体验类型按 `设定/题材定位.md` 主要阅读回报与默认 profile 选型，**不封闭为升级流的金手指/能力展示**；
- 日常温度、余韵本身可以有价值——安静章的承诺可以是"和这个人再待一会儿"式的明确体验；
- 成稿兑现了不同但同样成立的体验不算违约；是否值得读由全文回看与真实读者判断，不由这一行自证。

### 场景序列与章尾落点

连续创作接口：每场一行写起点/意图/行动可能/前后变化/承接——**写到"这场可能成立什么"，不写到"每句话怎么写"**。不预写逐句动作，不要求每场反转、冲突或明确升降。章尾落点只给收束方向，不强制实体钩子或谜物——章尾是否有钩由读者承诺与下一章承接自然决定。

### 复沓锚句（exact 锁；outline-deliver 查逐字落地）

复沓锚句是**签名句**（世界内实体原话，靠重复累积仪式感），登记即逐字承诺：outline-copy 的免报通道 + outline-deliver 查逐字落地。仅限世界内实体语句，作者性语句禁登记。

### 术语锚点（可在叙述中清楚引入）

术语是为读者理解服务的：新术语首次出现时，无论在对白还是叙述里，只要上下文把它讲清楚、读者能跟住，就是合法引入；不再强制「对白首现」。outline-deliver 只检查术语是否真实进入文本、与硬锁术语表是否一致，不裁判引入方式。堆砌未解释名词不属于清楚引入。

### 保密项与唯一解密位（无机械检查，走细纲走查纪律）

同一关键信息/解密**全批只允许一个「点破位」**，其余载体只做铺垫、不得提前解码。逻辑重复判定不可机械化，本字段不做脚本检查。

### 承接实物处置（AC1）

前章遗留实物/未兑现钩子（信内物证/口头承诺/悬念实体）须显式处置——本章兑现，或登 `追踪/伏笔.md` 顺延；无声消失是唯一禁区。

### 签名句归属（K2，跨章排他）

每章的签名句＝复沓锚句。本章声明的签名句不得在**其他章**正文出现（提前释放或归属被抢，`outline-signature-preempted` verify）。只查已声明的签名句，跨章走查兜另一半。

### 开篇附加（仅 ch001-003 且存在完整细纲时）

前三章是读者入口。第一组「读者承诺」行在开篇章承担入口方向，行值尽量写全三件事：

1. **当下目标**——主角外向、可执行、开篇可见的动作目标（内向状态落到第二组交代）；
2. **入口体验**——读者凭第一章的什么处境与行动读下去，按书级 profile 的主要回报选型；金手指/能力展示不是普适前提；
3. **近期回报**——前三章整体至少兑现或明确指向一笔（哪章兑现、兑现什么写进行值）。

机械门＝`guyin-check-opening-retention.js`，**仅当 ch001-003 存在完整细纲时运行**：第一组「读者承诺」行存在且值非「无/空」（缺即 hard）；语义质量留给全文回看。没有完整细纲时不运行、不补造字段——开篇吸引力由 drafted 全文回看负责。存量四留存字段细纲视为合法历史格式，不追溯。

### 密/疏（场景工具参考，不是字段）

密/疏不是字段、不是配额，只作为描述场景展开程度的口语：

- **密**＝重点场给足内容：对话往返、感官层次、有功能的心理都是**可选材料**，按题材与事件取材，**不默认再填手、杯、筷、呼吸**（写不满先回第二组核查事件和关系是否够：不够是细纲缺口，不是正文注水）；
- **疏**＝带过，但不是切碎：≤15 字单句成串是碎化信号，修法是恢复必要连接与句群。

机械配套＝`guyin-check-ai-patterns.js` 的 `prose-fragment-ratio`（editorial 观测值，需结合上下文判断）。

### 写作指令区（工序提示，不进正文）

指令性内容（执行方式/步数约束/落位要求）**必须收进本区，不得散落在内容字段**——指令与内容混排是指令漏进正文的生成机理。**本区只装本章特有提示；批次不变量上移 `大纲/批次公约.md`**。本区内容永不进正文；漏入由 `guyin-check-authority-leak.js`（工序词表，verify）拦。不设槽位硬门：指令不是每章都有。

## 写作纪律（细纲层）

### 场景选择三问（落盘前想一遍，不是打分表）

- **人物为何此刻这么做，而不是作者需要这样？**重要配角按自身利益/认知行动时，这一场还成立吗？
- **读者在这一场能经历什么？**指出产生体验的处境与行动，不填情绪词。
- **去掉这一场，会失去什么？**纯复述已知信息而无新作用的场，删并或换设计；日常温度、余韵本身可以有价值。

### 卡壳时的简案比较

卡壳时才比较 2-3 个**「人物选择或局势后果不同」**的简案；不能只换感官、比喻和开头句式。每场都强造障碍、反转或代价，同样判为模板化。

### 规划深度分层

当前章可细化到四组齐备；后续约 2-3 章保留承接和后果；更远保留阶段方向（卷纲）。章数只是起点，不是检查门——不预写十数章节点配额，也不因「批次没写满」拦截落盘。

### 强度按故事自然分配（不是每章顶满）

高压/爆发场与低压/喘息场按故事需要自然分布，由全文回看按阅读体验判断，不由字段配额预分配。每章的底线由第一组「读者承诺」行承担。无法从材料确定的关系或副线写 `[待补充]`，不得杜撰。

### 工艺词翻译纪律（W3）

细纲叙述层字段出现工艺概念词（题材分析词、框架词、档位词）时，**必须括注叙述者措辞**：「社会脸（写成：棚区人前一套人后一套的作派）」。细纲会被执笔时直接读到，工艺词必须在细纲层就翻译完。

### 术语准入（Fw-09 C4：无三件套，术语不进细纲）

框架内部词（**密/疏、外选、气压、回甘强度、音高、合问**等）与任何新造分析词，进细纲前必须带齐三件套，缺一件即退回，先补后写：

1. **定义**——一句话说清它指什么（不许用另一个黑话解释黑话）；
2. **反例**——至少一个"看着像但不是"的具体形态（如：密≠字数多，均段 20 字写满 250 字的碎句串是反例）；
3. **正文可指认特征**——成稿里能逐句指出来的客观形态（字数/句长/位置/动作计数等，执笔与检测能据此判"在/不在"）。

三件套落点：框架词写在本协议或批次公约对应条目里（密/疏见上文，已齐三件套）；项目自造词写在该词首次出现的细纲行内括注。**判据**：拿着这个词去翻任意一章成稿，指不出具体句子的就是没过关的词——气感词（"气压强一点""回甘更浓"）只允许活在会话判语里，细纲字段必须改写成可指认形态后才准落笔。

## 存量策略

- **既有获批细纲不自动重写，第四组锁定结果仍有效**；前三组与成稿冲突时成稿优先，偏差登记即可；后果使后续计划不合理时提出规划补丁建议，不把人物强拉回旧剧本。
- 存量旧格式细纲（多线节/情节点序列/章尾钩子/情绪落点等）未修订前仍可消费：按四组等价信息当核对清单，不要求先补格式再写作；下次修订该章细纲时并入四组。
- 旧项目升级只给迁移预览（冲突条款/建议/所需授权），不自动重写用户规划文件。
