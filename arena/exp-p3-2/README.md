## 实验合规点（对照 §10.1）

- A/C 同模型（本会话）、同事实卡、同篇幅预算（2200–6000 字，实际成稿 2900–3600 字）、一次生成；C 仅按事实卡冻结书级 profile（爽文 relationship-payoff v1 / 历史穿越 historical-causal v1），未获得额外关键设定。
- C 全程真实工具链：候选只在 `.guyin/work/{run}/drafts/`，审读/检查证据绑候选 hash12，v2 清单经 `_rerun_candidate_chain` 重跑，篡改证据/过期证据会被拒。
- 中断续写：ch2 的 v0001 为半稿（complete=false）跨进程持久化；phase3 以另一进程读 session 恢复，换稿 v0002 后按协议走 input 修订重授 selected-candidate 授权；发布后 v0001 字节经比对未改动，state rev=2 仅追加一次。
- 修订次数：爽文 ch3 被 integrity 以 hard「叠字"了了"」拦截一次，作者改句后重跑（§10.1 允许的"至多一次实质修订"边界内，修的是明确机械问题，未挑选成绩）。
- 已保留全部初稿与选定稿，未删失败样本（ch3 被拦记录见本 README 与 git 历史外的 run 目录）。
